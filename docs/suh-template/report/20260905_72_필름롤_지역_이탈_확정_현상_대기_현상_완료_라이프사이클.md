# ⚙️[기능추가][필름롤] 지역 이탈 확정 → 현상 대기 → 현상 완료 라이프사이클

## 개요

기본 시나리오의 마지막 구간(지역 이탈 → 1시간 뒤 현상 완료)을 구현했다. 진행 모드에서 위치가 갱신될 때마다 현재 좌표의 행정구역을 필름롤 지역과 비교해 이탈을 감지하고, 사용자 확인 후 `FilmRollsApi.exitFilmRoll`을 호출한다. 서버 응답이 `READY_TO_RENDER`(현상 조건 충족)면 로컬 필름롤을 새 상태 `developing`으로 전환해 카운트다운 화면을 보여주고, `EXPIRED`(조건 미충족)면 `expired`로 종료 처리한다. BE의 현상 결과(사진 공개) 조회 API가 아직 없어, `developing → completed` 자동 전환과 결과 화면은 이번 범위에서 제외하고 후속 이슈로 남겼다.

## 주요 구현 내용

- **로컬 DB가 source of truth**라는 기존 원칙을 유지했다. 서버 응답(exit/조회)은 로컬 상태 전이의 트리거일 뿐, 화면은 항상 로컬 필름롤을 기준으로 렌더링한다.
- 이탈 판정은 세션 캐시(`LocationVerificationResult.sessionCache`)를 쓰지 않고, 위치가 갱신될 때마다 Kakao 역지오코딩을 다시 호출해 신선한 좌표로 판정한다. 세션 캐시는 이동을 반영하지 못하기 때문이다.
- **`serverFilmRollId` 확보 문제**: 서버 동기화(`syncFilmRoll`)는 원래 "현재 위치가 필름롤 지역과 일치할 때만" 서버 필름롤을 생성하는데, 지역 이탈을 확정하려는 시점엔 이미 지역 밖이라 이 조건에 걸려 서버 등록이 막힐 수 있었다. `skipRegionCheck` 옵션으로 exit 처리 시에만 이 검사를 우회하도록 해결했다.
- 새 라우트를 만들지 않고 `ExploreScreen`의 기존 모드 전환 구조(#69)를 그대로 확장해, 채록길 탭 안에서 탐색 → 진행 → 현상 대기 → (완료 시) 다시 탐색으로 자연스럽게 순환하도록 했다.

## 주의사항

- 현상 완료(`developing` → `completed`) 자동 감지와 결과(사진 공개) 화면은 BE 결과 조회 API가 아직 없어 이번 범위에서 제외했다. `developing` 필름롤은 카운트다운이 0이 돼도 자동 전환되지 않으며, 완료 여부는 사용자가 추후(BE API 확정 후) 확인할 수 있게 된다.
- exit 응답의 EXPIRED 사유(3유형 미충족 vs 사진 1장 미만)를 구분하는 필드가 서버에 없어, 안내 문구는 사유 구분 없이 단일 문구로 처리했다.
- `flutter analyze` 무경고, `flutter test` 177개 전체 통과(신규 22개 포함) 확인했다.

**`lib/features/explore/presentation/widgets/film_roll_progress_view.dart` — 방문 인증 시도마다 Kakao 역지오코딩이 추가로 호출됨**

`_onVisitTap`이 방문 인증을 시도할 때마다 `LocationPermissionService.getCurrentPosition()`으로 새 좌표를 얻어 `widget.onPositionResolved(position)`으로 부모에 올린다(`film_roll_progress_view.dart:216-217`). 부모(`ExploreScreen`)는 이 콜백에서 `_currentPosition`을 갱신해 `FilmRollProgressView`에 새 `currentPosition`을 내려주고, 이는 `didUpdateWidget`을 통해 `_checkRegionDeparture()`를 다시 트리거한다(`film_roll_progress_view.dart:127-132`).

**영향**: 방문 인증 버튼을 누를 때마다(성공/실패 무관하게) Kakao Local API 호출이 1건씩 추가로 발생한다. 코스 내 미방문 장소 수(3~수십 곳)만큼 곱해지므로, 원래 "위치가 유의미하게 갱신될 때만" 이탈을 점검하려던 의도보다 호출량이 늘어난다. Kakao API는 호출량 기준 과금/쿼터가 있는 외부 서비스라 비용·레이트리밋 리스크가 있다.

**해결 제안**: `_checkRegionDeparture`에 최소 호출 간격(예: 마지막 판정 후 N초 내 재호출 스킵) 또는 마지막 판정 좌표와의 거리 임계값(예: 50m 이내 이동이면 스킵)을 추가해, 방문 인증처럼 짧은 시간에 반복되는 위치 갱신에서 중복 호출을 줄인다.

```dart
// 예시
Position? _lastCheckedPosition;
DateTime? _lastCheckedAt;

Future<void> _checkRegionDeparture() async {
  final position = widget.currentPosition;
  if (position != null && _lastCheckedPosition != null) {
    final elapsed = DateTime.now().difference(_lastCheckedAt!);
    final moved = Geolocator.distanceBetween(
      _lastCheckedPosition!.latitude, _lastCheckedPosition!.longitude,
      position.latitude, position.longitude,
    );
    if (elapsed < const Duration(seconds: 30) && moved < 50) return;
  }
  ...
}
```

**테스트 커버리지 — 지역 이탈 감지 상태 전이(`_checkRegionDeparture`/다이얼로그/배너)에 대한 테스트 없음**

`evaluateRegionDeparture` 순수 함수와 `ExitFilmRollUseCase`는 단위 테스트가 있지만, 이를 실제로 엮는 `_FilmRollProgressViewState._checkRegionDeparture`의 3분기(`inside`/`unknown`/`departed`) → 다이얼로그 1회 노출 → 거절 시 배너 전환 → 재이탈 시 배너 유지라는 상태 전이는 위젯 테스트가 전혀 없다. 이 프로젝트에 `FilmRollProgressView`/`ExploreScreen`류 위젯 테스트 관례가 아직 없다는 점은 알지만, 이번에 새로 들어간 로직 중 가장 분기가 많고 사용자 확인 플로우(되돌릴 수 없는 "현상 시작")가 걸린 부분이라 최소 골든 시나리오(1회만 다이얼로그 노출, 거절 후 배너로 전환) 정도는 위젯 테스트로 고정해두는 것을 권장한다.

**`lib/features/explore/presentation/widgets/film_roll_developing_view.dart:33-39` — 이미 만료된 시각으로 마운트되면 불필요한 타이머가 1틱 더 돈다**

```dart
void initState() {
  super.initState();
  _updateRemaining();               // _ticker가 아직 null이라 cancel()이 no-op
  _ticker = Timer.periodic(const Duration(seconds: 1), (_) {
    _updateRemaining();
  });
}
```

`developAvailableAt`이 이미 과거인 상태로 화면에 진입하면(예: 카운트다운 다 끝난 뒤 앱 재시작), 첫 `_updateRemaining()` 호출 시점엔 `_ticker`가 아직 할당되지 않아 `_ticker?.cancel()`이 아무 효과가 없고, 그 뒤 무조건 `Timer.periodic`이 시작된다. 다음 tick(1초 후)에서야 취소된다. 실사용에 지장은 없지만(1초짜리 낭비 tick), 아래처럼 타이머 생성 여부를 조건부로 하면 더 명확하다.

```dart
void initState() {
  super.initState();
  _updateRemaining();
  if (_remaining > Duration.zero) {
    _ticker = Timer.periodic(const Duration(seconds: 1), (_) => _updateRemaining());
  }
}
```

**`lib/features/explore/presentation/widgets/film_roll_developing_view.dart` — `didUpdateWidget` 미구현으로 `developAvailableAt` 변경에 대응하지 못함**

`ExploreScreen`이 `ValueKey(_activeFilmRoll!.id)`로 이 위젯을 키잉하므로, 같은 필름롤 id를 유지한 채 `reevaluate()`가 새 `FilmRoll` 인스턴스를 내려줘도 `State`는 재사용되고 `initState`는 다시 호출되지 않는다. 현재 코드 경로상 `developing` 상태의 `developAvailableAt`이 이후 변경될 일은 없어 실질적 버그는 아니지만, `FilmRollProgressView`가 이미 `didUpdateWidget`으로 이런 종류의 prop 변화에 대응하는 패턴을 쓰고 있으니 일관성 차원에서 아래처럼 방어적으로 맞춰두면 좋다.

@override
void didUpdateWidget(covariant FilmRollDevelopingView oldWidget) {

**`lib/features/film_roll/domain/usecase/exit_film_roll_use_case.dart:41-43` — `developAvailable`과 `status` 불일치 시 OR로 관대하게 판정**

### ✅ Positive (잘한 점)

- **`FilmRollSyncService.syncFilmRoll`의 `skipRegionCheck` 옵션**: 기본값 `false`로 기존 호출부(`EnterRegionUseCase`, `FilmRollController`)에 영향을 주지 않으면서, 이탈 확정 시점에만 지역 검사를 우회하도록 최소 침습적으로 확장했다. 이 시나리오를 커버하는 테스트(`skipRegionCheck가 true면 지역이 달라도 동기화한다`)도 함께 추가돼 있다.
- **`FilmRollExitResponse.developAvailableAt`을 nullable로 선제 방어**: BE 스펙이 확정되지 않은 상태에서 EXPIRED 응답에 필드가 없을 가능성을 미리 방어하고, `ExitFilmRollUseCase`에서 `exitedAt + 1h` fallback으로 이어지는 처리가 자연스럽다.
- **로컬 DB source-of-truth 원칙 유지**: `exitFilmRoll`/`getFilmRoll` 응답을 로컬 상태 전이의 트리거로만 쓰고, 화면은 항상 로컬 `FilmRoll`을 렌더링하는 기존 아키텍처 원칙을 그대로 따랐다.
- **마이그레이션 회귀 테스트 갱신**: `migration_v4_test.dart`의 `schemaVersion` 하드코딩을 `greaterThanOrEqualTo(4)`로 바꿔, 버전이 계속 올라가도 v4 컬럼 존재 자체를 검증하는 테스트가 깨지지 않게 했다. `migration_v5_test.dart`도 같은 패턴으로 신설.
- **`recoverLastActiveFilmRoll`/컬렉션 화면/카메라 진입** 세 지점 모두에 `developing` 상태를 빠짐없이 반영해, 상태 하나를 추가할 때 흔히 놓치기 쉬운 주변 로직 누락이 없었다.

### 💡 Minor (개선 권장)

**`lib/core/network/token_storage.dart:9`** — 사용되지 않는 테스트용 주입 파라미터
현재:
```dart
TokenStorage._({FlutterSecureStorage? storage})
  : _storage = storage ?? const FlutterSecureStorage(...);
```
생성자가 `private`이라 `TokenStorage._()`는 이 파일 내부(`instance` getter)에서만 호출되고, 실제로 `storage`를 넘기는 호출부는 어디에도 없습니다. 지금 시점에는 죽은 파라미터입니다.
제안: (a) 테스트 인프라를 이번에 같이 만들 게 아니라면 파라미터를 제거하고 필요해질 때 다시 추가하거나, (b) 정말 테스트 주입을 염두에 둔 거라면 `TokenStorage`를 인터페이스로 뽑아 fake를 만들 수 있게 하는 등 실제로 쓰이는 형태로 완성하는 게 좋습니다. 현재는 "혹시 몰라 열어둔 훅"이라 프로젝트 원칙(불필요한 추상화 지양)과 어긋납니다.
이유: 사용되지 않는 확장 지점은 읽는 사람에게 "누가 이걸 쓰나?"라는 혼란을 주고, 실제 테스트를 작성할 때도 이 훅만으로는 부족합니다(플랫폼 채널 기반이라 `FlutterSecureStorage` 자체를 mock하기 어려움).

**`lib/features/auth/presentation/signup_screen.dart:71`** — 빈 토큰 응답 시 조용히 "성공" 화면으로 진행
현재:
```dart
if (tokens.accessToken.isNotEmpty) {
  await TokenStorage.instance.saveTokens(...);
}
if (!mounted) return;
await Navigator.pushReplacement(... HomeScreen ...);
```
백엔드가 200을 반환했지만 `data`가 비어 `AuthApi.signUp`이 `TokenResponse.empty()`로 폴백하는 경우, 토큰 저장은 건너뛰지만 `log('회원가입 성공', ...)`을 찍고 그대로 `HomeScreen`으로 이동합니다. 사용자는 "가입 성공" 화면을 보지만 실제로는 인증 토큰이 없어 이후 API 호출이 전부 401로 실패하는 상태가 됩니다.
제안: `accessToken.isEmpty`인 경우를 정상 흐름이 아니라 에러로 취급해 `_errorMessage`를 세팅하거나 예외를 던지는 편이 사용자에게 더 정직합니다.
이유: 발생 가능성은 낮지만(백엔드 계약 위반 케이스), 조용히 넘어가면 "성공했는데 왜 로그인이 안 되지?"라는 훨씬 디버깅하기 어려운 증상으로 이어집니다.

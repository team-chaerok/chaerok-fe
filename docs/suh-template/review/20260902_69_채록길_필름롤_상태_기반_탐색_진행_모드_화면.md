## ⚠️ Major (배포 전 수정)

### M1. 방문 인증 게이트가 stale 좌표로 통과될 수 있음 — 명세 위반
**`film_roll_progress_view.dart:154-168` (`_onVisitTap`), `:240-247` (`_isVerifiable`)**

- 문제: `evaluateVisitGate(position: widget.currentPosition, ...)`는 부모(`ExploreScreen`)가 마지막으로 조회해 둔 좌표를 쓴다. 이 좌표는 수 분 전 값일 수 있고, `_onVisitTap`은 인증 직전 재조회를 하지 않는다. analyze §(e)는 "인증 직전 최신 좌표를 다시 받아 stale 좌표로 통과되는 것을 막는다"를 명시했다.
- 영향: 사용자가 장소를 떠난 뒤에도 예전 좌표로 인증이 통과될 수 있음. GPS 정확도 재확인(accuracy ≤ 50m)도 오래된 fix에 대해 수행돼 의미가 약해짐.
- 해결: `_onVisitTap` 진입 시 `await LocationPermissionService.getCurrentPosition()`(또는 부모의 `onRequestPosition` 후 반환값)으로 **새 좌표를 받아** 그 값으로 게이트를 평가한다. 실패 시 `noPosition` 처리.
  ```dart
  Future<void> _onVisitTap(FilmRollPlace place) async {
    final position = await LocationPermissionService.getCurrentPosition();
    final gate = evaluateVisitGate(position: position, ...);
    ...
  }
  ```
  (`_isVerifiable`/마커/필터의 "인증 가능"은 실시간성이 덜 중요하니 `widget.currentPosition` 유지 가능. 단, 부모가 주기적으로 위치를 갱신하도록 `onRequestPosition`을 진입 시 1회 호출 권장.)

### M2. 북마크 식별자가 검색 결과 vs 지역 목록에서 달라짐
**`explore_place.dart:88-100` (`_identityKey`)**

- 문제: `PlaceSearchResponse.id`는 non-null이라 검색에서 온 장소는 항상 `place:SOURCE:<id>` 키를 갖는다. 반면 `getExternalPlaces`(TourAPI 실시간)는 대부분 `id == null`이라 `external:SOURCE:<외부ID>` 또는 `title:...` 키를 갖는다. **같은 물리적 장소인데 진입 경로에 따라 identityKey가 달라진다.**
- 영향: 검색에서 북마크한 장소를 지역 목록에서 보면 북마크 표시가 안 되고, 중복 저장된다.
- 해결: 북마크 identityKey를 항상 외부 ID 우선(`tourContentId`/`kakaoPlaceId`)으로 만들고 서버 ID는 후순위로 두거나, 두 키를 모두 인덱싱한다. 최소한 `BookmarkStore`에 `(externalId, serverId)` 양쪽을 저장해 매칭 시 OR 비교.

### M3. "미기록" 카테고리 필터가 사실상 "전체"와 동일 (죽은 컨트롤)
**`explore_screen.dart:202` — `_selectedFilter.matches(place, isRecorded: false)`**

- 문제: 탐색 모드에서 `isRecorded`를 상수 `false`로 넘긴다. `ExploreCategoryFilter.unrecorded.matches` → 항상 `true`. "미기록" 칩이 "전체"와 결과가 같다.
- 영향: 사용자에게 동작하지 않는 필터를 노출. 시안 6b의 "미기록"/"기록 3개" 표현과도 불일치.
- 해결(택1): (a) 완료된 필름롤들의 방문 장소를 로컬 집계해 `isRecorded` 계산(범위 크면 별도 이슈), (b) 이번 범위에선 "미기록" 칩을 **빼거나** "북마크"로 대체, (c) 북마크 여부로 재정의. 최소 (b)로 오해 소지 제거.

### M4. 검색어 상태와 TextField가 분리됨 + 지역 변경 시 debounce 미취소
**`explore_screen.dart:119-127` (`_onRegionSelected`), `:434-454` (`_buildSearchField`)**

- 문제 1: `TextField`에 `controller`가 없어, `_onRegionSelected`가 `_searchKeyword=''`로 만들어도 입력창의 글자는 그대로 남는다(상태-뷰 불일치).
- 문제 2: `_onRegionSelected`가 `_searchDebounce?.cancel()`을 하지 않는다. 지역 전환 직전에 입력된 debounce 타이머가 새 `_regionId`로 뒤늦게 `_search`를 실행해, 이전 지역 키워드의 검색 결과가 새 지역 목록 위에 얹힐 수 있다.
- 해결: `TextEditingController`를 도입해 `dispose`에서 정리하고 지역 변경 시 `.clear()`. `_onRegionSelected`(및 `dispose`)에서 `_searchDebounce?.cancel()`.

### M5. 현상 조건 "확인하는 중" 무한 고착 + 재시도 수단 없음
**`film_roll_progress_view.dart:103-113` (`_loadVisits`), :391-403 (`_developConditionLabel`)**

- 문제: `_serverFilmRollId != null`인데 `getVisits`가 매번 실패(네트워크/서버 상태)하면 `_visits`는 계속 null → 라벨이 영구히 "현상 조건을 확인하는 중이에요". 재시도 버튼도, 탭 재진입 시 재조회도 없다(`didUpdateWidget` 부재).
- 영향: 사용자가 현상 조건을 영영 못 봄.
- 해결: `_loadVisits` 실패를 상태로 남겨(`_visitsLoadFailed`) "현상 조건을 불러오지 못했어요 · 다시 시도" 어피던스 노출. `didUpdateWidget`에서 `widget.filmRoll.serverFilmRollId`가 null→값 전이면 `_loadVisits()` 재호출. 방문 인증 후에도 재호출(현재는 함).

### M6. 신규 도메인 로직 테스트 0건
**`visit_verification.dart`, `explore_category_filter.dart`, `explore_place.dart`, `bookmark_store.dart`**

- 문제: `evaluateVisitGate`(4단계 경계), `ExploreCategoryFilter.matches`(그룹/키워드 매칭), `ExplorePlace._identityKey`(우선순위), `BookmarkStore.toggle`(추가/제거) 모두 순수·목킹 가능하나 테스트가 없다. analyze §3의 테스트 계획 미이행.

## 💡 Minor (개선 권장)

### m1. 지도 지연 로드가 실질적으로 동작하지 않음
`explore_screen.dart:79-81` — `addPostFrameCallback`로 `_mapEnabled=true`를 첫 프레임 직후 세팅. `ExploreScreen`은 `IndexedStack` 안이라 탭이 안 보여도 첫 프레임에 곧바로 지도 네이티브 뷰가 생성된다. analyze ⚠️4의 "탭 최초 진입 전까지 지연"은 미달성. → `MainTabScreen`이 탭 1 최초 진입 시 플래그를 올려 전달하거나, `VisibilityDetector` 도입.

### m2. `_onVisitTap` 게이트 실패 후 자동 재평가 없음
`film_roll_progress_view.dart:161-168` — `noPosition`/`inaccurate`면 `onRequestPosition()`으로 위치만 재조회하고 사용자가 버튼을 **다시** 눌러야 한다. 재조회 후 게이트를 한 번 더 평가해 바로 진행하거나, 최소 "위치를 다시 잡았어요. 다시 시도해주세요" 안내.

### m3. `BookmarkStore.toggle` read-modify-write 경합
`bookmark_store.dart:107-121` — `list()`→`setString` 사이 await로 두 토글이 인터리브되면 lost update. 사용자 페이스상 드물지만, 단일 `Future` 체인으로 직렬화(`_mutex`)하면 안전.

### m4. `_bookmarkedKeys` 로컬 낙관적 갱신이 스토어와 드리프트 가능
`explore_screen.dart:220-232` — `toggle` 결과로 set을 직접 재구성. m3의 경합이 나면 화면 set과 저장소가 어긋난다. `toggle` 후 `BookmarkStore.instance.bookmarkedKeys()` 재조회가 단순·안전.

### m5. 마커 재동기화 시 전체 제거→재추가로 깜빡임
`explore_map_view.dart:116-145` (`_syncMarkers`) — 필터 변경마다 모든 POI 삭제 후 `KImage.fromWidget`(위젯→이미지 렌더, 저렴하지 않음)를 순차 await하며 재추가. 3~30개 규모에서 수백 ms 깜빡임 가능. id 기준 diff(신규만 add, 사라진 것만 remove)로 개선.

### m6. `_focusMarker`가 한 번 설정되면 안 지워짐
`film_roll_progress_view.dart:81, 202-207` — "다음 코스 둘러보기" 후 그 장소를 방문해도 `_focusMarker`는 옛 장소를 가리킨 채 남는다. `didUpdateWidget`/방문 후 `_focusMarker=null` 또는 `_nextPlace`로 갱신.

### m7. 코스 미선택 시 지도가 먼 기본 좌표를 표시
`film_roll_progress_view.dart:322-329` — `!hasCourse`면 마커가 없어 `KakaoMapOption.defaultPosition`(수도권)만 보이는 빈 지도가 "추천 코스 선택하기" 위에 놓인다. 코스 미선택이면 지도를 숨기거나 지역 중심 좌표를 전달.

### m8. 게이트 4단계 순서가 명세와 다름
`visit_verification.dart:38-70` — 사용자 지정 순서는 "거리계산 → accuracy → 거리 → 중복". 구현은 중복을 맨 앞에서 검사(결과 집합은 동일, 실패 사유 문구만 상이). 의도적이면 주석으로 근거 명시. `evaluateVisitGate` DartDoc의 번호와 실제 코드 순서도 맞추기.

## ✅ Positive (잘한 점)

- **`evaluateVisitGate` / `ExploreCategoryFilter.matches` 를 순수 함수·enum으로 분리** — 게이트/필터 로직이 위젯과 독립적이라 테스트·재사용 용이(analyze 방향 준수).
- **`PlaceCategoryGroup/Detail` enum에 `unknown` 폴백** — 백엔드가 값을 추가해도 파싱이 깨지지 않음. 과거 장소 API 분석의 우려를 반영.
- **`ExplorePlace`로 목록/검색 응답을 정규화** — 별개 DTO 타입을 화면에서 하나로 다루는 관례적 해법. `identityParts` 우선순위도 기존 `NearbyPlaceRecorder`와 일관(식별 소스 불일치 M2만 보완하면 됨).
- **`serverFilmRollId == null` graceful degradation** — 현상 조건을 못 받아도 로컬 진행률로 안전하게 표시.
- **요청 토큰(`_fetchRequestId`/`_searchRequestId`) 경합 방어**를 기존 화면(`home_dashboard_screen`)과 동일 패턴으로 적용.
- **`ExploreMapView`의 세대(`_syncGeneration`) 가드 + 좌표 유효성 필터** — `CourseMapView`의 정적 한계를 넘어 동적 갱신을 안전하게 처리(깜빡임 m5만 개선 여지).
- **"필름 카메라 열기"는 촬영만, 방문 인증은 게이트 통과 시에만** — 인증 게이트의 실효성을 지키는 올바른 분리.

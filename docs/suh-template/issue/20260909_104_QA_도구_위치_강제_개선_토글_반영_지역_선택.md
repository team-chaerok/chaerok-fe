📝 현재 문제점
---

원거리 테스터가 Test Mode(QA) 패널로 위치 기반 시나리오를 검증하기 어렵다. 두 가지 지점이 막혀 있다.

### 1. "충남 외 지역 홈 강제" 토글이 껐다 켜도 반영되지 않음

- QA 도구의 스위치를 토글하면 `AppPreferences.setDebugOutOfServiceArea` 값만 바뀌고, 홈 대시보드가 이미 계산해 둔 세션 상태(`LocationVerificationResult.sessionCache` / `outOfServiceSessionCache`)는 그대로 남는다.
- 홈 대시보드는 최초 진입 시 한 번만 위치 인증을 수행하고, 이후 탭 재진입·앱 포그라운드 복귀에서는 위치 인증을 다시 태우지 않는다. 그래서 토글을 바꾸고 홈으로 돌아가도 화면이 그대로이고, 앱 재실행이나 "테스트 상태 초기화" 전까지는 결과를 확인할 수 없다.
- `공주 진입` · `테스트 상태 초기화` 핸들러는 세션 캐시를 명시적으로 비우지만, 이 토글 핸들러(`_onForceOutOfServiceChanged`)는 그 처리를 하지 않는다.
- 관련 파일:
  - `lib/features/test_mode/presentation/test_mode_panel_screen.dart` (`_onForceOutOfServiceChanged`)
  - `lib/features/home/presentation/home_dashboard_screen.dart` (`_ensureLocationVerified`, `_isOutOfService`)
  - `lib/features/location/data/location_verification_runner.dart`

### 2. 내 위치를 조정할 수 없음 — 항상 공주 고정

- QA 패널 시나리오에는 `1. 공주 진입`만 있고 `_onEnterGongju`가 `공주시`를 하드코딩한다. `TestModeSession.enterGongju()` 상태에서는 `MockLocationGate.currentMockPosition()`이 다른 설정을 무시하고 공주 대표 좌표를 반환한다.
- 지역별 둘러보기 홈 · 탐색 · 지역 판별 등을 QA하려면 부여/서산/예산 등 다른 지역이나 임의 좌표에서 시작할 수 있어야 하는데, 패널에 위치를 고를 방법이 없다.
- 내부적으로는 `mockLocationSpots`(gongju·buyeo·seosan·yesan)와 `AppPreferences.getMockRegionCodeName` / `getMockSpotIndex`가 이미 존재하지만 QA 패널에서 노출·제어되지 않는다.
- 관련 파일:
  - `lib/features/test_mode/presentation/test_mode_panel_screen.dart`
  - `lib/core/location/mock_location_gate.dart`
  - `lib/core/location/mock_location_spots.dart`

🛠️ 해결 방안 / 제안 기능
---

- **토글 즉시 반영**: "충남 외 지역 홈 강제" 값이 바뀌면 위치 인증 세션 캐시를 무효화하고, 홈 대시보드가 다음 표시에서 위치 판정을 다시 수행하도록 한다. 토글만으로 홈 상태(정상 홈 ↔ 지역별 둘러보기 홈)가 바뀌는 것을 확인할 수 있어야 한다.
- **위치(지역/스팟) 선택 UI 추가**: QA 패널에서 mock 위치를 직접 고를 수 있게 한다.
  - `mockLocationSpots`에 정의된 지역(공주·부여·서산·예산)과 스팟 선택
  - 가능하면 임의 위도/경도 직접 입력도 지원(서비스 지역 외 좌표 QA용)
  - 선택한 위치가 `공주 진입` 시나리오·방문 인증 좌표 주입보다 우선순위가 낮게 유지되도록 정리(기존 시나리오 흐름은 그대로).
- **현재 적용 위치 표시**: 지금 적용 중인 mock 위치(지역/좌표)를 패널 상단 상태 카드에 노출한다.

⚙️ 작업 내용

- `MockLocationGate.currentMockPosition` 우선순위 동작·주석 점검
- 상태 카드에 "현재 mock 위치" 항목 추가

📝 현재 문제점
---

- 필름롤 생성 / 코스 선택 / 방문 인증 / 사진은 현재 전부 로컬(Drift + 파일 시스템)에서만 처리되고 있고, 백엔드와 전혀 연동되어 있지 않다.
- `FilmRollsApi` / `VisitsApi` 는 클래스와 DTO가 정의되어 있으나 앱 어디에서도 호출되지 않는다. `isSynced` 컬럼도 예약만 되어 있고 항상 로컬 전용으로만 쓰인다.
- 이는 이슈 #41(로컬 필름롤 아키텍처)에서 "오프라인에서도 조회·방문·촬영이 끊기지 않아야 한다"는 요구로 내린 의도적 결정이지만, 서버에 필름롤/방문 기록이 남지 않아 기기 변경·재설치 시 데이터가 소실되고, 서버 측 통계·현상(develop) 파이프라인과 연결할 수 없다.
- 이슈 #61(홈 화면 API 연동 점검)에서도 "서버 필름롤 / 방문 API 와 로컬 상태 정합성 미확인" 항목이 남아 있다.

🛠️ 해결 방안 / 제안 기능
---

- 로컬을 계속 source of truth로 유지한 채, **필름롤 생성과 방문 기록을 백엔드에 반영**하는 동기화 계층(`FilmRollSyncService`)을 추가한다.
- 로컬 UUID는 `clientFilmRollId`로 그대로 두고, 서버 생성 성공 시 응답 `filmRollId`를 같은 로컬 행의 `serverFilmRollId`에 저장한다. 생성 재시도 시 새 UUID를 만들지 않고 기존 UUID를 재사용한다.
- `serverFilmRollId == null`이어도 로컬 촬영·방문은 정상 동작하며, 온라인 복귀 후 정해진 트리거 지점(지역 진입 / 필름롤 화면 로드 / 방문 인증 후 / 수동 재시도)에서 동기화를 재시도한다.
- 방문 기록(`isVisited`)은 `POST /api/film-rolls/{serverFilmRollId}/visits` 로 전송하고, 서버에 반영된 장소는 `visitSyncedAt` 으로 표시한다.
- "현재 진행 중 롤 판단"은 계속 로컬 필름롤 기준으로 하며, `GET /api/film-rolls/current` 는 생성 충돌 복구 용도로만 1회 제한적으로 사용한다.
- 서버 `status` 는 로컬에 미러링만 하고, 완료(COMPLETED) 게이팅 로직 전환은 이번 범위에서 제외한다(현상/exit 선행 필요).
- **사진 서버 업로드는 이번 범위 제외** — 백엔드가 "사진 1장씩 업로드" API를 추가하기로 합의됨. 명세 확보 전까지 코드에 TODO 표식만 남긴다.
- 동기화는 항상 로컬 행의 계정이 현재 로그인 계정과 일치할 때만 수행한다(계정 전환 시 이전 계정 데이터 미동기화).

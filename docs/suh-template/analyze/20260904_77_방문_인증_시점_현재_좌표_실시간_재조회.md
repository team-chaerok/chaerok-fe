## 🔍 현재 상태

### 방문 인증 게이트 흐름

```
ExploreScreen._loadCurrentPosition()
  └─ LocationPermissionService.getCurrentPosition()  ← 앱/탭 진입 시 1회, onRequestPosition 시 재조회
       └─ setState(_currentPosition = position)      ← 수 분 전 값으로 고착 가능

ExploreScreen.build()
  └─ FilmRollProgressView(currentPosition: _currentPosition, onRequestPosition: _loadCurrentPosition)

FilmRollProgressView._onVisitTap(place)              ← lib/features/explore/presentation/widgets/film_roll_progress_view.dart:164
  └─ evaluateVisitGate(position: widget.currentPosition, ...)   ← ⚠️ stale 좌표로 평가
       ├─ canVerify=false → SnackBar(gate.message)
       │    └─ status ∈ {noPosition, inaccurate} 이면 await widget.onRequestPosition()  ← 이번 탭에는 반영 안 됨(다음 탭부터)
       └─ canVerify=true  → VisitCaptureScreen push → completeVisit → _loadVisits
```

### `evaluateVisitGate` (lib/features/film_roll/domain/visit_verification.dart)

- 순수 함수. 입력: `position`, `placeLatitude/Longitude`, `alreadyVisited`.
- 4단계 게이트: `alreadyVisited` → `position == null`(noPosition) → `accuracy > 50m`(inaccurate) → `distance > 100m`(tooFar) → `ok`.
- **이미 좌표만 주면 검증되는 구조라 재조회 로직은 이 함수 밖(호출부)에만 추가하면 된다.**

### `widget.currentPosition` 사용처 (총 4곳)

| 위치 | 용도 | 실시간성 필요 |
|------|------|--------------|
| `_onVisitTap` (:165) | **방문 인증 실행 게이트** | ✅ **필수 (이번 이슈 대상)** |
| `_isVerifiable` (:251) | 마커 색상 / "인증 가능" 필터 / 타일 라벨 | ❌ (참고 표시용, #69 리뷰도 유지 허용) |
| `_buildNextSpotCard` (:471) | "다음 장소" 카드의 안내 문구(`gate.message`) | ❌ (안내용) |
| `_buildMarkers` → `_isVerifiable` | 지도 마커 상태 | ❌ |

### 테스트 자산

- `evaluateVisitGate` 전용 테스트 **없음** (신규 필요).
- `FilmRollProgressView` 위젯 테스트 **없음**.
- 참고 패턴: `test/features/film_roll/presentation/page/visit_capture_screen_test.dart` — `PermissionHandlerPlatform.instance` / `CameraPlatform.instance`에 fake 주입.
- `LocationPermissionService.getCurrentPosition()`는 내부에서 `Geolocator.checkPermission()`(비 macOS는 `Permission.locationWhenInUse.status`) + `Geolocator.getCurrentPosition()` 호출 → 위젯 테스트 시 `GeolocatorPlatform.instance` + `PermissionHandlerPlatform.instance` fake 필요.

## 🎯 구현 목표

1. **방문 인증 버튼을 누른 시점(`_onVisitTap` 진입)에 `getCurrentPosition()`으로 새 좌표를 받아, 그 좌표로 `evaluateVisitGate`를 평가한다.**
2. 재조회 지연 동안 **로딩 표시**(중복 탭 차단 포함), 재조회 **실패(null) 시 `noPosition` 게이트로 처리**(현행 메시지/`onRequestPosition` 재사용).
3. 재조회로 얻은 좌표를 부모에도 올려 화면 다른 부분(`_isVerifiable` 등)도 최신화(선택, 권장).
4. **신규 좌표로 게이트를 평가하는 단위 테스트** + 재조회 흐름 위젯 테스트 추가.
5. `_isVerifiable`/마커/필터/`_buildNextSpotCard` 문구는 `widget.currentPosition` 유지 (스코프 밖).

### 비목표 (이번 이슈에서 다루지 않음)

- `_isVerifiable`·마커·필터의 실시간화.
- 탐색/진행 화면의 `LocationProviderFactory`(mock 위치) 연동 — 별도 이슈 권장(⚠️ 아래 참조).
- `evaluateVisitGate` 시그니처/게이트 단계 변경.

## 📝 상세 구현 계획

### 1️⃣ 준비 단계

- 신규 의존성 없음. `geolocator`, `permission_handler`, `flutter_test` 모두 존재.
- 위치 재조회는 기존 `LocationPermissionService.getCurrentPosition()` 재사용 — 형제 호출부(`ExploreScreen._loadCurrentPosition`, `VisitCaptureScreen._onCaptureTap`)와 동일 방식으로 맞춘다.
- `import 'package:chaerok/features/location/data/location_permission_service.dart';`를 `film_roll_progress_view.dart`에 추가.

### 2️⃣ 핵심 구현

#### (A) `lib/features/explore/presentation/widgets/film_roll_progress_view.dart`

**상태 필드 추가**
- `bool _isVerifyingLocation = false;` — 재조회 진행 중 플래그(중복 탭 차단 + 버튼 로딩).

**`_onVisitTap(FilmRollPlace place)` 재작성** (현재 :164-193)
- 진입 가드: `if (_isVerifyingLocation) return;`
- `if (place.isVisited)` 조기 처리(이미 방문) — 재조회 없이 기존 `alreadyVisited` 메시지 표시(불필요한 GPS 호출 방지).
- `setState(() => _isVerifyingLocation = true);`
- `try`:
  - `final position = await LocationPermissionService.getCurrentPosition();`
  - `if (!mounted) return;`
  - (권장) `position != null`이면 부모로 전달 → `widget.onPositionResolved?.call(position)` 또는 기존 `onRequestPosition` 대체 콜백. 최소안은 생략 가능.
  - `final gate = evaluateVisitGate(position: position, placeLatitude: place.latitude, placeLongitude: place.longitude, alreadyVisited: place.isVisited);`
  - `if (!gate.canVerify)`:
    - `_showSnackBar(gate.message);`
    - `if (gate.status == VisitGateStatus.noPosition || gate.status == VisitGateStatus.inaccurate) { await widget.onRequestPosition(); }` (현행 로직 유지 — 재조회 결과가 null/부정확일 때 부모도 갱신 유도)
    - `return;`
  - 통과 시: 기존 로직 그대로 — `VisitCaptureScreen` push → `_controller.completeVisit(place.id)` → `_loadVisits()`.
- `finally`: `if (mounted) setState(() => _isVerifyingLocation = false);`

**로딩 표시**
- `_buildNextSpotCard`의 `ChaerokButton(text: '방문 인증하기', ...)` (:508)에 `isLoading: _isVerifyingLocation` 추가 → `ChaerokButton`이 `isLoading` 시 스피너 표시 + `onPressed` 무효화 지원(확인함, `chaerok_button.dart:29`).
- `_buildPlaceTile`의 `TextButton('방문 인증')` (:590-593)은 `onPressed: _isVerifyingLocation ? null : () => _onVisitTap(place)`로 비활성화(간단). 필요 시 텍스트를 '확인 중…'으로 스왑.
- 대안: 전역 모달 배리어(`showDialog` 스피너) — 단, 코드베이스에 해당 패턴 없음 → 버튼 단위 로딩이 기존 스타일(`_isCompleting`, `_isResolvingRegion`, `isLoading`)과 일치.

**정확도(accuracy) 재확인 의미 회복**
- 새 좌표로 `accuracy > 50m` 검사가 수행되므로 `inaccurate` 분기가 "이번 시도"에 대해 유효해짐 — 추가 코드 불필요, 재조회만으로 해결.

#### (B) (권장) 재조회 좌표를 부모에 반영 — `explore_screen.dart` + `film_roll_progress_view.dart`

- 목적: 인증 탭 시 얻은 최신 좌표로 `_isVerifiable`/마커/거리 라벨도 갱신 → 화면 일관성.
- 방법 1 (콜백 추가): `FilmRollProgressView`에 `final ValueChanged<Position>? onPositionResolved;` 추가, `_onVisitTap`에서 `position != null`일 때 호출. `ExploreScreen`은 `onPositionResolved: (p) { if (mounted) setState(() => _currentPosition = p); }`.
- 방법 2 (최소): 생략하고 `_onVisitTap` 로컬에서만 사용 — 이슈 요구사항은 충족. 다른 표시가 잠깐 stale일 수 있음.
- **권장: 방법 1** (비용 작고 #69 리뷰 의도에 부합). 스코프 커지는 게 부담되면 방법 2.

#### (C) 위치 재조회 실패 UX

- `getCurrentPosition()`은 내부적으로 예외를 삼키고 `null` 반환(권한 없음 / 타임아웃 30s / 서비스 꺼짐 모두 null).
- `null` → `evaluateVisitGate(position: null)` → `noPosition` → `'현재 위치를 확인하는 중이에요'` SnackBar + `onRequestPosition()`.
- 30초 타임아웃 동안 `_isVerifyingLocation` 스피너가 계속 도는 문제 → 허용 가능하나, 필요 시 `_positionTimeLimit`은 서비스 내부값이라 그대로 두고 안내 문구만 신뢰.

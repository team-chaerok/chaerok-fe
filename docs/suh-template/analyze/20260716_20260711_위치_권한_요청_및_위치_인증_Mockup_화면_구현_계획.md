### 📊 분석 요약

**감지된 프로젝트 타입**: Flutter
**주요 기술 스택**: Dart SDK `^3.9.2`, Flutter 3.35.5(stable), 상태관리는 별도 라이브러리 없이 `StatefulWidget` + `setState`, 네트워크는 `dio` 기반 `DioClient` 싱글톤 + `ApiResponse<T>` 래퍼, 인증은 `flutter_secure_storage` 기반 `TokenStorage` 싱글톤
**코드 스타일**:
- 파일명 snake_case, 클래스명 UpperCamelCase
- `lib/features/<feature>/data/`(서비스) + `presentation/`(화면) 분리 (예: `auth`)
- API 클래스는 `static` 메서드 + private 생성자(`const ClassName._()`), `DioClient.instance` 사용, 실패 시 fallback 값(`?? const []`, `?? XxxResponse.empty()`) 반환

- `initState`에서 비동기 초기화 시 `unawaited(_fetchXxx())` 패턴
- 디자인 시스템: `ChaerokColors`/`ChaerokSpacing`/`ChaerokTypography`/`ChaerokRadius` 상수 클래스 사용, 매직넘버 하드코딩 지양
- 공통 버튼은 `ChaerokButton`(`shared/widgets/`) 재사용
- 린트: `flutter_lints` + `require_trailing_commas`, `prefer_single_quotes`, `always_declare_return_types`, `type_annotate_public_apis`, `unawaited_futures`, `discarded_futures`, `use_build_context_synchronously` 등 엄격 규칙 적용 중

### 🔍 현재 상태

- `pubspec.yaml`: 위치 관련 패키지 없음 (`dio`, `flutter_secure_storage`, `google_sign_in`, `kakao_flutter_sdk_user`, `cupertino_icons`만 존재)
- `android/app/src/main/AndroidManifest.xml`, `android/app/src/debug|profile/AndroidManifest.xml`: `INTERNET` 권한 외 위치 권한 선언 없음
- `ios/Runner/Info.plist`: 위치 사용 목적 문자열(`NSLocationWhenInUseUsageDescription` 등) 없음
- `lib/features/`: `auth`, `home`, `settings`, `splash`만 존재, `location` feature 없음
- `lib/data/models/resolve_region_request.dart`, `region_response.dart`: 모델만 정의되어 있고 실사용처(API 클래스, 호출부) 전혀 없음(grep 0건) — 이번 작업 범위 밖
- `lib/app/app.dart` → `SplashScreen`(시작) → `TokenStorage.resolveSession()`으로 세션 확인 → 인증됨: `HomeScreen`, 아니면 `LoginScreen`
- `login_screen.dart`: `_handleLoginResponse()`에서 토큰 저장 성공(`saved == true`) 시 `HomeScreen`으로 `pushReplacement` (109~113행)
- `signup_screen.dart`: `_onSignupTap()`에서 토큰 저장 성공 시 `HomeScreen`으로 `pushReplacement` (77~86행)
- `flutter pub add geolocator permission_handler --dry-run` 검증 결과, 현재 SDK 제약(`^3.9.2`)과 충돌 없이 `geolocator 14.0.2`, `permission_handler 12.0.3`으로 해석됨 (pubspec.yaml은 아직 미수정 상태로 확인만 완료)

### ⚠️ 주의사항

- **iOS 크래시 위험**: `Info.plist`에 `NSLocationWhenInUseUsageDescription`이 없으면 위치 API 호출 시 앱이 즉시 크래시한다. 반드시 준비 단계에서 함께 반영해야 함.
- **Podfile 매크로 누락**: `permission_handler` 최신 버전(9.x 이상 iOS 플러그인)은 iOS에서 사용할 권한 종류를 `Podfile`의 `post_install`에서 `GCC_PREPROCESSOR_DEFINITIONS`로 명시적으로 켜야 한다. 이걸 빠뜨리면 iOS에서 권한 요청이 조용히 실패할 수 있다.
- **로그인/회원가입 흐름 차단 금지**: 위치 권한 거부가 로그인 자체를 막아서는 안 됨(이슈 요구사항에도 "위치 권한 요청"만 명시, 필수 게이트 조건 아님) — 권한 요청 실패/거부와 무관하게 `HomeScreen` 이동은 정상 진행되도록 구현.
- **`context.mounted` 체크**: `use_build_context_synchronously` 린트가 활성화되어 있으므로, 권한 요청(비동기) 이후 `Navigator` 호출 전 반드시 `context.mounted` 재확인 필요 (기존 코드 패턴과 동일).
- **resolveRegion/주기적 위치 확인 범위 외**: `ResolveRegionRequest`/`RegionResponse`를 이번 작업에서 임의로 연동하지 말 것 — 실사용 API 엔드포인트가 정의되어 있지 않아 백엔드와 스펙 협의가 선행되어야 함. 마찬가지로 주기적 위치 확인의 주기/트리거 조건도 미정이므로 이번 구현에 포함하지 않음.
- **패키지 버전**: `flutter pub add --dry-run` 기준 `geolocator 14.0.2`, `permission_handler 12.0.3`으로 현재 SDK 제약과 충돌 없이 해석됨. 실제 적용 시점에 다시 한번 `flutter pub add`로 최신 안정 버전 확인 권장.
- **Android minSdk**: `android/app/build.gradle.kts`가 `flutter.minSdkVersion`(Flutter 기본값)을 그대로 사용 중 — geolocator/permission_handler 요구 minSdk와 충돌 시 빌드 에러로 드러나므로 `flutter pub get` 직후 빌드 1회 필수.

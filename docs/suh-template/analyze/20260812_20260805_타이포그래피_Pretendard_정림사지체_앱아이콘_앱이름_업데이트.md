# 📊 분석 요약

**감지된 프로젝트 타입**: Flutter (Clean Architecture, feature-first)
**주요 기술 스택**: Flutter SDK `^3.9.2`, Material 3, `lib/core/design_system` 커스텀 디자인 시스템, drift/sqlite3 로컬 DB
**코드 스타일**: `dart format` 기준 trailing comma, `const` 생성자 적극 사용, 디자인 토큰(`ChaerokColors`/`ChaerokTypography`/`ChaerokSpacing`/`ChaerokRadius`)을 화면에서 참조하는 패턴

## 🔍 현재 상태

### 1. 타이포그래피

- `lib/core/design_system/chaerok_typography.dart`: `titleLarge`~`caption`, `progress` 등 9개 `TextStyle`이 모두 `fontFamily` 미지정 → OS 기본 폰트(Android: Roboto/Noto, iOS: San Francisco)로 렌더링됨.
- `jeongnimsajiFontFamily = 'Jeongnimsaji'` 상수만 정의돼 있고, `displayMedium`에는 "정림사지체와 함께 쓰는 걸 전제로 한다"는 주석만 있을 뿐 실제 `fontFamily` 필드는 비어 있음 → 상수 존재와 실제 적용이 분리되어 있음.
- `pubspec.yaml`의 `flutter.fonts`에는 `Jeongnimsaji`(weight 500, `assets/fonts/Jeongnimsaji-M.ttf`)만 등록. **Pretendard는 asset 파일도 pubspec 등록도 전혀 없음.**
- `lib/core/design_system/chaerok_theme.dart`의 `ChaerokTheme.light.textTheme`은 `ChaerokTypography`를 참조하지 않고 `titleLarge/titleMedium/bodyLarge/bodyMedium/labelLarge` 5개 스타일의 `fontSize/fontWeight`를 **직접 재작성**해 중복 정의하고 있음 (fontFamily도 물론 없음). 두 파일이 사실상 같은 값을 두 곳에서 따로 관리 중 → 하나를 고치면 다른 하나가 깨지는 구조.
- **실사용처는 2곳뿐**(요청 설명과 달리 "여러 화면에 산발적으로 적용"된 상태는 아님):
  - [home_dashboard_screen.dart:236](lib/features/home/presentation/home_dashboard_screen.dart#L236) — `ChaerokTypography.displayMedium.copyWith(fontFamily: ChaerokTypography.jeongnimsajiFontFamily, ...)` — **이미 `core/design_system`의 `ChaerokTypography`를 정상적으로 참조 중**. 다만 `fontFamily`를 매번 `copyWith`로 덮어써야 하는 게 문제.
  - [home_preview_screen.dart:180](lib/ui/home/home_preview_screen.dart#L180) — `UiPreviewTypography.jeongnimsajiFontFamily`를 사용하는데, 이는 `ChaerokTypography`가 **아니라** [lib/ui/preview_theme.dart](lib/ui/preview_theme.dart)에 별도로 정의된 **완전히 독립적인 병렬 디자인 시스템**(`UiPreviewColors`/`UiPreviewTypography`/`UiPreviewTheme`)임.

- **⚠️ 중요 발견 — 이중 디자인 시스템 구조**: `lib/main_ui_preview.dart`는 프로덕션 앱과 별개의 진입점으로, `MaterialApp(theme: UiPreviewTheme.light, home: HomePreviewScreen())`만 구동하는 **UI 프리뷰 전용 하네스**다. 실제 앱(`lib/main.dart` → `lib/app/app.dart` → `MaterialApp(theme: ChaerokTheme.light, ...)`)은 `home_preview_screen.dart`를 전혀 사용하지 않는다.
  - 즉 `home_preview_screen.dart`/`preview_theme.dart`는 배포되는 앱 코드가 아니라 디자인 검토용 별도 산출물이며, `ChaerokTypography`와 값(폰트 크기/weight/letterSpacing)이 상당 부분 겹치지만 클래스 자체가 다르다.
  - 요청 본문은 이 파일을 "디자인 시스템 레벨 미관리"의 근거로 들고 "ChaerokTypography 참조로 정리"를 요청했는데, 실제로는 **정리 대상이 하나가 아니라 두 개의 디자인 시스템**이다. `UiPreviewTypography`에도 `fontFamily` 규칙을 똑같이 넣을지, 아니면 이 기회에 `preview_theme.dart`를 걷어내고 `home_preview_screen.dart`가 `ChaerokTypography`/`ChaerokColors`를 직접 참조하도록 통합할지 결정이 필요함 (아래 ⚠️ 주의사항 참고).

### 2. Pretendard/정림사지체 폰트 파일

- `assets/fonts/`에는 `Jeongnimsaji-M.ttf`(1.7MB) 하나뿐. Pretendard 파일 자체가 저장소에 없음 → **폰트 파일 확보가 선행 조건**.
- 실사용 weight 확인 결과 (`chaerok_typography.dart` 기준): `w400`(bodyMedium/caption), `w500`(bodyLarge/displayMedium/labelSmall), `w600`(headingLarge/headingMedium/labelLarge/progress), `w700`(titleLarge/titleMedium) → **Regular(400)/Medium(500)/SemiBold(600)/Bold(700) 4종**이면 현재 스타일 전부 커버됨. `UiPreviewTypography`까지 포함해도 동일한 4종 범위.

### 3. 앱 아이콘 / 앱 이름

- Android: `mipmap-{h,m,x,xx,xxx}dpi/ic_launcher.png` 5개 파일만 존재, **adaptive icon(`mipmap-anydpi-v26/ic_launcher.xml`, foreground/background) 자체가 없음** → 현재는 legacy 방식의 flutter 기본 아이콘.
- iOS: `ios/Runner/Assets.xcassets/AppIcon.appiconset/`에 필요한 15개 사이즈(20~1024) 전부 존재하나 전부 flutter 기본 로고.
- `pubspec.yaml`에 `flutter_launcher_icons` 등 아이콘 자동 생성 패키지 **미등록**.
- 저장소 어디에도 확정된 브랜드 아이콘 원본(1024×1024 등)이 없음 — `macos/`, `web/` 쪽 아이콘도 전부 flutter 기본 템플릿.
- 앱 이름: Android `android:label="chaerok"` ([AndroidManifest.xml:11](android/app/src/main/AndroidManifest.xml#L11)), iOS `CFBundleDisplayName=Chaerok` / `CFBundleName=chaerok` ([Info.plist:7-16](ios/Runner/Info.plist#L7)) — 대소문자가 플랫폼 간 불일치. bundle id/applicationId는 양쪽 다 `com.leebakju.chaerok`로 이미 통일돼 있음.
- 저장소 내 `pubspec.yaml`의 `name: chaerok`, `README.md` 등에서 최종 확정된 한글/영문 브랜드 표기(예: "채록" vs "Chaerok" vs "chaerok")를 단정할 근거는 없음 — **최종 앱 이름 확정 필요**.

## ⚠️ 주의사항

1. **이중 디자인 시스템 처리 방침 미확정** (최우선 확인 필요): `home_preview_screen.dart`는 프로덕션 앱(`main.dart`)이 아니라 별도 진입점(`main_ui_preview.dart`)에서만 쓰이는 UI 프리뷰 전용 화면이고, `ChaerokTypography`가 아닌 독립된 `UiPreviewTypography`(`lib/ui/preview_theme.dart`)를 참조한다. 요청 문서는 이를 "디자인 시스템 미관리 사례"로 지목했지만, 실제로는 정리 대상이 `ChaerokTypography`가 아니라 별도 시스템이다. 두 가지 방향이 가능함:
   - (A) `UiPreviewTypography`에도 동일한 fontFamily 규칙을 그대로 적용 (프리뷰 하네스 유지)
   - (B) 이 기회에 `preview_theme.dart`를 걷어내고 `home_preview_screen.dart`가 `ChaerokTypography`/`ChaerokColors`를 직접 참조하도록 통합 (중복 코드 제거, 프리뷰가 실제 프로덕션 스타일과 100% 동일해짐)
   - 사용자 확인 후 진행 필요.
2. **정림사지체 웨이트 확장 여부**: 현재 Medium(500) 1종은 `displayMedium`(w500)에만 맞는다. 만약 향후 정림사지체를 다른 굵기로도 쓸 계획이 있다면 추가 웨이트 파일이 필요 — 없으면 현재 자산으로 충분함.
3. **Pretendard 라이선스/배포 방식**: OFL 폰트이므로 상업적 사용 자체는 문제없으나, 실제 사용 weight만 최소 포함(Regular/Medium/SemiBold/Bold 4종)해 번들 크기를 관리해야 함. Pretendard 전체 weight(9종) 대신 4종만 선별 필요.
4. **앱 번들 크기**: 정림사지체(1.7MB) + Pretendard 4 weight(TTF 기준 weight당 약 1.5~2MB 예상) 추가 시 합산 5~9MB 수준 증가 가능 — Pretendard Variable/subset 폰트 사용 여부도 검토 가치 있음(요청 범위 밖이라 별도 확인 필요).
5. **아이콘/앱 이름 확정 자산 부재**: 저장소 내에 브랜드 아이콘 원본, adaptive icon 배경/전경 분리 자산, 최종 앱 이름 확정본이 전혀 없어 **이 부분은 사용자 자산 제공 전까지 구현 착수 불가** — 요청 문서의 "추가 요청 사항"에서도 동일하게 명시된 선행 조건.
6. **`ChaerokTheme.light.textTheme` 리팩터링 범위**: `titleLarge`~`labelLarge` 값 재작성을 `ChaerokTypography` 참조로 바꾸면 `color` 속성(현재 `ChaerokColors.textPrimary`/`textSecondary`)은 유지해야 함 — 단순 치환이 아니라 `copyWith(color: ...)` 형태로 합성 필요.

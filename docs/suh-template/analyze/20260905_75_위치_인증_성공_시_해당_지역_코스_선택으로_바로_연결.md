#### 2️⃣-1. `ResolveFilmRollEntryUseCase` (신규 도메인 유스케이스)

파일: `lib/features/film_roll/domain/usecase/resolve_film_roll_entry_use_case.dart`

```dart
enum FilmRollEntryAction { needsCourseSelection, resumeInProgress, showDeveloping }

class FilmRollEntryDecision {
  const FilmRollEntryDecision({required this.action, required this.filmRoll});
  final FilmRollEntryAction action;
  final FilmRoll filmRoll;
}

class ResolveFilmRollEntryUseCase {
  const ResolveFilmRollEntryUseCase({
    required RecoverLastActiveFilmRollUseCase recoverLastActiveFilmRoll,
    required EnterRegionUseCase enterRegion,
  });

  Future<FilmRollEntryDecision> call(String cityCountyName, {required int regionId}) async {
    final active = await _recoverLastActiveFilmRoll();
    if (active != null) {
      if (active.status == FilmRollStatus.developing) {
        return FilmRollEntryDecision(action: showDeveloping, filmRoll: active);
      }
      if (active.selectedCourseId == null) {
        return FilmRollEntryDecision(action: needsCourseSelection, filmRoll: active);
      }
      return FilmRollEntryDecision(action: resumeInProgress, filmRoll: active);
    }
    final entered = await _enterRegion(cityCountyName, regionId: regionId);
    // 방금 새로 찾거나 생성한 필름롤이므로 developing일 수 없다(findOrCreateActiveByRegion은
    // inProgress만 생성/재사용). 코스 선택 여부만 확인.
    return FilmRollEntryDecision(
      action: entered.selectedCourseId == null ? needsCourseSelection : resumeInProgress,
      filmRoll: entered,
    );
  }
}
```
- 기존 `EnterRegionUseCase`/`RecoverLastActiveFilmRollUseCase`는 시그니처·동작 변경 없이 그대로 주입받아 재사용(안정성 우선 결정 반영).
- `UnsupportedRegionException`은 `_enterRegion` 호출부에서 그대로 전파(호출자가 기존과 동일하게 catch).
- `FilmRollModule`(`film_roll_module.dart`)에 다른 유스케이스와 같은 패턴으로 `late final ResolveFilmRollEntryUseCase resolveFilmRollEntry` 필드 추가, 생성자에서 `ResolveFilmRollEntryUseCase(recoverLastActiveFilmRoll: recoverLastActiveFilmRoll, enterRegion: enterRegion)`로 조립(두 의존성 모두 이미 같은 생성자에서 먼저 만들어짐 — 필드 선언 순서만 유스케이스 이후로 배치).

#### 2️⃣-5. `HomeDashboardScreen` 자동 연결

`_onLocationVerified`(L105-107) 옆에 신규 메서드 추가, `initState`의 `_ensureLocationVerified` 성공 경로에서 함께 호출:

```dart
Future<void> _onLocationVerified(LocationVerificationResult result) async {
  await Future.wait([
    _fetchWeather(result),
    _loadNearbyPlaces(result),
    _autoConnectFilmRollEntry(result),
  ]);
}

Future<void> _autoConnectFilmRollEntry(LocationVerificationResult result) async {
  try {
    final decision = await FilmRollModule.instance.resolveFilmRollEntry(
      result.region.cityCountyName,
      regionId: result.region.regionId,
    );
    if (!mounted) return;
    switch (decision.action) {
      case FilmRollEntryAction.needsCourseSelection:
        if (mounted) {
          await pushCourseSelectionAndConfirm(
            context,
            filmRollId: decision.filmRoll.id,
            regionId: result.region.regionId,
          );
        }
        if (!mounted) return;
        await Navigator.of(context).push(MaterialPageRoute(
          builder: (_) => FilmRollScreen(
            filmRollId: decision.filmRoll.id,
            regionId: result.region.regionId,
          ),
        ));
      case FilmRollEntryAction.resumeInProgress:
      case FilmRollEntryAction.showDeveloping:
        await Navigator.of(context).push(MaterialPageRoute(
          builder: (_) => FilmRollScreen(filmRollId: decision.filmRoll.id),
        ));
    }
  } on UnsupportedRegionException {
    // 서비스 미지원 지역 — 자동 진입 없이 기존 "필름롤 시작하기" 카드로 폴백.
  } catch (e, st) {
    log('필름롤 자동 진입 실패', name: _tag, error: e, stackTrace: st);
  } finally {
    if (mounted) await _loadRecoveredFilmRoll();
  }
}
```
- 기존 `_loadRecoveredFilmRoll()`/`_onStartFilmRollTap`/`_onResumeFilmRollTap`은 **그대로 유지**한다(폴백 안전망): `resolveFilmRollEntry`가 내부적으로 `recoverLastActiveFilmRoll`을 별도로 한 번 더 읽지만, 이미 idempotent 읽기 전용 호출이라 중복 호출의 부작용은 없다 — 두 initState 흐름(`_loadRecoveredFilmRoll` vs `_ensureLocationVerified`→`_autoConnectFilmRollEntry`)의 순서를 억지로 맞추지 않고 각자 독립적으로 최신 상태를 읽게 둔다(전략 문서의 "순서 보장 없음" 위험을 유스케이스 내부 재조회로 우회).
- `enterRegion` 자체는 idempotent(`findOrCreateActiveByRegion`)이므로 사용자가 이 자동 흐름 도중 수동으로 "필름롤 시작하기"를 누르는 극단적 케이스가 있어도 DB 상 중복 생성은 없다. 다만 화면이 두 번 push될 수는 있어 QA에서 확인 필요(주의사항 참고).

```dart
Future<void> _onEnterRegionTap() async {
  if (_isEnteringFilmRoll) return;
  final regionId = _regionId;
  if (regionId == null) return;

  setState(() => _isEnteringFilmRoll = true);
  try {
    final decision = await FilmRollModule.instance.resolveFilmRollEntry(
      _selectedRegion.cityCountyName,
      regionId: regionId,
    );
    if (!mounted) return;
    if (decision.action == FilmRollEntryAction.needsCourseSelection) {
      await pushCourseSelectionAndConfirm(
        context,
        filmRollId: decision.filmRoll.id,
        regionId: regionId,
      );
    }
    if (!mounted) return;
    await reevaluate();
  } on UnsupportedRegionException {
    if (!mounted) return;
    ScaffoldMessenger.of(context).showSnackBar(
      const SnackBar(content: Text('아직 필름롤을 지원하지 않는 지역이에요.')),
    );
  } catch (e, st) {
    log('필름롤 진입 실패', name: _tag, error: e, stackTrace: st);
    if (!mounted) return;
    ScaffoldMessenger.of(context).showSnackBar(
      const SnackBar(content: Text('필름롤을 불러오지 못했어요.')),
    );
  } finally {
    if (mounted) setState(() => _isEnteringFilmRoll = false);
  }
}
```
- 이 버튼은 `_mode == exploring`(활성 필름롤 없음)에서만 노출되므로 실질적으로 `resolveFilmRollEntry`는 항상 `needsCourseSelection`을 반환하지만, `enterRegion` 단독 호출 대신 `resolveFilmRollEntry`로 교체해 Home과 동일한 진입점을 공유하도록 통일한다(로직 중복은 없어지고, 향후 두 화면이 갈라질 이유도 줄어듦).
- 코스 선택 후 `reevaluate()`가 다시 `recoverLastActiveFilmRoll()`을 읽어 `_mode = progress`로 전환 — 기존 인프라 그대로 재사용, 추가 변경 없음.

### ⚠️ 주의사항

1. **초기 진입 시 화면 이중 push 가능성** — Home에서 `_autoConnectFilmRollEntry`가 `CourseSelectionScreen`→`FilmRollScreen`을 순차 push하는 동안 사용자가 뒤로가기를 연타하거나, `_onStartFilmRollTap`(기존 수동 버튼, 카드가 아직 안 바뀐 찰나)을 동시에 누르면 네비게이션 스택이 예상치 못하게 쌓일 수 있다. `_isEnteringFilmRoll` 플래그가 수동 버튼 쪽에는 있지만 자동 플로우와는 공유되지 않으므로, 구현 시 자동 플로우 진행 중에는 수동 버튼도 비활성화하는 별도 플래그(`_isAutoConnecting` 등) 추가를 권장.
2. **`IndexedStack` 동시 유지로 인한 두 탭 상태 어긋남** — `MainTabScreen`이 Home/Explore를 `IndexedStack`으로 동시에 살려두므로, Home에서 자동 진입시킨 필름롤을 Explore 탭이 나중에 `reevaluate()`로 읽을 때 두 화면의 `FilmRollController`/`_activeFilmRoll` 인스턴스가 서로 다르게 존재한다. 코스 선택 직후 탭 전환 시 표시 지연/불일치가 없는지 QA 필요.
3. **디버그 빌드의 지역 폴백** — `location_verification_screen.dart:28-33, 172-183`의 서비스 지역 밖 좌표 → `공주시` 대체 로직 때문에, 자동 진입 개발/QA 시 실제 지역과 다른 지역으로 자동 진입될 수 있다.
4. **`FilmRollDevelopingView` 이동은 단순 파일 이동이지만 import 경로 변경이 수반**되므로, 이동 후 `flutter analyze`로 미참조 경고가 없는지 반드시 확인.
5. **테스트 공백** — `HomeDashboardScreen`/`ExploreScreen`/`FilmRollScreen`/`CourseSelectionScreen`에 대한 위젯 레벨 테스트가 현재 전무하다. 이번 변경은 신규 유스케이스(`ResolveFilmRollEntryUseCase`) 단위 테스트로 로직만 검증하고, 실제 네비게이션 흐름(이중 push, 탭 전환 등)은 에뮬레이터/시뮬레이터 수동 QA로 보완해야 한다.
6. **`selectCourse` 실패 처리** — `pushCourseSelectionAndConfirm` 헬퍼가 `FilmRollModule.instance.selectCourse` 실패(예: `CourseChangeBlockedException`)를 그대로 던지게 할지, 조용히 무시하고 다음 화면(FilmRollScreen)에서 "추천 코스 선택하기" 버튼으로 재시도하게 할지 구현 시 결정 필요. 신규 진입 직후 시나리오에서는 방문/촬영 기록이 없으므로 `CourseChangeBlockedException`이 발생할 가능성은 낮지만, 방어적으로 try/catch 후 무시(로그만 남기고 FilmRollScreen으로 계속 진행)하는 편이 안정성 우선 원칙에 부합.

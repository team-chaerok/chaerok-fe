# 구현 계획서 — 촬영 화면 필름 카메라 UI 전면 개편

관련 이슈: [#57](https://github.com/team-chaerok/chaerok-fe/issues/57)
관련 전략 문서: `docs/suh-template/plan/20260822_20260822_기능개선_FilmRoll_촬영_화면_필름_카메라_UI_전면_개편.md`

> ⚠️ 전략 문서에서 신규 위젯 위치를 `presentation/page/widgets/`로 잠정 표기했으나, 코드 조사 결과 프로젝트 컨벤션은 `presentation/widgets/`(page와 형제 디렉터리)임을 확인. 본 문서에서 `lib/features/film_roll/presentation/widgets/`로 정정.

---

### 📊 분석 요약

**감지된 프로젝트 타입**: Flutter 앱 (feature-first, 클린 아키텍처 유사 레이어링: `data/domain/presentation`)
**주요 기술 스택**: `camera: 0.11.4`(잠금 버전), `permission_handler`, 로컬 DB(Drift 기반 `selectOnly`+`count()` 애그리게이트 패턴), `ChangeNotifier` 없는 경량 `StatefulWidget` + 정적 싱글턴 모듈(`FilmRollModule.instance`) DI
**코드 스타일**: 위젯은 `Chaerok*` 디자인 토큰(`ChaerokColors`/`ChaerokSpacing`/`ChaerokTypography`/`ChaerokRadius`)만 사용, 화면은 `StatefulWidget` + private `_State` 클래스, 유스케이스는 `class XxxUseCase { call(...) }` 형태의 얇은 패스스루, 데이터소스는 `selectOnly`+`count()`로 집계

### 🔍 현재 상태

- `VisitCaptureScreen`(`lib/features/film_roll/presentation/page/visit_capture_screen.dart`)은 `AppBar` + `CameraPreview` + `ChaerokButton("촬영하기")`로 구성된 기본 UI. 줌/플래시/카메라 전환/촬영 매수 카운터 없음.
- 촬영 저장 흐름: `_onCaptureTap()` → `CameraController.takePicture()` → `FilmRollModule.instance.savePhoto(...)`(`SavePhotoUseCase` → `PhotoRepository.savePhoto`) → `Navigator.pop(true)`.
- `PhotoRepository`(`lib/features/film_roll/domain/repository/photo_repository.dart`)는 `savePhoto`/`deletePhoto`/`findByPlace`/`findByFilmRoll(limit)`만 정의 — **필름롤 전체 촬영 수를 세는 메서드 없음**.
- `PhotoLocalDataSource`(`lib/features/film_roll/data/local/photo_local_data_source.dart`)도 `countByFilmRoll` 없음. `countByPlace`는 `findByPlace(...).length`로 구현되어 있어(라인 32-35) 전체 로우를 로드 후 세는 비효율 패턴 — 새 메서드는 이 패턴을 따르지 말 것.
- 집계 애그리게이트의 올바른 선례는 `FilmRollPlaceLocalDataSource.countByFilmRoll`(`lib/features/film_roll/data/local/film_roll_place_local_data_source.dart:23-29`)의 `selectOnly(...).addColumns([count])...map(...).getSingle()` 패턴이며, `FilmRollRepositoryImpl._toEntity`(`lib/features/film_roll/data/repository/film_roll_repository_impl.dart:233-237`)가 리포지토리 계층에서 카운트를 조회해 엔티티에 주입하는 매핑 패턴을 보여줌.
- `FilmRollModule`(`lib/features/film_roll/film_roll_module.dart`)은 DI 프레임워크 없이 private 생성자 + `static instance` getter로 구성된 컴포지션 루트. 신규 유스케이스는 필드 선언 + 생성자 바디에서 조립하는 방식으로 등록.
- 디자인 토큰은 이미 충분히 준비되어 있음: `ChaerokColors.cameraBlack`(다크 배경), `ChaerokTypography.progress`(탭 형태 숫자, "12 / 36" 같은 카운터 표기에 이미 의도된 스타일), `ChaerokSpacing`(4~32), `ChaerokRadius`(8~999, `full`은 원형 버튼에 적합).
- `ChaerokButton`은 고정 높이(52px) 사각형 버튼으로 원형 셔터 버튼에는 부적합 — 신규 위젯 필요.
- `camera: 0.11.4`(`camera_platform_interface: 2.13.0`)는 `getMinZoomLevel()`/`getMaxZoomLevel()`/`setZoomLevel(double)`/`setFlashMode(FlashMode)`를 모두 지원(`FlashMode.off/auto/always/torch`). 패키지 업그레이드 불필요.
- `lib/features/film_roll/presentation/`에는 `controller/page/state`만 존재, `widgets/`는 없음. 반면 `home` 피처는 `lib/features/home/presentation/widgets/`를 사용 중 — 동일 컨벤션 적용 대상.

### 🎯 구현 목표

전략 문서에서 확정한 대로, ①목업과 동일한 필름 카메라 레이아웃 ②줌/플래시/카메라 전환의 실제 동작 ③필름롤당 고정 노출수(24) 기반 촬영 매수 카운터 ④라이브 프리뷰 연동 하단 캡처 스트립을 `VisitCaptureScreen` 하나에 통합 구현한다.

### 📝 상세 구현 계획

```
📋 구현 계획서
├── 1️⃣ 데이터 계층 — 촬영 매수 카운트 애그리게이트 추가
├── 2️⃣ 도메인 계층 — 유스케이스/상수 추가
├── 3️⃣ 프레젠테이션 계층 — 신규 위젯 + 화면 재구성
├── 4️⃣ 테스트 작성
└── 5️⃣ 검증
```

**1️⃣ 데이터 계층**
- `lib/features/film_roll/data/local/photo_local_data_source.dart`: `Future<int> countByFilmRoll(String filmRollId)` 추가. `FilmRollPlaceLocalDataSource.countByFilmRoll`과 동일한 `selectOnly(_db.photos)..addColumns([_db.photos.id.count()])..where(_db.photos.filmRollId.equals(filmRollId))` 패턴 사용(비효율적인 `countByPlace` 패턴은 따르지 않음).
- `lib/features/film_roll/data/repository/photo_repository_impl.dart`(미조사, 존재 확인됨): `countByFilmRoll`을 새 인터페이스 메서드로 구현, 데이터소스 호출만 위임.

**2️⃣ 도메인 계층**
- `lib/features/film_roll/domain/repository/photo_repository.dart`: 추상 메서드 `Future<int> countByFilmRoll(String filmRollId);` 추가.
- 신규 유스케이스 `lib/features/film_roll/domain/usecase/get_film_roll_photo_count_use_case.dart`: `SavePhotoUseCase`와 동일한 얇은 패스스루 형태로 `class GetFilmRollPhotoCountUseCase { const GetFilmRollPhotoCountUseCase(this._photoRepository); Future<int> call(String filmRollId) => _photoRepository.countByFilmRoll(filmRollId); }`.
- 필름롤당 고정 노출수(24) 상수: `FilmRoll` 엔티티(`lib/features/film_roll/domain/entity/film_roll.dart`)에 `static const int maxExposureCount = 24;` 추가 — 인스턴스 필드가 아닌 전역 비즈니스 규칙이므로 DB 마이그레이션 불필요.
- `lib/features/film_roll/film_roll_module.dart`: `late final GetFilmRollPhotoCountUseCase getFilmRollPhotoCount;` 필드 선언 + 생성자 바디에 `getFilmRollPhotoCount = GetFilmRollPhotoCountUseCase(photoRepository);` 추가 + import.

**3️⃣ 프레젠테이션 계층**
신규 디렉터리 `lib/features/film_roll/presentation/widgets/`(page와 형제)에 다음 위젯 분리:
- `film_viewfinder_frame.dart`: 둥근 모서리 필름 프레임(테두리) 안에 `CameraPreview`를 감싸는 컨테이너. `ChaerokRadius.xl` + `ChaerokColors.cameraBlack` 계열 활용.
- `camera_top_bar.dart`: 플래시 토글 아이콘 + 필름 타입 라벨(좌측), 촬영 매수 카운터(`ChaerokTypography.progress`로 "N/24" 표기) + 닫기(X) 버튼(우측).
- `camera_zoom_selector.dart`: 2x/1x/0.5x 세로 배열 선택 UI. 초기화 시 `getMinZoomLevel()`/`getMaxZoomLevel()` 결과 범위를 벗어나는 배율은 비활성화(예: 0.5x 미지원 기기).
- `camera_shutter_button.dart`: 원형 버튼(`ChaerokRadius.full`), 저장 중 상태는 기존 `ChaerokLoadingIndicator` 재사용.
- `camera_switch_button.dart`: 전/후면 전환 아이콘 버튼.
- `capture_film_strip.dart`: 화면 최하단, 라이브 카메라 프리뷰와 연동되는 필름 스트립 시각 요소(과거 사진 목록이 아님 — 정확한 표현 방식은 목업 재확인 후 확정, 우선 프리뷰를 필름 프레임 슬라이스로 반복 표시하는 형태로 초안 구현).

`lib/features/film_roll/presentation/page/visit_capture_screen.dart` 재구성:
- 상태 추가: `double _zoomLevel = 1.0`, `double _minZoom = 1.0`, `double _maxZoom = 1.0`, `FlashMode _flashMode = FlashMode.off`, `CameraLensDirection _lensDirection = CameraLensDirection.back`, `int _photoCount = 0`.
- `_initializeCamera()` 확장: 컨트롤러 초기화 후 `getMinZoomLevel()`/`getMaxZoomLevel()` 조회해 `_minZoom`/`_maxZoom` 저장. `initState`에서 `FilmRollModule.instance.getFilmRollPhotoCount(widget.filmRollId)` 병행 호출해 `_photoCount` 초기값 세팅.
- `_onZoomSelected(double zoom)`: 요청 배율을 `_minZoom`~`_maxZoom`으로 클램프 후 `_cameraController!.setZoomLevel(...)` 호출 + `setState`.
- `_onFlashToggle()`: `FlashMode.off` ↔ `FlashMode.always`(또는 `auto`) 전환 + `_cameraController!.setFlashMode(...)`.
- `_onCameraSwitch()`: `availableCameras()`에서 현재와 반대 `lensDirection`을 가진 카메라를 찾아 기존 컨트롤러 dispose 후 재초기화(줌/플래시 상태 초기화, 라이프사이클 재초기화와 경합하지 않도록 `_isInitializingCamera` 가드 재사용).
- `_onCaptureTap()`: 저장 성공 후 `_photoCount++` 반영(또는 `countByFilmRoll` 재조회) — 카운터가 "N/24"로 즉시 갱신되도록.
- `build()`/`_buildBody()`를 위 신규 위젯 조합으로 재작성. 기존 에러/권한 거부 상태 UI(`_errorMessage`, 설정 이동 버튼)는 새 레이아웃 안에서도 그대로 노출되도록 최상위 분기 유지.

**4️⃣ 테스트 작성**
- `PhotoLocalDataSource.countByFilmRoll` 단위 테스트: 여러 장소에 걸쳐 사진을 삽입한 뒤 필름롤 단위 합계가 올바른지 검증(기존 `countByFilmRoll`류 데이터소스 테스트 파일 위치 패턴을 따름).
- `GetFilmRollPhotoCountUseCase` 단위 테스트: 리포지토리 위임 여부만 검증(다른 유스케이스 테스트와 동일한 얇은 패턴).
- 신규 위젯 위젯 테스트: `camera_zoom_selector`(배율 선택 시 콜백/활성 상태 갱신, 범위 밖 배율 비활성화 렌더링), `camera_shutter_button`(로딩 상태 렌더링), `camera_top_bar`(카운터 텍스트 "N/24" 렌더링, 닫기 버튼 콜백).
- `VisitCaptureScreen`은 기존에도 `camera` 플러그인 의존으로 인해 통합 테스트 난이도가 높을 것으로 예상 — 카메라 관련 로직은 가능한 만큼 위 개별 유닛/위젯 테스트로 커버하고, 화면 자체는 수동 검증(디바이스/시뮬레이터)으로 보완.

**5️⃣ 검증**
- `flutter analyze` / 기존 린트 통과.
- 실기기(또는 시뮬레이터)에서 촬영 화면 진입 → 줌 전환 → 플래시 토글 → 카메라 전환 → 촬영 → 카운터 증가 → 필름롤 24매 근접/도달 시나리오 수동 확인.

### ⚠️ 주의사항

- **0.5x 광각 미지원 기기**: `getMinZoomLevel()`이 1.0을 반환하는 기기가 다수 존재 — 이 경우 0.5x 옵션을 비활성화(또는 숨김) 처리해야 하며, 이는 실기기 테스트 없이는 시뮬레이터에서 확인이 어려움.
- **카메라 전환 시 경합**: `_onCameraSwitch()`가 `didChangeAppLifecycleState`의 재초기화 로직과 동시에 트리거되지 않도록 기존 `_isInitializingCamera` 플래그를 재사용/확장해야 함. 그렇지 않으면 컨트롤러 이중 생성 위험이 있음(기존 코드 주석에 이미 명시된 문제).
- **24매 초과 처리 미확정**: 전략 문서에서 P2로 남긴 항목 — 초과 시 셔터 비활성화 여부는 제품 정책 확정 후 별도 처리. 이번 구현에서는 우선 카운터가 "25/24"처럼 초과 표시되는 것을 허용하고 차단 로직은 넣지 않는 것을 기본값으로 제안(필요 시 구현 중 재확인).
- **하단 캡처 스트립의 정확한 시각적 형태**: "라이브 카메라 프리뷰 연동"이라는 요구만 확정되었고, 구체적 렌더링 방식(단일 프리뷰 반복 슬라이스 vs 다른 표현)은 목업 대비 검증이 필요 — 구현 착수 전 목업 재확인 권장.
- **`countByPlace`의 비효율 패턴을 신규 `countByFilmRoll`에 복제하지 말 것**: 기존 코드에 이미 있는 안티패턴이므로, 새 메서드는 `FilmRollPlaceLocalDataSource`의 `selectOnly`+`count()` 패턴을 따라야 함.
- **`photo_repository_impl.dart`는 이번 조사에서 직접 읽지 않음** — 구현 착수 시 실제 파일을 열어 `PhotoRepository` 구현체의 생성자/필드 구조를 확인 후 `countByFilmRoll` 구현을 추가해야 함.

## ✅ 백엔드 명세 (문서상 전달받은 내용 — 아래 실기기 검증으로 일부 정정됨)

- OAuth 로그인 요청 DTO 에 **nullable `nonce`** 필드 추가.
- `OAuthTokenVerifier` 검증 메서드가 `nonce` 를 전달받도록 인터페이스 변경. Kakao·Google verifier 는 기존 인증 로직 유지 + 변경된 인터페이스만 적용.
- `AuthService` 가 ID Token 과 nonce 를 verifier 로 전달.
- **Apple 로그인 시 `nonce` 필수** — 누락 시 인증 실패.
- ~~nonce 해싱 주체 = 백엔드. 클라이언트는 raw nonce 를 전송하고 백엔드가 SHA256(raw) 계산~~ **→ 실기기 검증 결과 사실이 아니었음. 아래 §🔧 실제 계약 참조.**
- Swagger 로그인 명세에 nonce · Apple 설명 반영, 백엔드측 nonce 검증 테스트 추가됨.

## 🔧 실제 동작 계약 (2026-09-02 실기기 검증으로 확정)

문서상 전달받은 명세대로(raw nonce 전송) 구현했으나 실기기에서 `401 Apple ID Token의 nonce가 일치하지 않습니다` 발생. identityToken을 직접 디코딩해 `SHA256(raw nonce)`가 JWT `nonce` claim과 정확히 일치함을 확인했음에도 실패 → **백엔드가 nonce를 해싱하지 않고 요청값과 claim을 문자열 그대로 비교**하는 것으로 확인.

- **클라이언트 → 백엔드 `nonce` 필드 = Apple SDK(`getAppleIDCredential`)에 넘겼던 것과 동일한 `SHA256(raw)` 해시값.** raw nonce를 그대로 보내면 401.
- 백엔드는 이 값을 추가 해싱 없이 identityToken의 `nonce` claim과 직접 비교.
- 코드 반영 완료: [apple_auth_service.dart](../../../lib/features/auth/data/apple_auth_service.dart)가 `hashedNonce`를 반환하고, [o_auth_login_request.dart](../../../lib/data/models/o_auth_login_request.dart) 주석도 갱신함.
- ⚠️ **문서화 리스크**: 백엔드 담당자에게 실제 동작이 원래 전달받은 명세와 다르다는 점을 알리고, 이 동작(해싱 없이 직접 비교)이 의도된 것인지 확인받을 것. 의도된 게 아니라면 백엔드가 나중에 "명세대로" 해싱 로직을 추가하는 순간 이 클라이언트 코드가 다시 깨짐.
- ⚠️ `authorizationCode` 는 명세에 없음 → 회원탈퇴 시 Apple 서버측 revoke 는 이번 백엔드 범위 밖 (§⚠️ 정책 위험 유지).

### 2️⃣ 핵심 구현 (파일별 변경)

#### (A) `lib/data/models/o_auth_login_request.dart` — 수정

```dart
enum OAuthProvider {
  kakao,
  google,
  apple;

  String toJson() => name.toUpperCase();

  static OAuthProvider fromJson(String value) =>
      values.byName(value.toLowerCase());
}

class OAuthLoginRequest {
  const OAuthLoginRequest({
    required this.provider,
    required this.idToken,
    this.nonce,
  });

  final OAuthProvider provider;
  final String idToken;

  /// Apple 로그인 시 재생공격 방지를 위해 클라이언트가 생성한 raw nonce.
  /// 백엔드가 identityToken(JWT)의 nonce 클레임과 대조한다. kakao/google 은 null.
  final String? nonce;

  Map<String, dynamic> toJson() => {
    'provider': provider.toJson(),
    'idToken': idToken,
    if (nonce != null) 'nonce': nonce,
  };
}
```
- `apple` → `toJson()` == `"APPLE"` (기존 `name.toUpperCase()` 로직 그대로).
- `nonce` 는 **선택 필드 + 조건부 직렬화** → kakao/google 요청 JSON 은 변화 없음 (회귀 0).
- ⚠️ 백엔드 필드명(`nonce`)·raw 여부 최종 확인 필요.

#### (B) `lib/features/auth/data/apple_auth_service.dart` — 신규

`KakaoAuthService` / `GoogleAuthService` 형태를 답습하되, Apple 은 **토큰 + nonce 쌍**이 필요하므로 반환형만 다르다.

```dart
import 'dart:convert';
import 'dart:developer';
import 'dart:math';

import 'package:crypto/crypto.dart';
import 'package:sign_in_with_apple/sign_in_with_apple.dart';

/// Apple 로그인으로 [identityToken] 과, 그 토큰 검증에 쓰인 raw [nonce] 를 반환한다.
typedef AppleSignInResult = ({String idToken, String rawNonce});

class AppleAuthService {
  static const _tag = 'AppleAuthService';

  Future<AppleSignInResult> signIn() async {
    final rawNonce = _generateNonce();
    log('애플 로그인 시도', name: _tag);

    try {
      final credential = await SignInWithApple.getAppleIDCredential(
        scopes: const [
          AppleIDAuthorizationScopes.email,
          AppleIDAuthorizationScopes.fullName,
        ],
        nonce: _sha256ofString(rawNonce),
      );

      final idToken = credential.identityToken;
      if (idToken == null || idToken.isEmpty) {
        throw Exception('애플 identityToken이 없습니다.');
      }
      log('애플 로그인 성공', name: _tag);
      return (idToken: idToken, rawNonce: rawNonce);
    } on SignInWithAppleAuthorizationException catch (e) {
      if (e.code == AuthorizationErrorCode.canceled) {
        log('사용자가 애플 로그인 취소', name: _tag);
      } else {
        log('애플 로그인 실패 - code: ${e.code}', name: _tag, error: e);
      }
      rethrow;
    }
  }

  String _generateNonce([int length = 32]) {
    const charset =
        '0123456789ABCDEFGHIJKLMNOPQRSTUVXYZabcdefghijklmnopqrstuvwxyz-._';
    final random = Random.secure();
    return List.generate(
      length,
      (_) => charset[random.nextInt(charset.length)],
    ).join();
  }

  String _sha256ofString(String input) =>
      sha256.convert(utf8.encode(input)).toString();
}
```
- 취소는 카카오·구글처럼 `rethrow` → `login_screen` 이 `catch` 로 흡수.
- `SignInWithApple.isAvailable()` 가드는 iOS 13 타깃이라 사실상 불필요 (P2, 생략 가능).
- `unlink`/`disconnect` 대응 메서드는 **없음** — Apple 클라이언트 SDK 에 revoke API 부재 (§⚠️ 참조).
- 반환형: Dart record 사용 (Dart 3.9). 프로젝트가 모델은 클래스로 두는 관례이나 이 값은 service↔screen 내부 배관이라 record 로 경량 처리. (대안: 소형 불변 클래스 `AppleSignInResult`.)

### 보안 고려

- nonce 는 `Random.secure()` 로 생성(암호학적 안전), raw 는 로그에 남기지 않기 — `AppleAuthService` 로그에 `rawNonce` / `idToken` 값 출력 금지 (kakao 서비스는 idToken 을 로그로 남기고 있음 → **답습하지 말고 값은 마스킹/생략**).
- `identityToken` 검증(서명/aud/iss/exp/nonce)은 전적으로 백엔드 책임. 클라이언트는 전달만.
- 산출물 문서에 실제 토큰/키 값 절대 미기재 (common-rules 민감정보 규칙).

### 대안

| 대안 | 채택 여부 |
|------|-----------|
| `firebase_auth` Apple provider | ✗ Firebase 미도입, 과함 |
| 네이티브 Swift + MethodChannel | ✗ `sign_in_with_apple` 가 동일 역할 |
| `SignInWithAppleButton` 위젯 사용 | △ Apple 규격 자동 준수 장점이나 기존 `SocialLoginButton` 과 스타일 이질 — 채택 안 함 |
| nonce 생략 | ✗ 사용자 확정(클라 생성 + 백엔드 검증) |
| `nonce` 를 별도 클래스 필드가 아닌 `Map` 확장으로 | ✗ 타입 안전성 손해 |

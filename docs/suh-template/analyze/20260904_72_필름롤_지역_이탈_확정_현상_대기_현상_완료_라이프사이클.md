### 서버 상태 머신 (BE 확정분 + 미확정분)

```
CAPTURING ──(exitFilmRoll)──┬── 조건 충족 → READY_TO_RENDER ──(1시간 렌더)──▶ ???(완료 토큰 미확정) / FAILED
                            └── 조건 미충족 → EXPIRED (종료)
```

| 서버 `status` | 의미 | 로컬 `FilmRollStatus` |
|---|---|---|
| `CAPTURING` | 이탈 전, 촬영 중 | `inProgress` (기존) |
| `READY_TO_RENDER` | exit 성공 + 현상 조건 충족 | **`developing`** (신규) |
| `EXPIRED` | exit 성공 + 조건 미충족, 종료 | **`expired`** (신규) |
| (완료 토큰 미확정) | 렌더링 완료 | `completed` — **이번 범위 밖, TODO** |

- 미확정: `READY_TO_RENDER` 이후 완료 시 `status` 값, `completedAt` 채워지는지, `getFilmRoll` 폴링으로 완료 확인 가능한지 → **결과 조회 API 미개발**이라 확인 불가. 완료 감지는 후속 이슈.
- 후속 이슈 스코프: 결과(현상된 사진)는 **링크(URL) 형태**로 내려올 예정 → 그때 로컬 엔티티/스키마에 `resultUrl`(또는 유사 필드) 추가 필요. #72에서는 만들지 않음.
- 미확정: exit 응답의 `developAvailableAt`이 `READY_TO_RENDER`에서 실제로 채워져 오는지 → 안 오면 `exitedAt + 1시간`으로 계산 (fallback 구현).

## ⚠️ 주의사항 (위험 요소 & 대안)

### 🟢 서버 스펙 — exit 응답 확정 / 완료는 후속

- **exit 응답 (확정)**: `status` = `READY_TO_RENDER`(조건 충족) / `EXPIRED`(조건 미충족). `FilmRollExitResponse.developAvailable` 과 1:1 대응할 것으로 보이나, `status` 문자열도 함께 확인해 **둘 중 하나라도 만족하면** 분기 (방어적). "3유형 부족" vs "사진 부족" 구분 필드는 없음 → EXPIRED 안내는 **단일 문구**
- **완료(렌더링 결과)**: BE 미개발, 완료 시 결과를 **링크로 반환**할 예정 → **#72 범위 밖**. `developing` → `completed` 자동 전환 없음. 코드에 `// TODO(#후속-이슈)` 만 남김. 후속 이슈에서 완료 감지(폴링 or 결과 API) + `resultUrl` 필드 + 결과 화면 진행
- **미확정 (구현 중 실측)**: exit 응답의 `developAvailableAt` 이 `READY_TO_RENDER`에서 채워져 오는지 → 안 오면 `exitedAt + Duration(hours: 1)` fallback. `ExitFilmRollUseCase` 안에서 처리, 상수 1곳(`_kDevelopDuration`)으로 격리

### 🟡 부분 유니크 인덱스 & developing

- 인덱스 `idx_unique_active_film_roll_per_region` 는 `WHERE status = 'inProgress'` → **developing 필름롤은 대상에서 자동 제외**. 즉 "부여 필름롤 현상 중"이어도 부여에 새 inProgress 필름롤 생성 가능
- **제품 결정 필요**: 현상 대기 중 사용자가 다른(또는 같은) 지역 새 필름롤을 시작하게 둘 것인가?
  - MVP 권장: **허용** (developing은 "완료된 것에 준함", 백그라운드 대기일 뿐). 별도 차단 로직 추가 안 함
  - 단 `recoverLastActiveFilmRoll` 은 마지막 1개만 추적 → 새 필름롤 시작 시 `lastActiveFilmRollId`가 새 것으로 덮여 **developing 필름롤이 채록길 탭에서 사라짐**(컬렉션에는 남음). MVP 허용 가능하나 이슈 담당 확인. 원하면 P1: `_onCameraTap`/`enterRegion` 전에 developing 필름롤 존재 시 경고

### 🟡 이탈 오탐 / 역지오코딩 비용

- `medium` 정확도(`LocationSettings`) → 경계 근처 오차 큼. `accuracy > 50m` 필터로 1차 방어. 필요 시 "2회 연속 departed" 로 강화 (MVP는 1회 + accuracy 필터)
- Kakao 역지오코딩은 위치 갱신 시에만 호출 (상시 아님). `didUpdateWidget`에서 `oldWidget.currentPosition != widget.currentPosition` 일 때만. 실패는 조용히 무시 + 마지막 판정 캐시
- `ExploreScreen`의 위치 갱신은 `initState` 1회 + `onRequestPosition`(방문 인증 실패 시)뿐 → **진행 모드에서 위치가 거의 안 바뀜**. 이탈을 실효성 있게 잡으려면 진행 모드 진입/`didChangeAppLifecycleState(resumed)` 시 `_loadCurrentPosition()` 재호출 추가 필요 (explore_screen에 lifecycle observer 없음 → `WidgetsBindingObserver` mixin 추가). 이 부분이 이번 구현의 실질 난이도 포인트

### 🟡 카운트다운

- 남은 시간은 매 tick `developAvailableAt.difference(DateTime.now())` 로 재계산 (누적 카운터 X) → 시스템 시계 변경에 자연 대응
- 카운트다운 0 도달 시 타이머 정지 + "곧 현상이 완료돼요" 표시. **완료 감지·전환은 안 함** (후속 이슈). `developing` 필름롤은 그대로 유지
- `Timer` 는 `initState` 1개만, `dispose` 취소

### 🟡 serverFilmRollId 확보 (해결책 확정: sync 지역검사 우회)

- `exitFilmRoll`은 서버 PK(int) 필수. `#64` 동기화 미완/부분 실패로 `serverFilmRollId == null` 가능
- **`FilmRollSyncService.syncFilmRoll`의 지역 검사가 보는 값**: `_currentRegion()` → `LocationVerificationResult.sessionCache`(위치 인증 화면에서 세션당 1회 설정). 진행 모드에서 걸어 이탈해도 이 캐시는 **처음 인증한 지역 그대로** → 앱을 안 껐으면 `_currentRegion() == 필름롤 지역`이라 sync가 안 막힘. **막히는 건 앱 재시작 후(sessionCache=null) 이탈한 케이스**
- **확정 해결**: `syncFilmRoll(id, {bool skipRegionCheck = false})` 옵션 추가. `ExitFilmRollUseCase`가 `serverFilmRollId == null`일 때만 `skipRegionCheck: true`로 1회 호출 → 지역 검사만 건너뛰고 멱등 서버 생성 + 미전송 방문 flush + status 미러링은 그대로. 그래도 null이면 `ExitNotSyncedException` → UI "동기화 후 다시 시도", **로컬 상태 불변**
- 부수 효과(의도한 것): exit 직전 미전송 방문이 서버로 밀려 올라가 서버의 현상 조건 판정(3유형/사진)이 정확해짐
- 기존 호출부(`enter_region_use_case`, `film_roll_controller._sync`)는 기본값 `false`라 무영향

### 🟢 마이그레이션 안전성

- `addColumn(developAvailableAt)` nullable → 기존 행 무영향. drift 스키마 테스트는 이 프로젝트에 없음(수동). `AppDatabase.forTesting(NativeDatabase.memory())`는 항상 최신 스키마로 `createAll` → 마이그레이션 경로는 테스트 안 됨(기존 관행과 동일)

### 🔍 현재 상태

**`HomeDashboardScreen`** (`lib/features/home/presentation/home_dashboard_screen.dart`)
- `initState`에서 3개 독립 플로우를 병렬 시작: `_fetchUserInfo()`(유저 정보), `_ensureLocationVerified()`(위치 인증, `LocationVerificationResult.sessionCache` 우선 사용), `_loadRecoveredFilmRoll()`(진행중 필름롤 복구)
- `build()`는 `_HomeHeader` + (진행중 필름롤 있으면 `ActiveFilmRollCard`, 없으면 `_buildStartFilmRollCard()`)만 렌더링 — 날씨/캐러셀/근처 장소 섹션 없음

**재사용 가능한 기존 자산**
- `LocationVerificationResult`(`lib/features/location/data/location_verification_result.dart`): `position`(GPS 좌표), `region`(`RegionResponse`), **`places`(`List<PlaceListResponse>`, 위치 인증 흐름에서 이미 조회된 근처 장소)** — 세션 캐시(`sessionCache`)로 화면 재진입 시 재조회 방지
- `RecommendedPlaceCard`(`lib/features/home/presentation/widgets/recommended_place_card.dart`) + `RecommendedPlaceSummaryData`(`home_card_data.dart`): `explore_screen.dart`에서 이미 사용 중인 장소 카드. `name`/`category`/`distance`/`placeholderMood`만 있고 **채록 완료 여부 필드 없음**
- `ActiveFilmRollCard`: `FilmRollSummaryData`(`name`/`capturedCount`/`totalCount`) 기반, 진행률 바만 표시. **사진 캐러셀 없음**
- `PhotoRepository`(`lib/features/film_roll/domain/repository/photo_repository.dart`) → `PhotoRepositoryImpl` → `PhotoLocalDataSource`(Drift `photos` 테이블): `findByPlace(placeId)`만 있고 **필름롤 전체 사진 조회 메서드 없음**. 단, `PhotoLocalDataSource.hasAnyByFilmRoll(filmRollId)`가 이미 `photos.film_roll_id` 컬럼으로 필터링하고 있어 **동일 컬럼으로 `findByFilmRoll(filmRollId)`를 추가하는 데 스키마 변경이 불필요함**을 확인
- `FilmRollPlace`(`domain/entity/film_roll_place.dart`): `serverPlaceId`/`externalPlaceId`/`isVisited` 보유 — `PlaceListResponse.id`/`kakaoPlaceId`/`tourContentId`와 매칭해 "채록 여부" 판정 가능
- `KakaoLocalApiService`(`lib/features/location/data/kakao_local_api_service.dart`): 외부 API 연동 표준 패턴(전용 `Dio` 인스턴스 + `AppSecrets`의 API 키, private 생성자 + static 메서드, try/catch 후 `log()` + null 반환)
- `RegionCode`(`lib/shared/region/region_code.dart`): 서비스 지역이 공주/부여/서산/예산 **4개로 고정**. `cityCountyName`/`displayName`처럼 지역별 고정값을 extension getter로 제공하는 패턴이 이미 있음

**테스트 컨벤션**: 네트워크 호출 자체(API 서비스 클래스: `KakaoLocalApiService`/`PlacesApi`/`RegionsApi`)는 테스트 대상에서 제외되어 있음(`test/` 어디에도 대응 테스트 없음). 대신 ①모델 `fromJson`(`test/data/models/*_test.dart`), ②로컬 데이터소스(Drift in-memory DB, `AppDatabase.forTesting(NativeDatabase.memory())`), ③리포지토리, ④유스케이스, ⑤일부 위젯을 테스트한다. 이번 작업도 이 컨벤션을 따른다.

### ⚠️ 주의사항

- **기상청 API 발표 시각 규칙**: 초단기실황은 매시 정각 관측 후 약 10~40분 뒤 제공된다. 호출 시각이 발표 시각 이전이면 이전 시간대 데이터를 요청해야 함 — `base_date`/`base_time` 계산 헬퍼에서 이 규칙을 명확히 처리해야 함(경계값 실수 시 "데이터 없음" 오류로 API가 응답할 수 있음)
- **인증키 발급 선행**: 공공데이터포털 키 발급에는 승인 시간이 걸릴 수 있어 실제 연동 검증 전 확보 필요. 코드 구조(서비스 클래스, 격자 lookup, 파싱 로직)는 키 없이도 구현 가능
- **격자좌표 하드코딩 리스크**: 4개 지역 한정이라는 전제가 향후 서비스 지역이 늘어나면 깨짐. `RegionCode` enum 자체가 이미 이 4개로 고정된 구조(`region_code.dart` 최상단 주석)이므로 같은 전제를 공유 — 지역이 늘어나면 `RegionCode`부터 확장이 필요해 일관된 실패 지점
- **채록 여부 매칭 필드 불일치 가능성**: `PlaceListResponse`는 `source`(카카오/투어API 등)에 따라 `id`/`kakaoPlaceId`/`tourContentId` 중 일부만 채워짐. `FilmRollPlace.serverPlaceId`/`externalPlaceId`와 매칭할 때 `source` 별로 어떤 필드를 비교해야 하는지 확인 필요 — `film_roll_place_mapper.dart`/`course_candidate_place.dart`에서 매칭 로직 선례 확인 권장
- **위치 인증 미완료 상태**: 날씨/근처 장소 섹션 모두 `_locationResult`에 의존하므로, 위치 인증이 오래 걸리거나 실패하면 두 섹션이 계속 로딩/빈 상태로 남음 — 기존 헤더의 "확인 중..." 패턴과 일관되게 처리
- **사진 캐러셀 성능**: 필름롤 진행에 따라 사진 수가 많아질 수 있어 `findByFilmRoll`에 `limit`(최근 N장) 적용을 고려 — 캐러셀은 전체 사진이 아닌 "최근 촬영 사진 프리뷰"이므로 무제한 조회는 불필요

## 📊 분석 요약

**감지된 프로젝트 타입**: Flutter (SDK `^3.9.2`), `pubspec.lock` 커밋됨
**주요 기술 스택**: Dio 5.8(백엔드), Drift 2.20(로컬 DB, schemaVersion 4), `kakao_map_sdk ^1.2.6`(이미 도입·초기화됨), `geolocator ^14`, `shared_preferences ^2.3`, 상태관리 라이브러리 없음(`setState` + 자체 `Controller` 패턴)
**코드 스타일**:
- 화면: `StatefulWidget` + `setState`. 복잡한 흐름만 별도 `XxxController`(콜백 `onStateChanged`로 화면이 setState) — 예 `FilmRollController`. 단순 화면은 Controller 없이 State 안에서 직접 API 호출.
- API 클래스: `class XxxApi { const XxxApi._(); static Future<T> m() ... response.data ?? T.empty() }`.
- 모델: 수동 `fromJson` factory + `const` 생성자, `freezed`/`json_serializable` 미사용. `categoryGroup`/`source` 등은 느슨하게 `String`.
- 큰 위젯은 `_PascalCase` private 위젯으로 분리, DartDoc `///`로 "왜"를 설명.
- 비동기 경합은 요청 토큰(`int _requestToken`) 또는 `mounted` 가드로 방어(`home_dashboard_screen.dart`, `explore_screen.dart` 참고).

## 🔍 현재 상태

### 1. 채록길 탭 = `ExploreScreen` (지도 없음)

[lib/features/explore/presentation/explore_screen.dart](../../../lib/features/explore/presentation/explore_screen.dart) — 302줄, `StatefulWidget` + `setState`.
- 구성: AppBar(`채록길`) → 지역 `ChoiceChip`(공주/부여/서산/예산) → `PlaceCategoryMenu`(선택 인덱스만 저장, **필터링 미동작**) → `Expanded(_buildPlacesList)` → `_buildFooter`(`{지역}에서 필름롤 시작하기` CTA).
- 데이터: `initState`에서 `LocationPermissionService.getCurrentPosition()`(거리 계산용) + `_fetchPlaces()`.
- `_fetchPlaces`: `RegionsApi.resolveRegion(충청남도 + region.cityCountyName)` → `regionId` → `PlacesApi.getExternalPlaces(regionId)`. 요청 토큰(`_fetchRequestId`)으로 경합 방어.
- CTA: `FilmRollModule.instance.enterRegion(cityCountyName, regionId:)` → `FilmRollScreen(filmRollId:, regionId:)` push.
- **지도(`KakaoMap`) 없음.** `getExternalPlaces`(TourAPI 실시간, DB 미저장)를 쓰므로 대부분 `PlaceListResponse.id == null`, 식별자는 `tourContentId`/`kakaoPlaceId`.

### 2. 진행(필름롤) 화면 = `FilmRollScreen` (별도 라우트)

[lib/features/film_roll/presentation/page/film_roll_screen.dart](../../../lib/features/film_roll/presentation/page/film_roll_screen.dart) — `FilmRollController` 사용.
- `FilmRollController(filmRollId, onStateChanged)` → `FilmRollState { status, filmRoll, places, errorMessage, lastSyncHadError }`. **재사용 가능** — 화면 비종속.
- `load()` = 로컬 DB `_reload()` + `_triggerSync()`(fire-and-forget 백엔드 동기화).
- `_buildLoaded`: 진행률 카드(`filmRoll.progress`, `visited/total`) → 코스 미선택이면 `추천 코스 선택하기`(regionId 필요 → `widget.regionId` 또는 `RegionsApi.resolveRegion(filmRoll.regionName)`) / 선택됐으면 `places.map(_buildPlaceTile)` + `필름롤 완료하기`(`filmRoll.isCompletable`).
- `_buildPlaceTile`: 이름/주소/사진수, `isVisited`면 체크 아이콘 / 아니면 `방문 인증` → `VisitCaptureScreen(filmRollId, filmRollPlaceId)` → 촬영 성공(`pop(true)`) → `_controller.completeVisit(place.id)`.
- **`VisitCaptureScreen`은 GPS 거리 검증을 하지 않는다.** 촬영 후 무조건 로컬 방문 처리.

### 3. 진행중 필름롤 판별 / 복구

- `FilmRollModule.instance.recoverLastActiveFilmRoll()` → `FilmRoll?`. `home_dashboard_screen.dart`·`main_tab_screen.dart`가 이미 사용. `AppPreferences.getLastActiveFilmRollId()`(shared_preferences) 기반.
- `main_tab_screen.dart`: `IndexedStack(index:_selectedIndex, children: const [HomeDashboardScreen(), ExploreScreen(), FilmRollCollectionScreen(), MyScreen()])`. **4탭 상시 alive, 탭 전환 시 생명주기 콜백 없음.** 카메라는 탭이 아니라 `onCameraTap` 액션.
- 프로젝트에 `RouteObserver`/`VisibilityDetector`/`RouteAware` **사용처 없음**(`visit_capture_screen`만 `WidgetsBindingObserver`).

### 4. 현상(완료) 조건 데이터 — `VisitsApi.getVisits`

[lib/data/remote/visits_api.dart](../../../lib/data/remote/visits_api.dart) `getVisits(int filmRollId)` → `VisitListResponse`:
- `visitedCategoryCount`, `requiredCategoryCount`(=3), `visitRequirementMet`(bool), `visits: List<VisitItemResponse>{ visitId, placeId, placeName, categoryGroup, visitedAt }`.
- 카테고리 그룹: `TOURISM`(관광지) / `FOOD`(식당) / `CAFE_DESSERT`(카페·디저트) 각 1곳 이상 → 현상 조건 충족. → **"서로 다른 관광 유형 N/3"** 문구의 정답 소스.
- **`filmRollId`는 서버 필름롤 PK(int)** — 로컬 UUID 아님. `FilmRoll.serverFilmRollId`(nullable).
- 현재 `VisitsApi.getVisits`는 **호출처가 한 곳도 없다**(신규 연동). `createVisit`만 `FilmRollSyncService`가 사용.

### 5. `serverFilmRollId`가 채워지는 조건 (진행 모드의 전제)

[lib/features/film_roll/data/sync/film_roll_sync_service.dart](../../../lib/features/film_roll/data/sync/film_roll_sync_service.dart) `syncFilmRoll`:
1. `findById`로 필름롤 로드(현재 계정 스코프) — null이면 중단
2. `AppPreferences.getCurrentUserId()` null이면 중단
3. `_currentRegion() != filmRoll.regionCode`면 중단 — `_currentRegion`은 `LocationVerificationResult.sessionCache`(홈 탭 위치 인증 완료 시 세팅)를 읽음
4. `serverFilmRollId == null`이면 `POST /api/film-rolls`(멱등키 `clientFilmRollId`) → `linkServerFilmRoll`로 로컬 저장
- 즉 **위치 인증 미완료·오프라인·서버 오류·지역 불일치 시 `serverFilmRollId`는 계속 null**. `FilmRollController.load()`가 `_triggerSync()`를 fire-and-forget으로 돌리지만 완료·성공 보장 없음.

### 6. "미기록/방문 여부" 배지 — 이미 존재

- [lib/features/home/presentation/nearby_place_recorder.dart](../../../lib/features/home/presentation/nearby_place_recorder.dart) `NearbyPlaceRecorder.isRecorded(PlaceListResponse, List<FilmRollPlace>)` — 서버 ID 우선, 없으면 `source`별 external ID(`kakaoPlaceId`/`tourContentId`)로 `FilmRollPlace`와 매칭.
- `RecommendedPlaceSummaryData.isRecorded` 필드 + `RecommendedPlaceCard`의 `_RecordedBadge`(체크 뱃지) 이미 구현. `home_dashboard_screen._toNearbySummary`가 사용 중.
- **탐색 모드(필름롤 없음)**: 비교 대상 `FilmRollPlace`가 없음 → 전 장소가 자동으로 "미기록". 시안의 "아직 기록하지 않았어요"와 일치.

### 7. 카테고리 필터 소스

- `PlaceListResponse`/`PlaceSearchResponse`: `categoryGroup`(String), `categoryDetail`(String), `isRepresentative`, `source`.
- [lib/features/home/presentation/widgets/place_category_menu.dart](../../../lib/features/home/presentation/widgets/place_category_menu.dart): `전체 / 유적·역사 / 음식 / 카페·디저트 / 자연·산책 / 문화·전시 / 시장·상권 / 소품샵` (8개, `categoryName` 문자열 보유, 콜백은 index만).
- 과거 분석([plan/20260711 장소 API](../plan/20260711_20260711_장소_Place_API_연동_구현.md))에 "Swagger가 `categoryGroup` enum 전체 값을 명시하지 않음 → 카테고리 필터 UI 붙이는 시점에 enum 승격 + 백엔드와 값 재확인" 이라고 명시. **실제 응답값이 코드에 없음.**

### 8. 지도 위젯 — `CourseMapView` (동적 갱신 불가)

[lib/shared/widgets/course_map_view.dart](../../../lib/shared/widgets/course_map_view.dart):
- `StatelessWidget`, `KakaoMap(option:, onMapReady: (c) => _addMarkers(c, markers))`. `onMapReady`는 **최초 1회만** 발화 → rebuild로 마커를 바꿔도 반영 안 됨. `controller`를 State에 보관하지 않음.
- `CourseMapMarker.fromCoursePlaces`: 좌표 null/NaN/범위초과 방어 필터(재사용 가능한 패턴).
- 마커 아이콘: `KImage.fromWidget(_MarkerBadge(order), Size(28,28))` → `controller.labelLayer.addPoi(LatLng, style: PoiStyle(icon:, textStyle:), text:)`.
- `KakaoMapSdk.instance.initialize(...)`는 `app_startup.dart`에서 이미 호출. 콘솔 "카카오맵" 플랫폼 활성화는 이미 코스 선택 화면에서 동작하므로 검증됨.
- 사용처: `course_selection_screen.dart`의 `_CourseMapPreviewSheet`(바텀시트, 코스별 "지도로 보기")뿐.

### 9. 저장소

- `AppPreferences`(shared_preferences 래퍼): 단순 키-값(`lastActiveFilmRollId`, `currentUserId`, mock 설정). 리스트/구조체 저장 API 없음.
- `AppDatabase`(Drift, schemaVersion **4**): `FilmRolls`, `FilmRollPlaces`, `Photos`. `MigrationStrategy.onUpgrade`에서 `from < N` 블록으로 `addColumn` 누적. **북마크 테이블 없음.**

## 🎯 구현 목표

1. `ExploreScreen`을 "진입 시 진행중 필름롤 유무로 **탐색 모드 / 진행 모드** 전환되는 단일 화면"으로 재구성한다.
2. 두 모드가 지도 + 하단 시트 골격을 공유하고, 시트 내용·마커·CTA·필터만 교체한다.
3. 진행 모드의 현상 조건은 `VisitsApi.getVisits(serverFilmRollId)` 응답을 그대로 표기하고, `serverFilmRollId`가 없으면 로컬 진행률만 안전하게 노출한다.
4. 카카오맵을 채록길 탭에 도입하되 마커를 **동적 갱신 가능한** 형태로 만든다.
5. 장소 검색 / 카테고리 필터 실동작 / 진행 상태 필터 / 저장(북마크)를 포함한다.
6. 기존 코드 스타일(정적 API 클래스, `Controller` 재사용, `setState`, private 위젯 분리)을 100% 준수한다.

### 2️⃣ 핵심 구현 (파일별)

#### (a) 모드 판별 컨테이너 — `explore_screen.dart` 재구성

- `enum _ExploreMode { exploring, filmRollNoCourse, filmRollInProgress }`.
- `initState` + 재평가 시점에 `FilmRollModule.instance.recoverLastActiveFilmRoll()` 호출:
  - `null` → `exploring`
  - `filmRoll.selectedCourseId == null` → `filmRollNoCourse`
  - else → `filmRollInProgress`
- 공통 골격: `Scaffold` → 상단 지도 영역(`_ExploreMapView`, 아래 (d)) → 하단 시트(`DraggableScrollableSheet` 또는 고정 `Column`, 시안 6a/6b 절충). 시트 본문과 `markerSpec`, CTA는 모드 위젯이 주입.
- 모드별 본문 위젯을 파일 분리: `lib/features/explore/presentation/widgets/explore_mode_view.dart`, `film_roll_progress_view.dart`, `explore_place_filter.dart`, `explore_map_view.dart`.
- **재평가 트리거**(⚠️2): `MainTabScreen`이 `GlobalKey<ExploreScreenState>` 보유 → `_onTabSelected(index==1)` 및 `_onCameraTap` 종료 후 `exploreKey.currentState?.reevaluate()` 호출. (Key 교체로 전체 재생성하면 지도 네이티브 뷰가 매번 재초기화되므로 지양.) `main_tab_screen.dart`의 `const [...]` 리스트를 non-const로 바꾸고 `ExploreScreen(key: _exploreKey)` 전달.

#### (b) 탐색 모드 — `explore_mode_view.dart`

- 기존 `ExploreScreen`의 지역 `ChoiceChip` + `PlaceCategoryMenu` + 장소 리스트 로직을 이관.
- **장소 검색**: 검색 입력(`TextField`) → debounce → `PlacesApi.searchPlaces(regionId:, keyword:)`(`PlaceSearchResponse`). 빈 키워드면 `getExternalPlaces` 목록으로 복귀. 요청 토큰으로 경합 방어.
- **카테고리 필터 실동작**: 서버 분류 체계 확정됨 —
  `categoryGroup ∈ { TOURISM, FOOD, CAFE_DESSERT }`, `categoryDetail` 하위값:
  - `TOURISM`: `HERITAGE`, `MUSEUM`, `WALK`, `MARKET`, `SOUVENIR_SHOP`, `NATURE`, `EXPERIENCE`
  - `FOOD`: `RESTAURANT`, `LOCAL_FOOD`, `SNACK_MEAL`
  - `CAFE_DESSERT`: `CAFE`, `BAKERY`, `DESSERT`, `TEA_HOUSE`, `SNACK`

  이 enum을 `lib/data/models/place_category.dart`(신규)로 승격(문자열→enum, 미지값은 `unknown` 폴백 — 백엔드 값 추가 시 파싱 실패 방지). `PlaceCategoryMenu` 항목 ↔ 필터 매핑:

  | 필터 칩 | 매칭 조건 |
  |---|---|
  | 전체 | 무조건 |
  | 미기록 | `NearbyPlaceRecorder.isRecorded == false` (탐색 모드에선 전부) |
  | 유적·역사 | `categoryDetail == HERITAGE` |
  | 문화·전시 | `categoryDetail in { MUSEUM, EXPERIENCE }` |
  | 자연·산책 | `categoryDetail in { NATURE, WALK }` |
  | 시장·상권 | `categoryDetail == MARKET` |
  | 소품샵 | `categoryDetail == SOUVENIR_SHOP` |
  | 음식 | `categoryGroup == FOOD` |
  | 카페·디저트 | `categoryGroup == CAFE_DESSERT` |

  `_CategoryFilter` enum + `matches(place)` 로 구현. 시안 칩(자연/문화/카페/음식/유적지)은 위 라벨의 축약 표기로 통일.
- 리스트: 기존 `RecommendedPlaceCard`(거리/카테고리/`isRecorded` 뱃지) 재사용, 첫 항목 `isFeatured`.
- CTA: `이 채록길 시작하기`(기존 `_onEnterRegionTap` 로직) / 카드 탭 시 `자세히 보기`(→ `PlacesApi.getPlaceDetail`, 별도 상세 화면은 범위 밖이면 스낵바 or 최소 시트) / 저장(북마크) 토글.

#### (c) 진행 모드 — `film_roll_progress_view.dart`

- `FilmRollController(filmRollId: filmRoll.id, onStateChanged:)`를 **재사용**해 로컬 진행률/스팟 목록/방문 인증/완료를 그대로 연결(`FilmRollScreen`와 동일 흐름).
- `filmRollNoCourse` 모드: `추천 코스 선택하기` CTA → `FilmRollScreen._onSelectCourseTap`과 동일(regionId는 `filmRoll.regionId ?? RegionsApi.resolveRegion(filmRoll.regionName)`) → `CourseSelectionScreen` → `controller.selectCourse`.
- **현상 조건 섹션**: `filmRoll.serverFilmRollId != null`일 때만 `VisitsApi.getVisits(serverFilmRollId)` 호출 →
  `서로 다른 관광 유형 ${r.visitedCategoryCount}/${r.requiredCategoryCount}` + `visitRequirementMet` 시 "현상 준비 완료" 안내.
  실패/`serverFilmRollId==null` → 섹션 숨기고 `서버 동기화가 완료되면 현상 조건을 확인할 수 있어요` 로 대체(로컬 진행률은 항상 표시).
  호출 위치: 진행 모드 진입 + 방문 인증 성공(`completeVisit`) 후 1회. 캐싱은 화면 state에만(전역 캐시 불필요).
- **다음 장소 카드**(6a 스타일): `places` 중 `visitOrder` 순 첫 `!isVisited` 항목을 강조 카드로.
  `방문 인증하기`(활성 조건 = (e) 4단계 게이트 통과) / `필름 카메라 열기`(→ `VisitCaptureScreen(filmRollId, nextPlace.id)`, `main_tab_screen._onCameraTap`과 동일 후처리).
- **진행 상태 필터**: `전체 / 미방문(!isVisited) / 인증 가능(!isVisited && (e)게이트 통과) / 방문 완료(isVisited) / 촬영한 장소(photoCount > 0)`.
- **"다음 코스 둘러보기"**(3순위): 진행중 필름롤은 그대로 두고, 남은 코스 스팟을 미리 훑는 동선.
  탭 시 지도 카메라를 다음 미방문 스팟으로 이동 + 하단 목록을 해당 스팟으로 스크롤/하이라이트(진행 상태 필터 `미방문`과 연동). 필름롤 이탈/전환은 이번 범위에서 제공하지 않음(진행 모드는 활성 필름롤에 고정).
- 필름롤 완료(`completeFilmRoll` 성공) → `reevaluate()` → 자동으로 탐색 모드 복귀.

#### (d) 지도 위젯 — `explore_map_view.dart` (신규, Stateful)

- `CourseMapView`는 동적 갱신 불가하므로 **State에 `KakaoMapController`를 보관**하는 새 위젯 작성:
  - `onMapReady`에서 controller 저장 + 초기 마커 렌더.
  - `didUpdateWidget`에서 마커 목록/모드 변화 시 `labelLayer` POI를 갱신(기존 제거 후 재추가, 또는 diff).
  - 입력: `List<ExploreMapMarker>`(값 객체 신규 — `title, lat, lng, MarkerState`) + `currentPosition`.
  - `enum MarkerState { normal, recommended, categoryHighlighted /*탐색*/, visited, next, unvisited, verifiable /*진행*/ }` → `_MarkerBadge` 스타일 분기(색/아이콘/원형 하이라이트).
  - 좌표 유효성 필터는 `CourseMapMarker.fromCoursePlaces` 패턴 재사용.
- `CourseMapView` 자체는 건드리지 않음(코스 선택 화면 회귀 방지). 공통화가 필요하면 좌표 필터 헬퍼만 `lib/shared/`로 추출.
- 성능: 지도는 **채록길 탭에 1개만**. `IndexedStack` 상시 alive이므로 최초 진입 지연 로드(`Visibility`/`Offstage` 또는 첫 프레임 이후 생성) 고려(⚠️4).

#### (e) 방문 인증 4단계 게이트 (하드 차단)

`방문 인증하기` 탭 시 아래를 순서대로 재확인하고, 하나라도 실패하면 인증을 막고 사유별 안내 노출:

1. **거리 계산** — `Geolocator.distanceBetween(pos.lat, pos.lng, place.lat, place.lng)`.
2. **GPS 정확도 재확인** — `position.accuracy <= kVisitMinGpsAccuracyMeters`(50m). 초과 시 `현재 위치가 정확하지 않아요. 잠시 후 다시 시도해주세요` + 재조회.
3. **거리 재확인** — 1의 결과 `<= kVisitVerifiableRadiusMeters`(100m). 초과 시 `장소에 더 가까이 가면 인증할 수 있어요` + 현재 거리 표기.
4. **동일 필름롤 중복 인증 재확인** — `place.isVisited == false` (및 가능하면 `getVisits().visits`에 해당 `placeId` 없음). 이미 인증됐으면 `이미 방문 인증한 장소예요`.

- 위치 재조회: `LocationPermissionService.getCurrentPosition()` (권한/서비스 없으면 null → 1단계 진입 전 `현재 위치를 확인하는 중이에요` + 재시도). 인증 직전 최신 좌표를 다시 받아 stale 좌표로 통과되는 것을 막는다.
- 진행 상태 필터의 "인증 가능"도 1~3 게이트(중복 제외)를 그대로 사용해 목록/마커(`verifiable`)를 표시. 위치 미확인 시 "인증 가능" 판정 불가로 처리.
- `VisitCaptureScreen` 진입 자체는 게이트 통과 후에만 허용(촬영→`completeVisit` 흐름은 유지).

#### (f) 저장(북마크)

- `BookmarkRepository`(또는 간단히 `BookmarkStore`) — (1️⃣)에서 택한 저장소 위에 `toggle(identityKey, meta)`, `isBookmarked(identityKey)`, `list()`.
- 탐색 모드 카드/상세에 북마크 아이콘(3순위). 목록 화면은 이번 범위면 최소 형태, 아니면 자리만.

## ⚠️ 주의사항 (위험 요소 · 대안 · 결정 필요)

1. **방문 인증 게이트 = 신규 하드 차단(확정)** — 현재 `VisitCaptureScreen`/`completeVisit`엔 거리 검증이 전혀 없다. 이번에 (e)의 4단계(거리계산 → accuracy ≤ 50m → 거리 ≤ 100m → 중복 아님)를 **인증 차단 수준**으로 신규 도입한다. `visits_api.dart` 주석 전제("프론트가 GPS·거리 검증 후 placeId 전달")와 정합. Android는 `LocationSettings.accuracy`가 `medium`이라 `position.accuracy`가 50m를 자주 초과할 수 있음 → 게이트용 좌표는 `accuracy: high` + 짧은 timeout으로 별도 조회 검토(에뮬레이터 mock 좌표 accuracy 값 실측 필요).

2. **탭 전환 시 모드 재평가 메커니즘 부재** — `IndexedStack`(const children) + `RouteObserver`/`VisibilityDetector` 미사용. `GlobalKey<ExploreScreenState>` + `MainTabScreen`에서 명시 호출로 해결 예정이나, `main_tab_screen.dart`의 `const` 리스트/`ExploreScreen()` 시그니처 변경이 수반된다. 대안: 전역 `ValueNotifier<int> filmRollRevision`을 필름롤 변경 지점(enterRegion/selectCourse/completeVisit/completeFilmRoll)마다 bump하고 `ExploreScreen`이 구독 — 침투 범위가 넓어 1차는 GlobalKey 권장.

3. **카테고리 분류 체계 확정됨** — `categoryGroup ∈ {TOURISM, FOOD, CAFE_DESSERT}` + (b)의 `categoryDetail` 하위 enum. `place_category.dart`로 enum 승격하되 **미지값 `unknown` 폴백 필수**(백엔드가 값 추가 시 파싱 크래시 방지 — 과거 장소 API 분석의 지적). `EXPERIENCE`는 `문화·전시` 필터로 흡수했는데 시안 의도와 다를 수 있어 구현 시 라벨만 재확인. `getExternalPlaces`(TourAPI 실시간)가 이 enum 값을 그대로 주는지 실응답 1회 로깅으로 스팟체크 권장.

4. **지도 상시 alive 비용** — `MainTabScreen` `IndexedStack`은 4탭을 항상 살려둔다. 채록길 탭에 `KakaoMap`을 넣으면 백그라운드에서도 네이티브 뷰가 유지된다. 최초 진입 전까지 지연 생성(`Offstage`/첫 프레임 이후) 권장. `kakao_map_sdk`는 커뮤니티 패키지라 다중 인스턴스/생명주기 이슈 가능성 있어 실기기 확인 필수(과거 분석 문서 ⚠️2 참조).

5. **`getExternalPlaces` 장소엔 서버 `id`가 없음** — 방문 인증(`VisitsApi.createVisit`는 `serverPlaceId` 필요)·북마크 식별에 external ID(`tourContentId`/`kakaoPlaceId`)를 써야 한다. `NearbyPlaceRecorder`/`CoursePlaceResponse.identityParts`의 우선순위 규칙을 북마크 identityKey에도 동일 적용. 탐색 모드에서 임의 장소를 바로 방문 인증하는 흐름은 코스 개념과 충돌하므로 범위에서 제외(방문 인증은 진행 모드의 코스 스팟 한정).

6. **진행 모드 = `serverFilmRollId` 의존** — 현상 조건은 서버 필름롤 생성이 선행돼야 조회 가능. 생성은 `FilmRollSyncService`가 (위치 인증 세션 캐시 + 로그인 userId + 지역 일치) 조건에서만 수행. 오프라인/타지역/미인증 시 계속 null → **로컬 진행률(`visitedPlaceCount/totalPlaceCount`)로 graceful degradation** 필수. `FilmRollController`는 `serverFilmRollId`를 노출하지 않지만 `state.filmRoll.serverFilmRollId`로 접근 가능.

7. **진행 모드 = 활성 필름롤 고정(확정)** — 진행중이면 탐색 모드로 못 돌아간다. 대신 진행 모드 3순위 액션은 **"다음 코스 둘러보기"**((c) 참조 — 지도 카메라 이동 + 목록 하이라이트)로 처리한다. 필름롤 이탈/전환(`exitFilmRoll`/`deleteFilmRoll`) 동선은 이번 범위에서 **제외**(기존 `FilmRollScreen`/필름 컬렉션 경유).

8. **`ExploreScreen` 비대화** — 현재 302줄에 진행 모드까지 얹으면 관리 불가. 반드시 모드/필터/지도/카드 위젯을 `lib/features/explore/presentation/widgets/`로 분리하고, 진행 데이터는 `FilmRollController` 재사용으로 로직 중복을 피한다.

9. **`getVisits` 204 처리** — 서버가 방문 0건에 204를 줄 경우 `DioClient`가 `response.data`를 null로 주고 `VisitListResponse.empty()`(count 0)로 폴백되므로 화면은 "0/3"로 정상 표기. 별도 처리 불필요하나 실제 응답 코드 확인 권장.

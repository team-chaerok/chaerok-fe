### 핵심 흐름 재확인

**1) 홈 최초 진입 (`HomeDashboardScreen.initState`)**
- `addPostFrameCallback` → `_ensureLocationVerified()`
  - `LocationVerificationResult.sessionCache != null` → `_locationResult` 세팅 + `_onLocationVerified(cached)` → **`_autoConnectFilmRollEntry`(코스 선택/필름롤 화면 자동 push)**
  - `outOfServiceSessionCache == true` → `_isOutOfService = true` (뷰만 전환, 자동 push 없음)
  - 둘 다 아니면 `_runLocationVerification()` → `_applyLocationOutcome(outcome)` → `LocationVerified`면 다시 `_onLocationVerified` → 자동 push
- `refresh()` 도 호출되지만 내부는 `_loadRecoveredFilmRoll()` 뿐 (위치 재판정 없음)

**2) 홈 탭 복귀 (`MainTabScreen._onTabSelected(0)`)**
- `_homeKey.currentState?.refresh()` → `_loadRecoveredFilmRoll()` 만.
- **위치 인증은 재실행되지 않는다** — 코드 주석(`home_dashboard_screen.dart:131~137`)이 "캐시 히트 시 `_autoConnectFilmRollEntry`가 자동 네비게이션하므로 단순 탭 전환에서 절대 재실행 금지"라고 명시.

**3) 포그라운드 복귀 (`didChangeAppLifecycleState(resumed)`)**
- `refresh()` 호출 (역시 필름롤만).

**4) QA 토글 (`_onForceOutOfServiceChanged`)**
- `AppPreferences.setDebugOutOfServiceArea(enabled)` 만. 세션 캐시 미변경 → 홈 무반응. (버그 #1)

**5) `_onEnterGongju` / `_onReset`**
- 세션 캐시(`sessionCache` / `outOfServiceSessionCache`)를 직접 `null` / `false` 로 비우는 선례 존재.

**6) mock 좌표 결정 (`MockLocationGate.currentMockPosition`)**
- 우선순위: `injectPlace` → `gongjuEntered/Exited`(공주 대표) → `getMockRegionCodeName` + `getMockSpotIndex`(clamp).
- `setMockRegionCodeName` / `setMockSpotIndex` 는 **lib 전체에서 호출부 0건** — getter/게이트만 존재하는 미연결 상태. (버그 #2)

**7) mock 활성화 판정 (`MockLocationGate.isActive`)**
- `isAllowed()`(debug/profile 무조건, release는 `isTester`) AND (`TestModeSession.overridesLocation` OR `isMockLocationEnabled()`).
- `isMockLocationEnabled()` 가 false면 `LocationProviderFactory` 가 `RealLocationProvider` 반환 → 지역/스팟 설정 무의미.

**8) 러너의 서비스 지역 외 처리 (`location_verification_runner.dart:96~123`)** — ⚠️ 중요
- mock provider 경로에서도 `KakaoLocalApiService.resolveAdministrativeRegion(mock 좌표)` 로 실제 역지오코딩 수행.
- `forceOutOfServiceArea = !gongjuEntered && isAllowed() && isDebugOutOfServiceArea()`
- `isOutOfServiceArea = !gongjuEntered && (forceOutOfServiceArea || provinceName != '충청남도')`
- `useFallbackRegion = gongjuEntered || (kDebugMode && isOutOfServiceArea && !forceOutOfServiceArea)`
- **결론**: 디버그 빌드에서 "충남 외" 임의 좌표(예: 서울)를 넣으면 `useFallbackRegion == true` 가 되어 **공주시로 대체**된다. `OutOfServiceHomeView` 를 보려면 임의 좌표만으로는 부족하고 `충남 외 지역 홈 강제` 토글을 함께 켜야 한다. release/tester 빌드(`kDebugMode == false`)에서는 임의 좌표만으로 서비스 지역 외 판정됨.

### 대안 솔루션 (기각 사유는 plan 문서 §4 참조)

- 즉시 반영: 방식 A(패널이 직접 러너 실행 후 캐시 재적재) → 홈이 `cached != null` 분기로 `_autoConnectFilmRollEntry` 재실행 → P0-3 위반.
- 즉시 반영: 방식 C(홈 `refresh()` 가 항상 재판정) → 탭 전환마다 Kakao/백엔드 재호출 + 자동 네비 재발.
- 위치 UI: 별도 화면 신설 → 이슈의 "패널에 노출" 요구와 불일치.

### 성능 / 보안

- 재판정은 dirty=true 일 때만(패널 방문·변경 후 1회). 일반 탭 전환 비용 불변.
- 재판정 1회 = Kakao 역지오코딩 + `RegionsApi.resolveRegion` + `PlacesApi.getExternalPlaces` (최초 진입과 동일).
- 신규 저장값은 QA 게이트 뒤 SharedPreferences 로컬 전용, 민감정보 아님.

# 카카오맵 API 연동 — 코스/장소 위치조회 및 지도 표시 (분석)

## 📊 분석 요약

**감지된 프로젝트 타입**: Flutter (SDK ^3.9.2)
**주요 기술 스택**: Dio 5.8(네트워크), Drift(로컬 DB), `kakao_flutter_sdk_user`(카카오 로그인만 존재, 지도 SDK 없음), 상태관리 라이브러리 미사용(setState + 자체 Controller 패턴), Clean Architecture는 `features/film_roll/` 등 개별 feature 내부에서만 적용(domain/data/presentation 3계층), 전역은 `core/`·`data/`(공용 DTO·API)·`features/` 구조.
**코드 스타일**:
- API 클래스: `class XxxApi { const XxxApi._(); static Future<...> method(...) }` — 정적 메서드만 있는 private-constructor 유틸 클래스, `DioClient.instance.get/post<T>(path, fromJson: ...)` 후 `response.data ?? T.empty()` fallback.
- Response 모델: `json_serializable`/`freezed` 미사용, 수동 `fromJson` factory + `const` 생성자.
- Entity(도메인) 변환: Entity 자신이 `factory Xxx.fromYyyResponse(...)` 형태로 DTO→Entity 변환 책임을 가짐(별도 Mapper 클래스 아님). 좌표처럼 안전이 중요한 값은 변환 시점에 엄격 검증 후 예외를 던짐.
- 파일명 snake_case, DartDoc `///` 주석으로 "왜"를 설명하는 관례.

## 🔍 현재 상태

### 1. 이미 갖춰진 카카오 인프라 (재사용 가능)

이슈 본문은 "카카오맵 API 연동을 위한 API 키 설정"을 신규 작업으로 명시하지만, 실제로는 **카카오 REST API/네이티브 앱 키 인프라가 이미 완비**되어 있음:

- [lib/core/config/app_secrets.dart](lib/core/config/app_secrets.dart) — `kakaoNativeAppKey`, `kakaoRestApiKey` 이미 정의(gitignore 처리, `app_secrets.example.dart`가 템플릿).
- [lib/app/app_startup.dart](lib/app/app_startup.dart) — `KakaoSdk.init(nativeAppKey: AppSecrets.kakaoNativeAppKey)`가 이미 앱 부트스트랩에서 호출됨.
- Android: `android/local.properties`(`kakao.nativeAppKey`) → `build.gradle`의 `manifestPlaceholders` → `AndroidManifest.xml`의 `kakao${kakaoNativeAppKey}://` 스킴.
- iOS: `ios/Flutter/Secrets.xcconfig`(gitignore) → `Info.plist`의 `kakao$(KAKAO_NATIVE_APP_KEY)` URL scheme, `LSApplicationQueriesSchemes`.
- **카카오 로컬(Local) REST API 연동 레퍼런스가 이미 존재**: [lib/features/location/data/kakao_local_api_service.dart](lib/features/location/data/kakao_local_api_service.dart) — `dapi.kakao.com`을 백엔드용 `DioClient`와 별개인 자체 `Dio` 인스턴스(`Authorization: KakaoAK {REST_KEY}`)로 호출, `/v2/local/geo/coord2regioncode.json`(좌표→행정구역) 사용 중.

즉 "좌표/주소 조회"를 위한 API 키·호출 패턴은 신규 구축이 아니라 **기존 서비스를 확장**하는 작업이다.

### 2. 장소 좌표는 이미 코스 응답에 포함되어 있음 (단, 확정 코스는 제외)

| 모델 | 파일 | 좌표 필드 |
|---|---|---|
| `CoursePlaceResponse` (추천 코스 후보) | [lib/data/models/course_place_response.dart](lib/data/models/course_place_response.dart) | `double? latitude`, `double? longitude` — **있음(nullable)** |
| `SelectedCoursePlaceResponse` (확정된 코스) | [lib/data/models/selected_course_place_response.dart](lib/data/models/selected_course_place_response.dart) | **없음** — `placeId, source, title, categoryGroup, categoryDetail?, address, sequence`뿐 |
| `CourseCandidatePlace` (도메인 엔티티, 확정 저장 전 단계) | [lib/features/film_roll/domain/entity/course_candidate_place.dart](lib/features/film_roll/domain/entity/course_candidate_place.dart) | `double latitude/longitude`(non-null) — `fromCoursePlaceResponse`가 null/NaN/범위초과 시 `InvalidCoursePlaceException`을 던져 검증 |

`CoursesApi.getRecommendedCourses()`(`/api/courses/recommend`)는 `CourseRecommendResponse → List<CourseResponse> → List<CoursePlaceResponse>`를 반환하며 이미 좌표를 포함하므로, **추천 코스 화면([lib/features/film_roll/presentation/page/course_selection_screen.dart](lib/features/film_roll/presentation/page/course_selection_screen.dart))에서 지도에 마커를 찍는 데 추가 API 호출이 필요 없다.** 반면 확정된 코스(`SelectedCourseResponse`, `/api/courses/active` 등)를 지도에 표시하려면 좌표가 없어 별도 처리가 필요하다(⚠️ 참고).

### 3. 지도 표시 기능은 완전 미구현

`MapView|KakaoMap|GoogleMap|NaverMap|WebView` 전체 검색 결과 hit 0건. `pubspec.yaml`에도 지도 관련 패키지가 전혀 없다. `CourseSelectionScreen`은 현재 `ListView.separated` + 텍스트 카드로만 코스/장소를 나열하며(`'· ${place.title}'`), 지도·좌표 시각화가 전혀 없다.

### 4. 관련 기존 코드 패턴

- 네트워크: [lib/core/network/dio_client.dart](lib/core/network/dio_client.dart) 싱글톤 + interceptor 체인(Auth/Error/Logging). 백엔드 전용. 외부 호스트(Kakao 등) 직접 호출 시엔 `KakaoLocalApiService`처럼 별도 `Dio` 인스턴스를 만드는 게 이 프로젝트의 기존 관례.
- API 서비스 예시: [lib/data/remote/courses_api.dart](lib/data/remote/courses_api.dart), [lib/data/remote/places_api.dart](lib/data/remote/places_api.dart).
- 상태관리: 외부 라이브러리 없음. `film_roll_controller.dart` 주석: "이 프로젝트는 Provider/Riverpod 등 별도 상태관리 라이브러리를 쓰지 않으므로, 화면(State)이 이 클래스를 들고 콜백으로 setState한다." `CourseSelectionScreen`처럼 단순한 화면은 Controller 없이 `StatefulWidget`+`setState`만 사용.

## 🎯 구현 목표

1. 코스에 포함된 장소(추천 후보 및 확정 코스)의 좌표를 카카오맵 지도 위에 마커로 시각화한다.
2. 좌표가 없는 확정 코스 장소에 대한 조회 경로(Kakao Local API 재사용)를 마련한다.
3. `CourseSelectionScreen`(및 필요 시 확정 코스 상세 화면)에서 지도 뷰를 확인할 수 있게 한다.
4. 기존 코드 스타일(정적 API 클래스, Entity 변환 패턴, setState 기반 상태관리)을 100% 준수한다.

### 2️⃣ 핵심 구현 (파일별)

**a) Kakao Local API 확장** — [lib/features/location/data/kakao_local_api_service.dart](lib/features/location/data/kakao_local_api_service.dart)
- 확정 코스(`SelectedCoursePlaceResponse`, 좌표 없음)의 주소를 좌표로 역변환하는 메서드 추가: `/v2/local/search/address.json` 호출. 기존 `resolveAdministrativeRegion`과 동일한 클래스/Dio 인스턴스/에러 처리(`try-catch` + `log` + null 반환) 패턴을 따른다.
- 추천 코스(`CoursePlaceResponse`)는 이미 좌표가 있으므로 이 신규 호출이 **필요 없음** — 지도 마커는 응답값을 그대로 사용.

**b) 지도 마커 변환 헬퍼(신규)**
- `CourseCandidatePlace.fromCoursePlaceResponse`는 좌표 무효 시 예외를 던지는 "엄격 검증" 전용이라 지도 미리보기처럼 "일부 장소는 마커 생략, 나머지는 표시" 같은 관용적 처리에는 그대로 재사용하면 화면이 깨진다. 좌표가 유효한 장소만 걸러내는 **nullable 반환 헬퍼**(예: `List<CourseCandidatePlace> 대신 좌표 있는 place만 매핑`, 또는 지도 전용 경량 값 객체)를 새로 만들지, 기존 엔티티의 검증 로직을 그대로 감싸 try-catch로 스킵할지 결정 필요(사용자 확인 권장 — ⚠️ 참고).

**c) 지도 위젯(신규)**
- `KakaoMap` 위젯을 감싸는 재사용 위젯을 `lib/shared/widgets/`에 추가(예: `course_map_view.dart`, snake_case). `List<CoursePlaceResponse>`(또는 좌표 유효성 필터링된 리스트)를 받아 마커를 렌더링하는 `StatelessWidget`, `const` 생성자.

**d) `CourseSelectionScreen` 통합** — [lib/features/film_roll/presentation/page/course_selection_screen.dart](lib/features/film_roll/presentation/page/course_selection_screen.dart)
- 코스 카드마다 개별 지도(미니맵)를 렌더링하면 네이티브 뷰가 리스트 길이만큼 생성되어 스크롤 성능이 떨어짐 → **비권장**.
- 권장 UX: 카드 선택(`_onCourseSelected`) 이전에 "지도로 보기" 액션을 추가해 해당 코스의 장소들을 한 번에 보여주는 지도 프리뷰(바텀시트 또는 별도 화면)를 띄운다. 기존 `_isLoading`/`_errorMessage`/setState 패턴을 그대로 유지.

**e) 도메인 매핑**
- 매핑 체인: `CoursePlaceResponse(DTO, nullable 좌표)` → (지도 전용 필터링) → `KakaoMap` 마커. 기존 `CourseCandidatePlace` 확정 저장 흐름과는 별개의 경로로 취급한다(확정 저장은 여전히 엄격 검증을 유지해야 함 — 지도 미리보기 때문에 검증 강도를 낮추면 안 됨).

## ⚠️ 주의사항

1. **확정 코스에는 좌표가 없다** — `SelectedCoursePlaceResponse`에 위경도 필드 자체가 없어, "확정된 코스"를 지도에 표시하려면 (a) 백엔드에 좌표 필드 추가를 요청하거나 (b) 프론트에서 주소 기반 Kakao Local 재조회로 좌표를 역보강해야 한다. 두 방식 모두 정확한 좌표 정합성·비용(추가 API 호출) 트레이드오프가 있어 **백엔드 팀과 사전 조율이 필요**하다. 이슈 범위가 "추천/선택 코스" 둘 다를 언급하므로 이 부분을 먼저 확정하지 않으면 작업량 산정이 부정확해진다.
2. **써드파티 패키지 리스크** — `kakao_map_sdk`(pub points 145, 10 likes), `kakao_map_plugin`(pub points 140, 48 likes) 모두 카카오 공식이 아닌 커뮤니티 유지보수 패키지다. Flutter/Dart SDK 업그레이드 시 호환성이 깨질 수 있어 장기 유지보수 리스크를 감안해야 한다.
3. **iOS 지원 성숙도** — 카카오맵 네이티브 iOS SDK는 Android 대비 상대적으로 덜 성숙한 것으로 알려져 있어, 실기기 테스트를 반드시 거쳐야 한다.
4. **키 관리 재검토** — 이슈 본문은 "API 키 설정"을 신규 작업처럼 서술하지만 실제로는 기존 `AppSecrets.kakaoNativeAppKey`/`kakaoRestApiKey`를 재사용하면 되므로, 신규 키 발급이 필요한지(카카오 콘솔에서 "카카오맵" 서비스가 별도 활성화를 요구하는지) 먼저 확인해 불필요한 작업을 줄여야 한다.
5. **좌표 검증 로직 재사용 주의** — `CourseCandidatePlace.fromCoursePlaceResponse`는 코스 "확정 저장"을 안전하게 막기 위한 엄격 검증(예외 발생)이다. 지도 "미리보기"처럼 일부 장소의 마커만 생략하고 나머지는 보여줘야 하는 곳에 그대로 재사용하면 안 되고, 별도의 관용적(느슨한) 필터링 로직이 필요하다.
6. **성능** — 코스 카드 리스트에 개별 미니맵을 렌더링하는 방식은 네이티브 뷰 다중 생성으로 스크롤 성능 저하를 유발할 수 있어 지양하고, 선택 후 단일 지도 프리뷰 방식을 권장한다.
7. **상태관리 관례** — 이 프로젝트는 Provider/Riverpod 등을 쓰지 않으므로, 지도 관련 상태(마커 선택, 카메라 위치 등)도 기존 setState/Controller 패턴을 그대로 따라야 한다.

## ✅ 결정사항 (사용자 확인 완료)

1. **패키지**: `kakao_map_sdk`(네이티브) 채택 확정. 기존 `AppSecrets.kakaoNativeAppKey`를 재사용하며 신규 JavaScript 키 발급 불필요.
2. **작업 범위**: 이번 작업은 **추천 코스(`CourseSelectionScreen`, `CoursePlaceResponse`)의 지도 표시만** 포함한다. 확정 코스(`SelectedCourseResponse`) 지도 표시는 좌표 필드가 아예 없어 백엔드 스펙 변경이 선행되어야 하므로 **이번 범위에서 제외**하고 후속 작업으로 분리한다.

이에 따라 위 "2️⃣ 핵심 구현"의 (a) Kakao Local API 확장(주소→좌표 역조회)은 확정 코스용이었으므로 **이번 작업 범위에서 제외**되고, (b)~(e)만 진행한다.

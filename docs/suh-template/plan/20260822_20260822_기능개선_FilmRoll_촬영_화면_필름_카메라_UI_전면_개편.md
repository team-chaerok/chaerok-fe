# 🎯 촬영 화면 필름 카메라 UI 전면 개편 전략 문서

관련 이슈: [#57](https://github.com/team-chaerok/chaerok-fe/issues/57)
대상 파일: `lib/features/film_roll/presentation/page/visit_capture_screen.dart`

---

## 1. 요약

기본 Material UI로 구성된 현재 촬영 화면(`VisitCaptureScreen`)을, 사용자가 첨부한 디자인 목업을 기준으로 필름 카메라 컨셉의 커스텀 UI로 전면 개편한다. UI뿐 아니라 줌·플래시·카메라 전환·촬영 매수 카운터의 실제 동작까지 모두 구현하는 풀스펙 범위로 진행하며, 촬영 매수 카운터는 필름롤당 고정 노출수(24)를 새로 도입해 "현재 촬영 수 / 24" 형태로 표시한다. 하단 캡처 스트립은 과거 촬영 사진 갤러리가 아니라 현재 라이브 카메라 프리뷰와 연동된 필름 스트립 형태의 시각 요소로 구현한다.

## 2. 배경 및 목적

**문제/필요성**: 현재 촬영 화면은 `AppBar` + `CameraPreview` + 버튼 하나로 구성된 임시 UI로, 채록 서비스의 "필름 카메라" 정체성을 전혀 담고 있지 않다.

**목표**: 첨부 목업과 동일한 필름 카메라 UI(뷰파인더 프레임, 촬영 매수 카운터, 줌 셀렉터, 플래시 토글, 필름 타입 라벨, 카메라 정보, 닫기/전환/셔터 버튼, 하단 캡처 스트립)를 구현하고, 각 컨트롤이 실제 카메라 동작(줌 레벨, 플래시 모드, 전/후면 전환)과 연동되게 한다.

**범위**:
- 포함: 화면 레이아웃 전면 개편, 신규 위젯 분리, 줌/플래시/카메라 전환 실동작 연동, 필름롤당 고정 노출수(24) 도입 및 촬영 매수 카운터 실데이터 연동, 하단 라이브 캡처 스트립 구현.
- 제외: 필름 타입("공주:공주의 잔(殘)") 자체를 사용자가 선택/커스터마이징하는 기능(라벨 표시만 대상이며, 필름 타입 선택 플로우는 범위 밖). 24매 초과 시 촬영을 강제로 막을지 여부는 이번 문서의 결정사항에 포함하되 별도 확인이 필요하면 구현 단계에서 재확인.

## 3. 요구사항

**필수 (P0)**
- 뷰파인더 프레임(둥근 모서리 필름 프레임) 안에 `CameraPreview` 표시
- 상단: 플래시 OFF/ON 토글 + 필름 타입 라벨, 촬영 매수 카운터("N/24") + 닫기(X) 버튼
- 프레임 하단: 카메라 정보(카메라명 "Chaerok" + 부제 "Flim Camera")
- 우측: 줌 배율 선택(2x/1x/0.5x) + 원형 셔터 버튼, 셔터 버튼 하단 카메라 전환 버튼
- 줌 선택 시 `CameraController.setZoomLevel` 연동
- 플래시 토글 시 `CameraController.setFlashMode` 연동
- 카메라 전환 시 `availableCameras()` 기반 전/후면 컨트롤러 재초기화
- 필름롤당 고정 노출수(24) 도입 + `PhotoLocalDataSource.countByFilmRoll` 신규 구현으로 실제 촬영 매수 표시
- 하단 캡처 스트립: 라이브 카메라 프리뷰와 연동된 필름 스트립 시각 요소

**중요 (P1)**
- 줌 레벨은 기기가 지원하는 `minZoomLevel`~`maxZoomLevel` 범위를 벗어나지 않도록 클램프
- 카메라 전환 시 기존 초기화/라이프사이클 처리(권한 재확인 없이 컨트롤러만 교체)와 자연스럽게 통합
- 기존 에러/권한 거부 상태 UI(설정 이동 버튼 등)는 새 레이아웃에서도 동일하게 동작

**선택 (P2)**
- 24매 초과 시 셔터 비활성화 등 노출수 초과 처리(제품 정책 확정 전까지는 시각적 경고만 우선 고려)
- 줌/플래시 전환 시 마이크로 인터랙션(애니메이션)

## 4. 선택한 접근 방식

**방식**: 풀스펙 — UI 개편과 동시에 줌/플래시/카메라 전환/촬영 매수 카운터를 모두 실제 데이터·컨트롤러 API에 연동.

**이유**: 사용자가 명시적으로 "풀스펙(전체 기능 동작)"을 선택함. 카메라 UI는 인터랙션이 곧 UX의 핵심이라 UI만 먼저 만들고 나중에 로직을 붙이면 위젯 인터페이스를 다시 설계해야 하는 경우가 많아, 처음부터 실데이터 연동까지 함께 설계하는 편이 재작업 비용이 낮음.

**대안**: MVP(UI 우선, 로직은 스텁) 방식도 검토했으나, 카메라 제어(`CameraController`)는 이미 프로젝트에 도입되어 있어 신규 의존성 추가 없이 바로 연동 가능하고, 사용자가 후속 이슈 분리보다 한 번에 완성하는 것을 선호해 채택하지 않음.

**촬영 매수 카운터 데이터 소스**: 필름롤당 고정 노출수(24) 신규 도입 채택.
- 대안 1(방문 장소 수 재사용: `FilmRoll.totalPlaceCount`/`visitedPlaceCount`) — 기존 필드라 구현 비용은 가장 낮지만, "촬영 매수"라는 의미와 "방문 장소 수"라는 의미가 실제로 다르며(한 장소에서 여러 장 촬영 가능) 목업의 필름 롤 컨셉과 맞지 않아 기각.
- 대안 2(정적 하드코딩) — 검증용으로는 빠르지만 풀스펙 요구사항과 맞지 않아 기각.
- 채택안: 새 상수(예: 필름롤당 최대 노출수 24)를 도메인에 도입하고, `PhotoLocalDataSource`에 필름롤 전체 촬영 수를 세는 `countByFilmRoll` 메서드를 신규 추가해 실제 촬영 수를 분자로 사용.

**하단 캡처 스트립**: "현재 촬영되고 있는 카메라 영상"을 반영하는 요소로 채택.
- 대안(이번 방문 촬영 사진 썸네일 갤러리 / 필름롤 전체 사진 갤러리)은 과거 촬영물을 다시 보여주는 방식으로, 사용자가 선택하지 않아 기각.
- 채택안: 과거 사진 목록이 아니라 라이브 프리뷰와 연동된 필름 스트립 형태의 시각 요소로 구현(정확한 시각적 동작은 구현 단계에서 목업을 다시 참고해 세부 확정).

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 작업 범위 | 풀스펙(UI + 실동작) | 사용자 확정, 재작업 비용 최소화 |
| 촬영 매수 카운터 데이터 | 필름롤당 고정 노출수(24) 신규 도입 | 방문 장소 수와 의미가 달라 기존 필드 재사용 불가 |
| 하단 캡처 스트립 | 라이브 카메라 프리뷰 연동 | 과거 사진 갤러리가 아닌 실시간 촬영 상태 반영 |
| 신규 위젯 위치 | `lib/features/film_roll/presentation/page/widgets/` | 다른 feature의 `presentation/widgets/` 컨벤션과 일관성 유지 |
| 카메라 관련 상태 관리 | `VisitCaptureScreen`의 `StatefulWidget` 내부 상태 유지(별도 컨트롤러 미도입) | 줌/플래시/전환 상태는 이 화면에 한정된 휘발성 상태로, 별도 `ChangeNotifier` 컨트롤러 도입은 과설계 |

## 6. 고려사항 및 위험요소

**기술적 위험**
- 기기별로 `minZoomLevel`/`maxZoomLevel`이 다르며 0.5x(광각) 미지원 기기가 있을 수 있음 → UI 노출 전 `CameraController.value` 또는 관련 API로 지원 여부 확인 후 미지원 배율은 비활성화 처리 필요.
- 카메라 전환(전/후면) 시 기존 컨트롤러 dispose → 재초기화 과정에서 현재 구현된 라이프사이클 로직(`didChangeAppLifecycleState`)과 경합할 수 있음 → 전환 중에는 라이프사이클 재초기화가 중복 실행되지 않도록 가드 필요.
- `countByFilmRoll` 신규 쿼리 추가로 인한 로컬 DB 조회 비용 → 촬영 직후마다 재조회하지 않고 로컬 상태에서 증분 처리하는 방식 고려.

**비즈니스 위험**
- 24매를 초과해도 촬영을 막지 않을 경우 "필름 카메라" 컨셉과 카운터 표시가 모순될 수 있음(예: "25/24") → 초과 시 동작(차단 vs 표시만)은 구현 전 재확인 필요(P2 항목).
- 하단 캡처 스트립의 정확한 시각적 의미(라이브 프리뷰를 어떤 형태로 필름 스트립화할지)는 목업 해석에 따라 달라질 수 있어 구현 착수 전 디자인 재확인 권장.

- [ ] 플래시 토글 시 실제 플래시 모드 변경
- [ ] 카메라 전환 버튼으로 전/후면 카메라 전환 동작
- [ ] 촬영 매수 카운터가 실제 촬영 수 기준으로 "N/24" 형태로 갱신

- [ ] 하단 캡처 스트립이 라이브 카메라 프리뷰와 연동되어 표시

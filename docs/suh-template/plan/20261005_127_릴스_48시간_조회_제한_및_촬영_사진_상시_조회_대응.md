## 🎯 릴스 48시간 조회 제한 및 촬영 사진 상시 조회 대응 전략 문서

- 관련 이슈: [#127](https://github.com/team-chaerok/chaerok-fe/issues/127) "🚀[기능개선][현상결과] 릴스 48시간 조회 제한 및 촬영 사진 상시 조회 대응"
- 작업 브랜치: `20261005_#127_릴스_48시간_조회_제한_및_촬영_사진_상시_조회_대응`
- 작성일: 2026-10-05

### 1. 요약

백엔드는 현상 결과(필터 사진·릴스)를 현상 완료 후 48시간만 보관하고, 그 뒤에는 결과 조회에
`EXPIRED` 상태와 빈 결과를 내려준다. 프론트의 현상 결과 화면은 이 상태를 처리하지 않아 48시간이
지나면 사진은 빈 화면, 릴스는 "릴스를 준비하지 못했어요."로 보인다. 이번 작업은 (1) 48시간 안에
결과 화면을 열 때 필터 사진을 기기에 내려받아 보관하고, (2) 만료 후에는 기기에 보관된 필터 사진을
보여주되 못 받은 사진만 촬영 원본으로 대체하며, (3) 릴스는 "보관 기간 종료"로 명확히 안내한다.
백엔드 변경 없이 프론트만으로 처리한다.

### 2. 배경 및 목적

**문제/필요성**

- 백엔드 정책: 현상 완료 시 `expiresAt = completedAt + 48시간`. 만료 후 결과 조회는 `EXPIRED` +
  빈 결과. 다운로드 주소는 10분짜리이며 48시간 안에는 다시 조회하면 새로 발급된다.
- `FilmRollResultScreen`은 `isCompleted`/`isExpired`를 구분하지 않고 `filteredPhotos`와 `reel`을
  그대로 그린다. 만료 응답이 오면 오류처럼 보이는 빈 화면이 된다.
- 결과 화면의 사진은 전부 서버 주소(`Image.network`)에 의존한다. 기기에는 촬영 원본
  (`film_rolls/{filmRollId}/{placeId}/original|thumbnail/{photoId}.jpg`)만 있고 필터 사진은 없다.
- 현상 대기 화면(`FilmRollDevelopingView`)은 폴링 중 `EXPIRED`를 받으면 안내만 띄우고 로컬 상태를
  완료로 바꾸지 않는다. 현상 후 48시간 넘게 앱을 열지 않은 필름 롤은 계속 "현상 중" 화면에 머문다.

**목표**: 릴스는 현상 후 48시간 동안만, 사용자가 촬영한 사진은 기간과 관계없이 볼 수 있게 한다.

**범위**

- 포함: 현상 결과 화면의 만료 상태 처리, 릴스 조회 기한 안내, 필터 사진 기기 보관, 만료 후 사진
  표시(보관된 필터 사진 → 없으면 촬영 원본), 현상 대기 화면의 만료 진입 흐름, 관련 테스트.
- 제외: 백엔드 보관 정책 변경, 사진의 갤러리 저장(내보내기) 기능, 기기 변경·재설치 시 사진 복원,
  현상 결과 화면 전체 UI 리디자인.

### 3. 요구사항

**필수 (P0)**

- 결과 조회가 `EXPIRED`이면 오류 화면이 아니라 "릴스 보관 기간 종료" 상태로 결과 화면을 그린다.
- 만료 상태에서 릴스 재생·저장·공유는 비활성화하고, 다음 문구로 안내한다:
  "릴스 보관 기간이 끝났어요. 촬영한 사진은 계속 볼 수 있어요."
- `COMPLETED` 상태로 결과 화면을 열면 필터 사진을 기기에 내려받아 보관한다.
- 만료 후 대표 사진·미리보기·전체 사진 화면은 기기에 보관된 필터 사진을 보여준다. 보관본이 없는
  사진은 촬영 원본으로 대체한다.
- 촬영 원본으로 대체된 사진에는 "필터 미적용" 표시를 붙인다 (대표 사진·미리보기·전체 사진 화면 공통).
- `EXPIRED`여도 `completedAt`·`expiresAt`이 null일 수 있다고 보고 처리한다 (아래 4번의 만료 구분 참고).
- 필름 롤을 삭제하면 보관한 필터 사진도 함께 삭제된다.

**중요 (P1)**

- 48시간 이내에는 릴스를 언제까지 볼 수 있는지 표시한다 (응답의 `expiresAt` 기준).
- 화면을 열어 둔 사이 만료된 경우(저장·공유·재생 직전 재조회가 `EXPIRED`) 만료 상태로 전환한다.
- 현상 대기 화면이 폴링 중 "보관 기간 경과" `EXPIRED`(`completedAt` 있음)를 받으면 필름 롤을
  완료 처리하고 만료 상태의 결과 화면으로 이어지게 한다. "조건 미달 종료" `EXPIRED`
  (`completedAt` 없음)는 기존 안내를 그대로 유지한다.
- 방문 장소 수·사진 수 통계는 만료 응답의 빈 값이 아니라 기기 데이터 기준으로 표시한다.

**선택 (P2)**

- 필름 롤 모아보기 진입 시, 아직 필터 사진을 받지 않은 완료 필름 롤을 미리 내려받기 (결과 화면을
  48시간 안에 한 번도 열지 않는 경우를 줄이기 위함).
- 네트워크 오류로 결과 조회가 실패해도 기기에 보관된 사진이 있으면 사진만 먼저 보여주기.

### 4. 선택한 접근 방식

**방식**: 필터 사진 기기 보관 + 촬영 원본 대체.

- 보관 위치: 기존 필름 롤 폴더 아래 `film_rolls/{filmRollId}/filtered/{serverPhotoId}.jpg`.
  필름 롤 삭제 시 폴더째 지우는 기존 동작(`deleteFilmRollDirectory`)에 그대로 포함되므로 별도
  정리 로직과 DB 스키마 변경이 필요 없다.
- 연결 기준: 서버 `filteredPhotos[].photoId` ↔ 기기 `FilmRollPhoto.serverPhotoId`. 정렬은 기기
  사진의 `sequence`를 따른다.
- 표시 규칙:

| 상태 | 사진 | 릴스 |
|------|------|------|
| `COMPLETED` (48시간 이내) | 기기 보관본이 있으면 보관본, 없으면 서버 주소 | 재생·저장·공유 가능 + 기한 안내 |
| `EXPIRED` (48시간 경과) | 기기 보관본, 없으면 촬영 원본 | 보관 기간 종료 안내, 버튼 비활성화 |

- 만료 구분 (백엔드 코드 확인 결과, 실제 호출 검증은 아님):

| 필드 | 보관 48시간 경과 | 이탈 시 조건 미달로 종료 |
|------|------------------|--------------------------|
| `status` | `EXPIRED` | `EXPIRED` |
| `completedAt` | 현상 완료 시각 | null |
| `expiresAt` | 완료 + 48시간 | null |
| `totalPhotoCount` | 촬영 장수 | 촬영 장수 |
| `processedPhotoCount` | 촬영 장수와 동일 | 0으로 추정 |
| `filteredPhotos` / `zip` / `reel` | `[]` / null / null | `[]` / null / null |

  두 경우는 `completedAt` 유무로 구분한다. "릴스 보관 기간이 끝났어요" 안내는 보관 기간 경과에만
  쓴다. 조건 미달 종료는 현상된 적이 없으므로 이 문구를 쓰지 않는다.
- 화면은 서버 응답 모델을 직접 그리지 않고, "기기 파일 또는 서버 주소" 중 하나를 가진 표시용
  사진 목록을 받아 그린다. 목록을 만드는 일은 화면 밖(유스케이스)에서 한다.

**이유**: 사용자가 선택한 방향이며, 백엔드 변경 없이 만료 전후로 같은 필터 사진을 볼 수 있다.
폴더 구조와 삭제 흐름을 재사용해 변경 범위가 작다.

**대안 (선택하지 않은 이유)**

- *촬영 원본만 표시*: 가장 단순하지만 만료 전후로 사진 색감이 달라져 "현상된 필름 사진"이라는
  결과물의 의미가 사라진다.
- *백엔드에 사진 보관 요청*: 기기 변경·재설치에도 유지되지만 백엔드 정책·비용 변경이 필요하고
  이번 일정에서 프론트만으로 끝낼 수 없다.

### 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 만료 후 사진 | 보관된 필터 사진 → 없으면 촬영 원본 | 사용자 확정 |
| 필터 사진 보관 시점 | `COMPLETED` 결과를 받은 직후 (결과 화면 진입 시) | 다운로드 주소가 10분짜리라 받은 즉시 내려받아야 함 |
| 보관 위치 | 필름 롤 폴더 아래 `filtered/` | 기존 삭제 흐름 재사용, DB 변경 없음 |
| 서버·기기 사진 연결 | `photoId` ↔ `serverPhotoId` | `sequence` 기본값(0)인 옛 데이터에도 안전 |
| 보관 실패 처리 | 화면은 정상 표시, 다음 진입 때 재시도 | 보관은 부가 동작이라 결과 열람을 막지 않음 |
| 48시간 값 | 프론트에 하드코딩하지 않고 응답의 `expiresAt`·`status` 사용 | 백엔드 정책 변경에 따라가기 위함 |
| 만료 시 릴스 버튼 | 비활성화 + 안내 문구 | 이슈 명세 그대로 |
| 만료 안내 문구 | "릴스 보관 기간이 끝났어요. 촬영한 사진은 계속 볼 수 있어요." | 사용자 확정 |
| 원본 대체 사진 표시 | "필터 미적용" 라벨 표시 | 사용자 확정, 만료 전후 색감 차이를 설명 |
| 만료 종류 구분 | `completedAt` 유무 | 조건 미달 종료도 같은 `EXPIRED`로 내려옴 |
| 의존성 주입 | 생성자 선택 인자 + `FilmRollModule` 기본값 | `FilmRollDevelopingView`의 기존 패턴, 테스트 용이 |

### 6. 구현 단계

1. **필터 사진 보관소** — `lib/core/file/local_photo_storage.dart`
   - 필터 사진 저장, 필름 롤별 보관 경로 조회 기능 추가. 경로는 기존처럼 문서 폴더 기준 상대
     경로 규칙을 따른다.
2. **표시용 사진 모델과 유스케이스** — `lib/features/film_roll/domain/`
   - 표시용 사진 엔티티 (순서, 기기 파일 경로 또는 서버 주소, 필터 적용 여부).
   - 필터 사진 내려받아 보관하는 유스케이스 (이미 받은 사진은 건너뜀, 일부 실패 허용).
   - 결과 상태와 기기 사진을 합쳐 표시용 목록을 만드는 유스케이스 (위 표시 규칙 적용).
   - `FilmRollModule`에 등록.
3. **현상 결과 화면** — `film_roll_result_screen.dart`
   - 만료 상태 분기, 릴스 영역의 기한 안내 / 보관 기간 종료 안내 (확정 문구 사용).
   - 촬영 원본으로 대체된 사진에 "필터 미적용" 라벨 표시.
   - `expiresAt`이 null이면 기한 안내를 숨긴다.
   - 사진 영역을 표시용 사진 목록 기반으로 전환 (기기 파일·서버 주소 모두 그림).
   - 통계를 기기 데이터 기준으로 표시.
   - 저장·공유·재생 직전 재조회가 만료면 만료 상태로 전환.
4. **전체 사진 화면** — `film_roll_result_photos_screen.dart`
   - 표시용 사진 목록을 받도록 변경, 원본 대체 사진에 "필터 미적용" 라벨 표시.
5. **현상 대기 화면** — `film_roll_developing_view.dart`
   - 폴링 중 `completedAt`이 있는 `EXPIRED`를 받으면 완료 처리 후 결과 화면(만료 상태)으로 이동.
   - `completedAt`이 없는 `EXPIRED`(조건 미달 종료)는 기존 동작 유지.
6. **테스트**
   - 결과 화면: 48시간 이내(기한 안내 표시), 만료(안내 문구·버튼 비활성화·기기 사진 표시),
     보관본 없는 사진의 원본 대체와 "필터 미적용" 라벨, `expiresAt` null 처리.
   - 유스케이스: 표시 규칙, 보관 건너뛰기·부분 실패.
   - 현상 대기 화면: 보관 기간 경과 만료 시 결과 화면 이동, 조건 미달 종료 시 기존 안내 유지.
7. **(P2)** 필름 롤 모아보기 진입 시 미리 내려받기, 조회 실패 시 기기 사진 표시.

### 7. 고려사항 및 위험요소

**기술적 위험**

- *48시간 안에 결과 화면을 한 번도 열지 않으면 필터 사진을 받을 수 없다* → 촬영 원본으로
  대체해 사진 자체는 항상 보이게 한다. P2의 미리 내려받기로 빈도를 줄인다.
- *기기 변경·앱 재설치 시 기기 사진이 모두 사라진다* → 이번 범위 밖. "상시 조회"는 같은 기기
  기준임을 이슈에 남기고, 필요하면 백엔드 보관을 별도 이슈로 다룬다.
- *내려받는 도중 다운로드 주소(10분) 만료* → 실패한 사진만 다음 진입 때 새 주소로 다시 받는다.
- *서버가 처리하지 못해 필터 사진이 없는 촬영분* → 48시간 이내에는 안 보이다가 만료 후 원본으로
  나타날 수 있다. 만료 후에도 "보관본이 있는 사진 + 서버에 올라간 적 없는 사진"만 원본 대체할지
  구현 단계에서 확인한다.
- *저장 공간* → 필름 롤당 최대 24장 수준이라 영향이 작고, 필름 롤 삭제 시 함께 지워진다.
- *수정 범위* → 파일 보관소와 유스케이스 추가는 UI 전용 작업 범위를 넘는 기능 변경이다. 인증,
  네트워크 설정, API 계약, DB 스키마는 건드리지 않는다.

**비즈니스 위험**

- *사용자가 릴스가 사라지는 것을 모르고 놓친다* → 48시간 이내에 기한을 항상 보여 주고, 저장하기
  버튼을 그대로 눈에 띄게 둔다.
- *만료 화면이 오류처럼 보인다* → 오류 색상·문구를 쓰지 않고 안내 박스로 표현하며, 사진은 계속
  볼 수 있다는 점을 함께 적는다.

### 8. 성공 기준

- [ ] 48시간 이내: 사진·릴스가 지금과 동일하게 보이고, 릴스 조회 기한이 표시된다.
- [ ] 48시간 이내에 결과 화면을 열면 필터 사진이 기기에 보관된다.
- [ ] 48시간 경과: 릴스 영역에 보관 기간 종료 안내가 나오고 재생·저장·공유가 비활성화된다.
- [ ] 48시간 경과: 대표 사진·미리보기·전체 사진 화면에 사진이 계속 보인다 (보관본 우선, 없으면 원본).
- [ ] 촬영 원본으로 대체된 사진에 "필터 미적용" 표시가 보인다.
- [ ] `completedAt`·`expiresAt`이 null인 `EXPIRED` 응답에도 화면이 깨지지 않는다.
- [ ] 현상 후 48시간 넘게 앱을 열지 않은 필름 롤도 "현상 중"에 머물지 않고 결과 화면으로 이어진다.
- [ ] 필름 롤 삭제 시 보관한 필터 사진이 함께 삭제된다.
- [ ] `flutter analyze`, `flutter test` 통과.

### 9. 확인이 필요한 사항

- "필터 미적용" 라벨의 모양과 위치 (사진을 가리지 않는 작은 라벨 기준으로 구현 후 확인).
- 조건 미달로 종료된 필름 롤의 `processedPhotoCount` 초기값 (백엔드 미확인, 프론트는 이 값에 의존하지 않음).
- 백엔드 응답 내용은 코드로 확인한 것이므로, 구현 후 실제 만료 응답으로 한 번 검증한다.

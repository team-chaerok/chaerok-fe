## 1. 요약

필름롤이 지역 이탈을 확정하면 서버는 1시간 뒤 현상(릴스 생성)을 예약하지만, FE에는 현상 완료를 감지하거나 결과(방문 장소/사진/릴스)를 보여주는 화면이 없다. 조사 결과 릴스 생성 파이프라인(`POST /develop`, `GET /results`, Lambda 렌더러)은 백엔드에 이미 완성되어 있고, `User.reviewMode` 플래그가 켜진 테스트 계정은 1시간 대기 검사가 서버에서 자동으로 면제된다는 사실도 확인했다. 따라서 백엔드 변경 없이 FE가 이탈 확정 직후 `/develop`을 즉시 호출하고 `/results`를 폴링하는 것만으로 "개발 단계 즉시 릴스 생성"과 "현상 결과 페이지" 두 가지를 모두 구현할 수 있다.

## 2. 배경 및 목적

**문제/필요성**: 사용자가 장소 인증 후 지역을 이탈하면 릴스가 생성되어야 하지만, 현재는 완료 감지·결과 화면이 없어 기능을 확인할 방법이 없다. 원래 스펙(이탈 1시간 후 알림 + 릴스 생성)은 개발 단계에서 검증하기엔 너무 느리다.

**목표**:
1. 지역 이탈 확정 즉시(1시간 대기 없이) 릴스 생성을 트리거한다.
2. 생성 완료를 폴링으로 감지해 "현상 결과 페이지"로 자동 전환한다.
3. 결과 페이지에서 방문 장소 수/촬영 사진/릴스를 확인하고, 저장·공유까지 가능하게 한다.

**범위**:
- 포함: FE의 `/develop`·`/results` API 연동, 현상 대기 화면의 즉시 트리거·폴링 로직, 현상 결과 페이지(+ 전체 사진 화면), 릴스 재생/저장/공유.
- 제외: 백엔드 코드 변경, "1시간 후 알림" 자체(개발 단계에서는 미적용, 원 스펙의 알림 기능은 별도 후속 과제), 웹소켓/푸시 기반 완료 알림, 릴스 생성 실패 자동 재시도 UX.

## 3. 요구사항

**필수 (P0)**
- 지역 이탈 확정 직후 `POST /api/film-rolls/{id}/develop` 즉시 호출
- `GET /api/film-rolls/{id}/results` 폴링(2~3초 간격)으로 완료 감지
- 완료 시 현상 결과 페이지로 자동 전환 (타이틀/지역/날짜/대표 이미지/방문 장소 수/촬영 사진 수/사진 3장 미리보기/릴스 카드)
- 릴스 전체화면 재생

**중요 (P1)**
- 저장하기(갤러리 저장), 공유하기(OS 공유 시트) — 릴스 mp4 기준
- "오늘의 사진 전체 보기" 그리드 화면
- FAILED/EXPIRED 상태에 대한 최소 에러 안내

**선택 (P2)**
- 없음 (이번 범위는 P0/P1으로 충분히 완결되는 단위 기능)

## 4. 선택한 접근 방식

**방식**: 서버 사이드 `reviewMode` 기반 즉시 트리거 + 클라이언트 폴링

이탈 확정 후 FE가 스케줄러(60초~1시간)를 기다리지 않고 바로 `/develop`을 호출한다. 일반 계정은 서버가 `FilmRollDevelopmentTimingService`에서 1시간 대기를 강제하므로 이 호출 방식은 dev/prod 분기 없이 프로덕션에도 그대로 둘 수 있다. 완료 감지는 `/results`를 2~3초 간격으로 폴링하는 방식을 쓴다.

**이유**:
- 백엔드 코드를 전혀 건드리지 않고 "개발 단계 즉시 생성" 요구를 충족한다.
- 이미 검증된 테스트 계정(`reviewMode=true`)으로 바로 end-to-end 확인이 가능하다.
- 웹소켓 인프라가 프로젝트에 없으므로(사용자 확인 완료) 폴링이 가장 단순하고 리스크가 적은 방식이다.

**대안(왜 선택하지 않았는지)**:
- *백엔드에 별도 dev-bypass 플래그/프로퍼티 신설*: `reviewMode`와 기능이 중복되고, 백엔드 코드 변경 및 배포가 추가로 필요해 범위가 커진다. 이미 켜져 있는 테스트 계정을 활용하는 편이 더 빠르고 안전하다.
- *웹소켓/푸시 기반 완료 알림*: 백엔드에 관련 인프라가 없고, 이번 범위(개발 단계 검증)에 비해 과도한 투자다.

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|---|---|---|
| 즉시 생성 트리거 방식 | 이탈 확정 직후 FE가 `/develop` 즉시 호출 | 서버 `reviewMode`가 1시간 대기를 이미 면제해줌, 백엔드 변경 불필요 |
| 완료 감지 방식 | `/results` 폴링(2~3초) | 웹소켓 인프라 없음(확인 완료), 폴링이 가장 단순 |
| 결과 데이터 영속화 | 로컬 DB 저장 안 함, 진입 시마다 재조회 | presigned URL이 짧은 만료시간을 가짐 |
| 릴스 재생 위치 | 카드 인라인 재생 대신 탭 시 전체화면 플레이어 | 리스트 스크롤 중 리소스 낭비 방지 |
| 저장/공유 범위 | 실제 기능까지 구현(갤러리 저장 + OS 공유 시트) | 사용자 승인 완료, "전체 구현" 요청 |
| 신규 패키지 | `video_player`, `gal`, `share_plus` | 재생/저장/공유에 필요한 최소 패키지, 기존 미사용 확인 |

## 6. 고려사항 및 위험요소

**기술적 위험**
- *폴링 중 앱이 백그라운드로 가거나 화면이 dispose될 경우*: 타이머/스트림 구독이 누수되지 않도록 `dispose`에서 반드시 취소해야 한다 → 구현 단계에서 `WatchFilmRollResultUseCase` 구독 해제 검증.
- *presigned URL 만료 후 재생/다운로드 시도*: 결과 페이지 재진입 시 `/results`를 재호출해 최신 URL을 받으므로, 페이지에 오래 머문 상태에서 만료되는 경우는 저장/공유 액션 시점에 재조회하는 방어 로직이 필요할 수 있다.
- *테스트 계정의 `reviewMode` 의존성*: 이 계정이 아니면 정상적으로 1시간 대기가 걸린다 — QA/다른 개발자가 새 계정으로 테스트할 때 혼선이 생길 수 있으므로, 결과 문서에 "reviewMode 계정으로만 즉시 생성 확인 가능"임을 명시한다.

**비즈니스 위험**
- 원 스펙의 "1시간 후 알림" 기능이 이번 범위에서 빠지므로, 실제 사용자 대상 릴리즈 전에는 별도 이슈로 알림 기능을 반드시 추가해야 한다 (범위 밖으로 명시, 후속 이슈 필요).

## 7. 성공 기준

- [ ] `reviewMode=true` 테스트 계정으로 지역 이탈 확정 후 1시간을 기다리지 않고 즉시 릴스 생성이 시작된다.
- [ ] 생성 완료가 폴링으로 감지되어 현상 결과 페이지로 자동 전환된다.
- [ ] 결과 페이지에 타이틀/지역/날짜/대표 이미지/방문 장소 수/촬영 사진 수/사진 3장/릴스 카드가 목업대로 표시된다.
- [ ] 릴스 탭 시 전체화면 재생, 저장하기로 갤러리 저장, 공유하기로 OS 공유 시트가 정상 동작한다.
- [ ] FAILED/EXPIRED 응답 시 에러 안내가 표시되고 앱이 크래시하지 않는다.

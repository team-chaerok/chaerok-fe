# 🎯 회원가입 로직 구현 — signup API 연동 전략 문서

> 관련 이슈: [#12 ⚙️[기능추가][Auth] 회원가입 로직 구현 — signup API 연동](https://github.com/team-chaerok/chaerok-fe/issues/12)

---

## 1. 요약

`SignupScreen`을 스켈레톤 상태에서 실제 동작하는 회원가입 화면으로 구현한다.
닉네임 입력 UI와 약관 동의 체크박스를 추가하고, `AuthApi.signUp()`을 연동해 API 호출 후 `HomeScreen`으로 이동하는 흐름을 완성한다.
토큰 저장은 별도 토큰 관리 이슈에서 처리하므로 이번 범위에서 제외한다.

---

## 2. 배경 및 목적

**문제/필요성**
- `SignupScreen`은 `signupToken` props를 받지만 아무런 동작을 하지 않는 스켈레톤 상태
- `SignupRequest` 모델과 `AuthApi.signUp()` 메서드는 이미 완성되어 있으나 UI·서비스 레이어와 미연결

**목표**
- 닉네임 입력 + 약관 동의 UI 구현
- `POST /api/auth/signup` API 연동
- 가입 성공 시 `HomeScreen` 이동, 실패 시 에러 메시지 노출

**범위**
- 포함: `SignupScreen` 구현, `AuthApi.signUp()` 연동, 에러 처리
- 제외: 토큰 저장 로직 (토큰 관리 이슈 선행 필요), `SignupRequest` 모델 변경

## 4. 선택한 접근 방식

**방식**: `SignupScreen`을 `StatefulWidget`으로 변환, UI 상태 직접 관리

**이유**
- 현재 `LoginScreen` 패턴(`StatelessWidget` + 로직 메서드 분리)과 일관성 유지
- 입력값·로딩·에러 등 로컬 상태만 필요하므로 외부 상태 관리(Provider/Bloc) 불필요
- 코드베이스 전반에 상태 관리 레이어가 아직 없음

**대안**: ChangeNotifier + Provider 패턴
- 기각 이유: 이번 이슈 범위를 초과하는 아키텍처 도입, 단일 화면에 과도함

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 약관 동의 UI | 체크박스 2개 (termsAgreed + privacyAgreed) | SignupRequest 필드 반영, 사용자 명시적 동의 |
| 토큰 저장 | 이번 이슈에서 생략 | "토큰 관리 이슈 선행 필요" 명시, 별도 이슈에서 처리 |
| 가입 성공 후 이동 | `Navigator.pushReplacement` → HomeScreen | 로그인 화면 스택 제거 (로그인·회원가입 화면으로 뒤로가기 불가) |
| 에러 처리 | 스낵바 또는 인라인 텍스트 | LoginScreen 패턴의 `_errorMessage()` 참고 |
| 위젯 타입 | `StatefulWidget` | 닉네임, 약관 체크, 로딩, 에러 등 4가지 로컬 상태 필요 |


**UI 구조**
```
Scaffold
└── body: Padding
    └── Column
        ├── TextField (닉네임 입력)
        ├── CheckboxListTile (이용약관 동의)
        ├── CheckboxListTile (개인정보처리방침 동의)
        ├── if (errorMessage != null) Text(에러, color: error)
        ├── Spacer
        └── ChaerokButton (
              text: '가입하기',
              isEnabled: nickname.isNotEmpty && termsAgreed && privacyAgreed && !isLoading
            )
```

### Step 2: 회원가입 로직 구현

```dart
Future<void> _onSignupTap() async {
  setState(() => isLoading = true);
  try {
    final tokens = await AuthApi.signUp(SignupRequest(
      signupToken: widget.signupToken,
      nickname: nicknameController.text.trim(),
      termsAgreed: true,
      privacyAgreed: true,
    ));
    // 토큰 저장 → 토큰 관리 이슈에서 처리 예정
    if (!context.mounted) return;
    await Navigator.pushReplacement(
      context,
      MaterialPageRoute(builder: (_) => const HomeScreen()),
    );
  } catch (e) {
    setState(() => errorMessage = _errorMessage(e));
  } finally {
    setState(() => isLoading = false);
  }
}
```

## 8. 고려사항 및 위험요소

**기술적 위험**
- 토큰 저장 없이 HomeScreen 이동 시, 이후 API 호출에 인증 토큰이 없어 401 발생 가능
  - 대응: 토큰 관리 이슈를 이 이슈 직후 처리해야 함. 지금은 HomeScreen이 스켈레톤 상태라 실질적 문제 없음

**비즈니스 위험**
- 닉네임 유효성 검사 정책(길이, 특수문자 등)이 서버와 미합의 시 UX 불일치
  - 대응: 서버 에러 메시지를 그대로 표시하는 방향으로 처리

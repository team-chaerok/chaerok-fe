## 🎯 홈 화면 방문 인증 안내 개선 전략 문서

- 관련 이슈: [#110](https://github.com/team-chaerok/chaerok-fe/issues/110) "[기능개선][Home] 홈 화면 구성 개선 · 장소 인증 안내 친절화"
- 관련 설계 문서: `docs/superpowers/specs/2026-09-20-home-visit-guidance-design.md`
- 작성일: 2026-09-20

### 1. 요약

홈 화면의 필름롤 갤러리(`RegionPhotoGallery`)는 미방문 장소를 탭하면 거리·GPS 확인 없이 바로
카메라가 열려, 처음 쓰는 사용자가 "어떻게 인증하는지" 안내받지 못한다. 이미 채록길 탭
(`FilmRollProgressView`)에 검증된 게이트(`evaluateVisitGate`)와 상태별 안내 카드 패턴이 있으므로,
이를 공유 위젯으로 추출해 홈 화면에도 동일하게 적용한다. 이번 스코프는 인증 안내 개선에 집중하고
홈 화면 섹션 재배치는 별도로 다룬다.

### 2. 배경 및 목적

**문제/필요성**: 홈 화면과 채록길 탭이 같은 "방문 인증"이라는 행위를 서로 다른 UX로 제공한다 —
채록길은 거리 게이트 + 상태 문구 + CTA가 있는 반면 홈은 아무 안내 없이 카메라부터 연다. 이슈에
적힌 "인증 안내 부족" 문제의 실체가 바로 이 격차다.

**목표**: 채록길 탭이 이미 검증한 게이트/문구 체계를 홈 화면에도 적용해, 두 화면에서 동일한
인증 UX·카피를 제공한다.

**범위**:
- 포함: 홈 화면 "다음 장소"/"자유 촬영" 안내 카드 신설, 거리·GPS 게이트 적용, 채록길 탭 카드
  UI 리팩터(공유 위젯화), 관련 위젯 테스트 보완.
- 제외: 홈 화면 전체 섹션 배치(헤더/날씨/근처 채록 장소 순서) 재구성 — 별도 이슈/작업으로 분리.

### 3. 요구사항

**필수 (P0)**
- 홈 화면 필름스트립의 미방문 칸 탭 시 `evaluateVisitGate`로 거리·GPS 정확도를 확인하고, 통과
  못하면 카메라 대신 상태별 안내 문구(스낵바)를 보여준다.
- 미방문 장소가 있을 때 이름·주소·상태 문구·"방문 인증하기" CTA를 담은 "다음 장소" 카드를
  hero와 필름스트립 사이에 노출한다.
- 기존 `region_photo_gallery_test.dart`의 깨지는 테스트를 수정하고, 새 동작에 대한 테스트를
  추가한다.

**중요 (P1)**
- 코스 필수 장소를 모두 인증했고 필름이 남았을 때 게이트 없이 촬영 가능한 "자유 촬영" 카드를
  제공한다.
- `GuidanceCard`/`VisitGateMessage` 공유 위젯을 추출해 채록길 탭의 기존 카드도 같은 위젯으로
  리팩터, 두 화면의 인증 UX·카피를 통일한다.

**선택 (P2)**
- 없음 — 이번 범위에서 선택 항목은 두지 않는다(스펙 문서 그대로 완성도 있게 진행하기로 확정).

### 4. 선택한 접근 방식

**방식**: 공유 위젯 추출(`GuidanceCard`, `VisitGateMessage`) + 홈은 기존 `_locationResult.position`
재사용 + 필름스트립 탭과 카드 CTA를 하나의 게이트 핸들러(`_onVerifyTap`)로 통합.

**이유**: 게이트 로직(`evaluateVisitGate`)과 상태별 카피는 이미 채록길 탭에서 검증되어 있다.
새로 만들지 않고 재사용하면 안정성이 가장 높고(우선순위 1순위), 홈이 이미 갖고 있는 위치 데이터를
그대로 쓰면 새 위치 추적 인프라 없이도 구현할 수 있어 리스크가 작다.

**대안(왜 선택하지 않았는지)**:
- *홈 전용 카드 독립 작성*: 채록길 코드를 건드리지 않아 리스크는 가장 작지만, 두 화면의 안내
  문구/스타일이 나중에 따로 놀 수 있어 "일관된 인증 UX"라는 이슈의 취지에 맞지 않는다.
- *새 카드 없이 hero 캡션만 확장*: 변경 폭은 가장 작지만 좁은 캡션 영역에 문구+버튼을 넣기
  어렵고, 처음 쓰는 사용자에게 "이게 안내다"라고 눈에 띄게 전달하기 부족하다.
- *탭마다 GPS 신선 조회를 부모까지 끌어올리는 구조(채록길과 완전 동일한 스트림 방식)*: 홈은
  지역 이탈 감지처럼 위치를 지속 추적해야 할 다른 이유가 없어 과설계다. 탭 시점 1회 조회 +
  내부 상태로 충분하다고 판단해 범위 밖으로 뺐다.

### 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|---|---|---|
| 게이트 로직 재사용 여부 | 기존 `evaluateVisitGate` 그대로 사용, 신규 로직 없음 | 이미 채록길에서 검증된 로직 — 안정성 우선 |
| 카드 UI 공유 범위 | `GuidanceCard`(컨테이너)+`VisitGateMessage`(상태 문구)만 공유, 게터·핸들러는 화면별 유지 | 짧은 로직까지 공유하면 두 화면이 과하게 결합됨 |
| 홈의 위치 데이터 소스 | `HomeDashboardScreenState._locationResult.position` 재사용 | 이미 날씨 조회에도 쓰는 값 — 새 인프라 불필요 |
| 탭 시점 신선한 좌표 조회 방식 | `@visibleForTesting debugFetchCurrentPosition` 훅 추가(기존 `debugRunLocationVerification`과 동일 패턴) | 테스트 가능성 확보 + 기존 관례 재사용 |
| 필름스트립 탭 vs 카드 CTA | `_onVerifyTap` 단일 핸들러로 통합 | 두 진입점이 같은 게이트를 반드시 통과해야 하므로 로직 이원화 방지 |
| 자유 촬영 상태 포함 여부 | 포함 | 이슈가 "완료된 상황"별 안내도 명시했고, 채록길 패턴을 그대로 가져오면 추가 비용이 작음 |
| 섹션 배치 재구성 | 이번 범위 제외 | 인증 안내에 집중해 리뷰·검증 범위를 좁히고 안정성을 높임(P0 우선순위와 일치) |

### 6. 고려사항 및 위험요소

**기술적 위험**
- 기존 `region_photo_gallery_test.dart`의 "미방문 타일 탭 → 카메라 즉시 오픈" 테스트가 깨진다.
  → 대응: `debugFetchCurrentPosition`으로 반경 안 좌표를 주입하도록 테스트를 함께 수정(스펙에
  이미 명시).
- `film_roll_progress_view.dart`는 현재 위젯 테스트가 전혀 없어 리팩터 회귀를 자동으로 잡을 수
  없다. → 대응: 구현 단계에서 채록길 탭 수동 스모크 테스트(다음 장소/자유 촬영 카드 렌더 확인)를
  체크리스트에 포함.
- 홈은 위치를 1회만 조회하므로(지속 스트림 없음) 사용자가 카드를 오래 보다가 위치가 바뀌면
  카드에 표시된 상태 문구가 살짝 낡을 수 있다. → 대응: CTA 탭 시점에는 항상 신선한 좌표를 다시
  조회하므로 실제 인증 가부 판단(=실행되는 동작)은 항상 최신 값을 기준으로 한다. 표시 문구만
  약간 지연될 수 있는 정도로, 이번 범위에서는 허용 가능한 트레이드오프로 명시.

**비즈니스 위험**
- 없음 — 순수 클라이언트 UX 개선이며 서버 API·데이터 모델 변경이 없다.

### 7. 성공 기준

- [ ] 홈 화면에서 반경 밖(100m 초과)이거나 GPS가 부정확한 상태로 미방문 장소를 탭하면 카메라가
      열리지 않고 채록길과 동일한 안내 문구가 스낵바로 뜬다.
- [ ] 미방문 장소가 있을 때 "다음 장소" 카드(이름·주소·상태 문구·CTA)가 hero와 필름스트립 사이에
      노출된다.
- [ ] 코스 필수 장소를 모두 인증하고 필름이 남았을 때 "자유 촬영" 카드가 게이트 없이 카메라를
      연다.
- [ ] `GuidanceCard`/`VisitGateMessage`가 채록길 탭과 홈 화면 양쪽에서 동일하게 렌더된다(수동
      확인 + 신규 위젯 테스트).
- [ ] 기존 `region_photo_gallery_test.dart` 전체와 신규 테스트가 모두 통과한다.
- [ ] 채록길 탭 수동 스모크 테스트에서 리팩터 이후 기존 동작(다음 장소/자유 촬영/필터/지역 이탈
      배너)에 회귀가 없다.

# 🎯 애플 로그인 기능 추가 전략 문서

> 작성일: 2026-09-01 · 상태: 전략 수립 (Plan) · 다음 단계: `/analyze`
> 이슈 컨텍스트 없음 — 순번 기반 파일명 사용. 구현 전 이슈 등록 권장.

---

## 1. 요약

기존 카카오·구글 OAuth 로그인에 **Apple 로그인(iOS 전용)** 을 추가한다. 백엔드는 이미
`provider = APPLE` 를 지원하며, 프론트는 `sign_in_with_apple` 패키지로 Apple `identityToken`
과 재생공격 방지용 `nonce` 를 획득해 기존 `/api/auth/login` 엔드포인트에 그대로 전달한다.
신규 회원 처리는 현행 `signupToken` → `SignupScreen` 플로우를 재사용하며, 클라이언트가
Apple 이름/이메일을 별도로 중계하지 않는다. Android 로그인 화면에는 Apple 버튼을 노출하지
않는다.

---

## 2. 배경 및 목적

### 문제 / 필요성
- App Store 심사 가이드라인 **4.8 / 5.1.1(v)**: 서드파티 소셜 로그인(카카오·구글)을 제공하는
  iOS 앱은 **Apple 로그인을 동등하게 제공**해야 한다. 현재 미제공 → 심사 리젝 리스크.
- 백엔드는 `provider` enum 에 `APPLE` 를 이미 추가한 상태로, 프론트 대응만 남았다.

### 목표
- iOS 로그인/회원가입 화면에서 "Apple로 계속하기" 로 로그인·가입이 가능하다.
- 기존 카카오·구글과 **동일한 요청/응답 계약**(`/api/auth/login` → `registered` / `tokens` /
  `signupToken`)을 그대로 사용한다.

### 범위

**포함**
- `sign_in_with_apple` 패키지 도입 및 iOS 네이티브 설정(Capability, 엔타이틀먼트, Apple Developer App ID)
- `AppleAuthService` 신규 추가 (`identityToken` + `rawNonce` 반환)
- `OAuthProvider` enum 에 `apple` 추가, `OAuthLoginRequest` 에 선택적 `nonce` 필드 추가
- `login_screen.dart` 에 Apple 버튼 + 핸들러 추가 (iOS 한정 노출)
- `my_screen.dart` provider 라벨 스위치에 `apple` 케이스 추가
- Apple 로그인 취소/실패 처리 (기존 패턴 답습)
- 단위 테스트 (요청 직렬화, enum 라운드트립)

**제외 (이번 범위 아님)**
- Android Apple 로그인 (웹 리다이렉트 + Service ID + redirect endpoint) — 미지원
- 회원탈퇴 시 Apple 서버측 토큰 revoke (`authorizationCode` 필요) — §6 위험요소로 별도 관리
- Apple 이름/이메일을 백엔드로 중계하는 기능 — 현행 닉네임 직접입력 유지
- macOS/web Apple 로그인

## 3. 요구사항

### 필수 (P0)
- [ ] iOS 에서 Apple 로그인 버튼 탭 → Apple 인증 시트 → `identityToken` 획득
- [ ] `nonce` 를 클라이언트가 생성(raw)하고 SHA256 해시를 Apple 요청에 전달, raw nonce 를
      `/api/auth/login` 요청에 포함 → 백엔드가 JWT 의 `nonce` 클레임과 대조
- [ ] `OAuthLoginRequest(provider: apple, idToken: <identityToken>, nonce: <rawNonce>)` 전송
- [ ] 응답의 `registered` / `signupToken` / `tokens` 분기를 기존 `_handleLoginResponse` 로 처리
- [ ] 신규 회원은 기존 `SignupScreen(signupToken:)` 플로우로 진입
- [ ] Apple 인증 취소 시 조용히 로딩만 해제 (카카오·구글과 동일한 UX)
- [ ] Android 로그인 화면에 Apple 버튼 미노출

### 중요 (P1)
- [ ] `my_screen.dart` 의 `_providerLabel` 에 `apple → 'Apple'` 추가 (exhaustive switch 컴파일 보장)
- [ ] Apple 브랜드 가이드 준수 버튼 스타일 (검정 배경 / 흰 글자 / Apple 로고, `assets/images/apple-logo.svg`)
- [ ] `OAuthLoginRequest.toJson` 단위 테스트 (apple + nonce 포함 케이스, kakao/google 은 nonce 미포함 유지)
- [ ] `OAuthProvider.fromJson('APPLE')` / `toJson()` 라운드트립 테스트

### 선택 (P2)
- [ ] `SignInWithApple.isAvailable()` 로 구형 기기 방어 (iOS 13 타깃이라 사실상 항상 true)
- [ ] Apple 로그인 로깅을 기존 `log(..., name: _tag)` 패턴으로 통일
- [ ] 회원탈퇴 화면 문구에 "Apple 설정 > Apple ID 로그인에서 앱 접근 권한을 직접 해제해 주세요" 안내 (revoke 미구현 보완)

## 4. 선택한 접근 방식

### 방식: `sign_in_with_apple` 패키지 + 기존 OAuth 파이프라인 재사용

**이유**
- `sign_in_with_apple` 은 Flutter 커뮤니티 표준(사실상 유일한 성숙 패키지), iOS 네이티브
  `ASAuthorizationController` 를 그대로 래핑해 추가 서버 구성 없이 native 플로우 동작.
- 기존 `KakaoAuthService` / `GoogleAuthService` 가 "SDK 로 토큰 얻어 문자열 반환" 형태로
  이미 정형화돼 있어, `AppleAuthService` 를 같은 모양으로 추가하면 `login_screen` 변경이 최소화됨.
- 요청 모델은 `provider` enum 확장 + `nonce` 선택 필드 추가만으로 충분 —
  백엔드가 `idToken` 필드를 그대로 재사용하므로 응답 처리 코드는 무변경.

**대안 1 — `firebase_auth` 의 Apple provider**
- 기각: 프로젝트에 Firebase 미도입. Auth 하나 때문에 Firebase 전체를 얹는 건 과함.

**대안 2 — iOS 네이티브(Swift) 직접 구현 + MethodChannel**
- 기각: `sign_in_with_apple` 가 정확히 이 일을 대신함. 유지보수 부담만 증가.

**대안 3 — nonce 없이 identityToken 만 전송**
- 기각: 사용자가 "클라이언트 생성 + 백엔드 검증" 으로 확정. 재생공격 방지를 위해 필요하고,
  Apple 이 권장하는 방식.

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 지원 플랫폼 | **iOS 전용** | Android 는 Apple 네이티브 미지원 → 웹 리다이렉트/Service ID/redirect endpoint 필요, 작업량 과다. iOS 만으로 심사 요건 충족 |
| 패키지 | `sign_in_with_apple` (^7.x, 최신 안정) | 커뮤니티 표준, native 플로우, 서버 구성 불필요 |
| 백엔드 토큰 계약 | `idToken` 필드에 Apple `identityToken` 그대로 | 사용자 확정. 응답 처리 코드 무변경 |
| nonce | 클라이언트가 raw 생성 → SHA256 해시를 Apple 에 전달, raw 를 백엔드로 | 사용자 확정. 표준 재생공격 방지 |
| 요청 모델 변경 | `OAuthProvider.apple` 추가 + `OAuthLoginRequest.nonce` **선택 필드** 추가 | kakao/google 직렬화에 영향 없이 apple 만 nonce 동반 |
| `AppleAuthService.signIn()` 반환형 | 문자열 대신 `({String idToken, String rawNonce})` 레코드 (또는 소형 클래스) | Apple 은 토큰+nonce 쌍이 필요 — kakao/google 의 `Future<String>` 시그니처와 달라지는 지점 |
| 신규 회원 이름 | 백엔드로 미중계, 기존 `signupToken` → `SignupScreen` 닉네임 직접입력 유지 | 사용자 확정. 클라이언트 변경 최소 |
| Android 버튼 | `Platform.isIOS` 로 조건부 렌더 (`location_permission_service` 의 `Platform.isAndroid` 패턴 답습) | Android 에서 동작 불가한 버튼 노출 방지 |
| `crypto` 의존성 | transitive → **direct dependency 로 승격** | nonce SHA256 해시에 명시적 사용 |
| 회원탈퇴 revoke | 이번 범위 제외, 위험요소로 관리 | `authorizationCode` 계약이 없음. §6 참조 |

## 6. 고려사항 및 위험요소

### 기술적 위험

| 위험 | 영향 | 대응 |
|------|------|------|
| **iOS 네이티브 설정 누락** — Xcode "Sign In with Apple" capability + `Runner.entitlements` + Apple Developer 포털 App ID(`com.leebakju.chaerok`) 에서 Sign In with Apple 활성화 필요 | 설정 없으면 `getAppleIDCredential` 즉시 실패 | `/analyze` 단계에서 체크리스트화, 구현 시 Xcode 설정 스크린샷으로 검증. 프로비저닝 프로파일 재발급 필요 |
| **`AppleAuthService` 반환형이 기존 서비스와 불일치** (`Future<String>` vs 토큰+nonce 쌍) | `login_screen` 핸들러 시그니처 분기 | Apple 전용 핸들러 `_onAppleLoginTap` 에서만 레코드 처리, 공통 `_handleLoginResponse` 는 그대로 재사용 |
| **`_providerLabel` exhaustive switch 컴파일 에러** | 빌드 실패 | 오히려 안전장치 — enum 추가 시 컴파일러가 누락 지점(현재 `my_screen.dart:206`) 강제 노출. 그 외 `OAuthProvider` 를 switch 하는 지점 전수조사 필요 |
| **nonce 계약 불일치** — 백엔드가 기대하는 필드명/형식(raw vs hashed, 필드명 `nonce`) 확인 필요 | 로그인 401/400 | 구현 착수 전 백엔드 담당자와 요청 JSON 스키마 1줄 확정 (`{ "provider": "APPLE", "idToken": "...", "nonce": "<raw>" }` 가정) |
| **Apple 이 email 을 relay(익명 이메일)로 주거나 최초 1회만 제공** | 백엔드가 email 을 identityToken JWT 에서 추출한다는 전제 | 사용자 확정대로 클라이언트는 관여 안 함. 백엔드가 JWT `email` 클레임 사용하는지만 확인 |
| **시뮬레이터에서 Apple 로그인 불안정** | QA 지연 | 실기기(iOS 13+) 테스트 필수로 명시 |

### 비즈니스 / 정책 위험

| 위험 | 영향 | 대응 |
|------|------|------|
| **App Store 5.1.1(v)** — 앱 내 회원탈퇴 시 Apple 토큰도 서버에서 revoke 해야 함. 현재 계약(`identityToken` only)엔 `authorizationCode` 가 없어 revoke 불가 | 심사 리젝 가능성 | (a) 백엔드가 별도로 Apple revoke 를 처리하는지 확인, 없다면 (b) `OAuthLoginRequest` 에 `authorizationCode` 도 추가하는 후속 이슈 등록. 최소한 탈퇴 안내 문구(P2)로 임시 보완 |
| **Apple 브랜드 가이드라인** — 버튼 문구/색상/로고 규격 있음 | 심사 지적 | "Apple로 계속하기" 문구, 검정 배경, 공식 로고 SVG 사용. `SignInWithAppleButton` 위젯 사용도 검토(단 기존 `SocialLoginButton` 과 스타일 이질감) |
| **카카오/구글 버튼과 시각적 정합성** | 디자인 QA | `assets/images/apple-logo.svg` 추가 후 기존 `SocialLoginButton` 재사용, 로고 위치(`Positioned left:86`) 확인 |

## 8. 성공 기준

- [ ] iOS 실기기에서 Apple 로그인 → 신규 계정: `SignupScreen` 진입 → 가입 완료 → `MainTabScreen`
- [ ] iOS 실기기에서 Apple 로그인 → 기존 계정: 토큰 저장 → `MainTabScreen` 직행
- [ ] Apple 인증 시트에서 취소 → 앱이 로그인 화면 유지, 로딩 인디케이터 해제, 크래시 없음
- [ ] 잘못된/변조된 nonce 로는 백엔드가 로그인을 거부 (계약 검증)
- [ ] Android 빌드에서 Apple 버튼 미노출, 카카오·구글 정상 동작 (회귀 없음)
- [ ] `flutter analyze` 무경고, 기존 + 신규 테스트 전부 통과
- [ ] `my_screen` 에서 Apple 로 가입한 계정의 provider 라벨이 "Apple" 로 표시
- [ ] App Store 심사 제출 전 회원탈퇴 revoke 정책(5.1.1(v)) 결론 문서화

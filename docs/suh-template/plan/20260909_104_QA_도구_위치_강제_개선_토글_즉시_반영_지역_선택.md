## 1. 요약

원거리 테스터가 Test Mode(QA) 패널만으로 위치 기반 시나리오를 검증하지 못하는 두 지점을 푼다.
(1) "충남 외 지역 홈 강제" 토글이 즉시 반영되지 않아 앱 재실행 전까지 결과 확인 불가, (2) mock 위치가 항상 공주 고정이라 부여·서산·예산이나 임의 좌표에서 시작 불가.
해결 방향은 **QA 상태 변경 시 위치 인증 세션 캐시를 무효화하고 홈 대시보드가 자동 네비게이션 부작용 없이 다시 위치 판정을 수행**하게 하고, **QA 패널에 지역/스팟 드롭다운 + 임의 위경도 입력 UI와 "현재 적용 위치" 상태 표시를 추가**하며, 위치를 고르면 mock 위치를 자동 활성화하는 것이다.

## 2. 배경 및 목적

### 문제 / 필요성

| # | 현상 | 근본 원인 |
|---|------|----------|
| 1 | QA 토글(`충남 외 지역 홈 강제`)을 껐다 켜도 홈이 그대로 | `_onForceOutOfServiceChanged`가 `AppPreferences.setDebugOutOfServiceArea`만 갱신하고 `LocationVerificationResult.sessionCache` / `outOfServiceSessionCache`를 비우지 않음. 홈 대시보드는 최초 1회만 `_ensureLocationVerified`를 수행하고, 탭 재진입·포그라운드 복귀 시 `refresh()`는 필름롤만 재조회함(`_loadRecoveredFilmRoll`). |
| 2 | 내 위치를 조정할 수 없음 — 항상 공주 | QA 패널에 위치 선택 UI 없음. `_onEnterGongju`가 `공주시` 하드코딩. `MockLocationGate.currentMockPosition`은 `AppPreferences.getMockRegionCodeName` / `getMockSpotIndex`를 이미 읽지만, 이 두 setter(`setMockRegionCodeName` / `setMockSpotIndex`)는 **현재 코드베이스 어디에서도 호출되지 않는 사실상 dead code**임. |

### 목표

- QA 토글·위치 선택을 바꾼 뒤 **탭을 홈으로 되돌리는 것만으로** 홈 상태(정상 홈 ↔ 지역별 둘러보기 홈, 지역명·근처 장소)가 갱신되게 한다.
- QA 패널에서 mock 위치를 **지역/스팟 드롭다운 + 임의 위경도 직접 입력**으로 선택할 수 있게 한다.
- 패널 상태 카드에 **현재 적용 중인 mock 위치**를 노출한다.

### 범위

**포함**
- `test_mode_panel_screen.dart`: 위치 선택 UI(드롭다운 2단 + 임의 좌표 입력), 상태 카드 "현재 mock 위치" 행, 토글/선택 변경 시 세션 캐시 무효화 + 홈 재판정 트리거
- `home_dashboard_screen.dart`: QA 변경 감지 시 자동 네비게이션 없이 위치만 재판정하는 경로 추가
- `AppPreferences`: 임의 좌표 저장용 키 추가(위경도), 필요 시 "mock 좌표 모드"(스팟 vs 임의) 구분 값
- `MockLocationGate.currentMockPosition`: 임의 좌표 우선순위 반영 + 우선순위 주석 최신화
- `mock_location_spots.dart` / `region_code.dart`: 필요 시 라벨/헬퍼만 (좌표 데이터 변경 없음)

**제외**
- `공주 진입` 등 기존 5단계 시나리오 흐름 자체의 동작 변경 (진입/방문/이탈 우선순위는 그대로 유지)
- 방문 인증 좌표 주입(`injectPlace`) 로직 변경
- release 빌드에서의 mock 허용 정책(`MockLocationGate.isAllowed`) 변경
- 상태관리 라이브러리 도입 (기존 `ChangeNotifier` + static 캐시 패턴 유지)
- 지역 확장(4개 지역 고정), 신규 화면 추가

## 3. 요구사항

### 필수 (P0)

- **P0-1** "충남 외 지역 홈 강제" 토글을 변경하면 `LocationVerificationResult.sessionCache` / `outOfServiceSessionCache`가 즉시 무효화된다.
- **P0-2** 홈 대시보드가 QA 변경(토글 + 지역/스팟 + 임의 좌표) 이후 홈 탭 복귀 시 위치 판정을 다시 수행하고, 그 결과로 정상 홈 ↔ `OutOfServiceHomeView`가 전환된다.
- **P0-3** P0-2의 재판정은 **자동 네비게이션 부작용이 없어야 한다** — `_autoConnectFilmRollEntry`(코스 선택/필름롤 화면 자동 push)가 단순 QA 재판정에서는 실행되지 않는다.
- **P0-4** QA 패널에 지역(공주·부여·서산·예산) + 지역별 스팟 드롭다운이 추가되고, 선택 시 `AppPreferences.setMockRegionCodeName` / `setMockSpotIndex`에 저장된다.
- **P0-5** QA 패널에 임의 위도/경도 직접 입력이 추가되고, 입력 시 `MockLocationGate.currentMockPosition`이 스팟 대신 그 좌표를 반환한다(서비스 지역 외 좌표 QA 가능).
- **P0-6** 지역/스팟 또는 임의 좌표를 선택하면 `AppPreferences.setMockLocationEnabled(true)`가 자동 호출된다.
- **P0-7** 선택한 mock 위치의 우선순위는 **`injectPlace`(방문 인증) > `공주 진입/이탈` 시나리오 > QA 선택 위치** 로 유지된다(기존 흐름 불변).
- **P0-8** 패널 상태 카드에 "현재 mock 위치"(지역·스팟 라벨 또는 위경도, mock 비활성 시 그 사실)가 표시된다.
- **P0-9** "테스트 상태 초기화"가 신규 저장 값(임의 좌표 등)까지 함께 초기화한다.

### 중요 (P1)

- **P1-1** 임의 좌표 입력값 유효성 검사(위도 −90~90, 경도 −180~180, 숫자 파싱 실패 처리).
- **P1-2** "현재 mock 위치"가 실시간 반영(선택 즉시 상태 카드 갱신) — 기존 `_reload()` 흐름에 태운다.
- **P1-3** 토글/선택 변경 시 사용자 피드백(스낵바 "홈에서 확인하세요" 수준)으로 재판정이 홈 복귀 시 일어남을 안내.
- **P1-4** 임의 좌표 모드 ↔ 스팟 모드 전환이 명확(둘 중 무엇이 적용 중인지 UI로 구분).

### 선택 (P2)

- **P2-1** 자주 쓰는 좌표 프리셋(예: "서울역", "제주공항") 버튼.
- **P2-2** 지도 탭으로 좌표 선택.
- **P2-3** QA 위치 설정 값의 앱 재시작 후 유지 여부를 패널에서 확인(현재 `AppPreferences` 저장이라 유지되나, `mockLocationEnabled`는 초기화 대상).

## 4. 선택한 접근 방식

### 4-1. 토글/위치 변경 즉시 반영 (P0-1 ~ P0-3)

**방식 B 채택 — "QA 변경 → 캐시 무효화 + dirty 신호 → 홈이 복귀 시 사일런트 재판정"**

- QA 패널의 토글/지역/스팟/좌표 변경 핸들러에서 공통으로:
  1. `LocationVerificationResult.sessionCache = null` / `outOfServiceSessionCache = false`
  2. `mockLocationEnabled` 자동 on (위치 선택 시)
  3. "QA 위치 dirty" 신호를 남긴다 (아래 세부안 중 택1은 `/analyze`에서 확정)
     - (a) `LocationVerificationResult`에 `static bool qaLocationDirty` 플래그 추가
     - (b) `TestModeSession`에 `bool locationDirty` + `markLocationDirty()` 추가 (이미 홈이 리스너로 붙기 쉬움 — 단, 홈 대시보드는 현재 `TestModeSession`을 구독하지 않음)
     - (c) 별도 `ValueNotifier<int>` (QA 위치 revision) 를 `MockLocationGate` 인접에 두고 홈이 구독
- 홈 대시보드 `refresh()`(홈 탭 복귀 시 `MainTabScreen._onTabSelected` → `_homeKey.currentState?.refresh()`)에서 dirty 신호가 있으면:
  - 신규 메서드 `_reevaluateLocationForQa()` 호출 → `_runLocationVerification()` 수행 후 `_applyLocationOutcome`로 `_locationResult` / `_isOutOfService`만 반영
  - **`_onLocationVerified` / `_autoConnectFilmRollEntry`는 호출하지 않는다** → 자동 네비게이션 없음 (P0-3)
  - 필요한 경우 날씨/근처 장소만 별도로 갱신(`_fetchWeather`, `_loadNearbyPlaces`) — 자동 진입과 무관
  - 처리 후 dirty 신호 clear

**이유**
- 기존 코드가 이미 "홈 최초 1회 `_ensureLocationVerified`, 이후 `refresh()`는 필름롤만"이라는 계약을 명시적 주석으로 못박고 있음(자동 네비게이션 방지). 이 계약을 깨지 않고 **QA 전용 예외 경로**를 추가하는 것이 부작용이 가장 작다.
- `_applyLocationOutcome`가 이미 `LocationVerified` / `LocationOutOfService` / 실패를 분기해 `_locationResult` / `_isOutOfService`를 세팅하므로, 자동 진입 없는 재판정에 그대로 재사용 가능.
- `공주 진입`·`테스트 상태 초기화`가 이미 세션 캐시를 직접 비우는 선례가 있어, 토글 핸들러도 같은 패턴으로 맞추면 일관적.

**대안 (기각)**
- **방식 A — QA 패널이 직접 `LocationVerificationRunner.run()` 실행 후 캐시 재적재**: 홈이 `cached != null` 분기로 들어가며 `_onLocationVerified` → `_autoConnectFilmRollEntry`가 실행돼 QA 중 원치 않는 코스 선택/필름롤 화면 자동 이동 발생. P0-3 위반.
- **방식 C — 홈 `refresh()`가 항상 위치 재판정**: 단순 탭 전환마다 Kakao/백엔드 재호출, 그리고 캐시 히트 시 자동 네비게이션 재발. 기존 주석이 명시적으로 금지한 동작.
- **방식 D — 홈을 `TestModeSession` 구독시켜 실시간 rebuild**: 홈이 QA 세션에 상시 결합되고, 리스너에서 async 위치 판정을 트리거하면 생명주기·중복 실행 관리 부담. dirty + 복귀 시 1회 재판정이 더 단순.

### 4-2. 위치 선택 UI + 임의 좌표 (P0-4 ~ P0-8)

**방식 채택 — `_buildToolsCard` 안에 "mock 위치" 서브섹션 추가 + `AppPreferences` 키 확장**

- `AppPreferences`에 추가:
  - `mock_custom_latitude` / `mock_custom_longitude` (double, nullable)
  - `mock_location_mode` (`'spot'` | `'custom'`) — 임의 좌표 모드 ↔ 스팟 모드 구분 (P1-4). 또는 두 좌표가 모두 non-null이면 custom으로 간주하는 방식(키 1개 절약)도 `/analyze`에서 비교.
- `MockLocationGate.currentMockPosition` 우선순위 갱신:
  1. `session.isInjecting` → 주입 좌표 (불변)
  2. `session.gongjuEntered || session.gongjuExited` → 공주 대표 좌표 (불변)
  3. **mock 모드가 custom** → 저장된 임의 위경도
  4. 그 외 → 기존 지역/스팟 좌표
  - 주석의 "우선순위" 블록을 위 4단계로 최신화 (이슈 "우선순위 동작·주석 점검").
- QA 패널 UI:
  - 지역 `DropdownButton<RegionCode>` (라벨: `RegionCodeX.displayName`)
  - 스팟 `DropdownButton<int>` (라벨: `mockLocationSpots[region][i].label`), 지역 변경 시 인덱스 0으로 리셋 + clamp
  - 임의 좌표: 위도/경도 `TextField` 2개 + "적용" 버튼 (또는 onChanged 디바운스) → 유효성 검사(P1-1)
  - 모드 토글(스팟/임의) — `SegmentedButton` 또는 라디오
  - 어느 선택이든 변경 시: 저장 → `setMockLocationEnabled(true)` → 4-1의 캐시 무효화 + dirty 신호 → `_reload()`로 상태 카드 갱신 → 스낵바(P1-3)
- 상태 카드(`_buildProgressCard` 또는 신규 `_buildMockLocationStatus`)에 "현재 mock 위치" 행:
  - mock 비활성: "mock 위치 꺼짐(실제 GPS)"
  - 스팟 모드: "공주 · 공산성 금서루"
  - 임의 모드: "임의 좌표 36.4657, 127.1238"
  - `공주 진입` 세션 활성 시: "공주 진입 시나리오 적용 중(위치 선택 무시)" 로 우선순위 안내

**이유**
- setter(`setMockRegionCodeName` / `setMockSpotIndex`)와 게이트 읽기 로직이 이미 존재 → UI만 연결하면 최소 변경으로 P0-4 달성.
- `test_mode_panel_screen.dart`가 이미 `_card()` / `ChaerokTypography` / `Dropdown` 없이도 일관된 컴포넌트 패턴을 갖고 있어, 같은 카드 스타일에 얹으면 디자인 일관성 유지.

**대안 (기각)**
- **별도 "QA 위치 설정" 화면 신규 추가**: 화면 하나 늘고 네비게이션 부담. 이슈는 "패널에 노출"을 요구.
- **`mockLocationSpots`에 임의 좌표를 5번째 항목으로 추가**: 좌표 데이터가 코스 스팟 대조 대상이라 성격이 다름(주석의 ⚠️ 확인 필요). 별도 저장 키가 명확.

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 즉시 반영 트리거 | 캐시 무효화 + dirty 신호 → 홈 복귀 시 1회 사일런트 재판정 | 기존 "자동 네비게이션 금지" 계약 유지, 부작용 최소 |
| 재판정 시 자동 진입 | 실행 안 함 (`_applyLocationOutcome`만) | P0-3, 기존 주석의 명시적 요구 |
| 위치 선택 UI 위치 | `TestModePanelScreen` QA 도구 카드 내 서브섹션 | 이슈 요구 "패널에 노출", 신규 화면 없음 |
| 임의 좌표 저장 | `AppPreferences` 신규 키(lat/lng + mode) | 게이트가 이미 prefs 기반, 코스 스팟 데이터와 분리 |
| mock 자동 활성화 | 지역/스팟/좌표 선택 시 `setMockLocationEnabled(true)` | 사용자 결정 — QA 동선 단순화 |
| mock 위치 우선순위 | inject > 공주 시나리오 > custom 좌표 > 지역/스팟 | P0-7, 기존 흐름 불변 + 주석 최신화 |
| 상태관리 | 기존 `ChangeNotifier` + static 캐시 유지 | 프로젝트 컨벤션 100% 준수, 라이브러리 미도입 |
| "테스트 상태 초기화" 범위 | 신규 키(custom 좌표/mode)까지 초기화 | P0-9, 기존 `_onReset` 패턴 확장 |

## 6. 고려사항 및 위험요소

### 기술적 위험

| 위험 | 영향 | 대응 |
|------|------|------|
| QA 재판정 경로가 `_autoConnectFilmRollEntry`를 우회하면서 홈 상태 불일치(예: 진행중 필름롤 카드 stale) | 중 | 재판정 후 기존 `refresh()`(필름롤 재조회)와 `_loadNearbyPlaces`를 순서대로 태워 정합성 유지. `_isAutoConnectingFilmRoll` 플래그는 건드리지 않음 |
| `MainTabScreen` 외 경로(포그라운드 복귀 `didChangeAppLifecycleState`)로 홈에 돌아올 때 dirty 미소비 | 중 | dirty 소비를 `refresh()` 진입부에 배치해 탭 전환·라이프사이클 양쪽에서 동작하게 함 |
| 임의 좌표가 서비스 지역 외일 때 `LocationVerificationRunner`의 `kDebugMode` fallback(`공주시`로 대체)이 걸려 "충남 외 지역 홈"이 안 뜸 | 중 | 러너의 `useFallbackRegion` 조건(`kDebugMode && isOutOfServiceArea && !forceOutOfServiceArea`) 확인. 순수 "서비스 지역 외 홈" 확인은 기존 `충남 외 지역 홈 강제` 토글과 병행하도록 UI에서 안내(P1-3). 러너 로직 변경은 범위 외 — `/analyze`에서 영향 재확인 |
| 지역 변경 시 스팟 인덱스 out-of-range | 저 | 드롭다운 rebuild 시 `clamp(0, spots.length-1)` + 지역 변경 핸들러에서 인덱스 0 리셋 (게이트에도 이미 clamp 존재) |
| `TextField` 입력 중 `setState`/`_reload` 남발로 포커스 튐 | 저 | onChanged 즉시 저장 대신 "적용" 버튼 또는 `onEditingComplete`/`onSubmitted` 사용 |
| release(테스터) 빌드에서 임의 좌표 QA가 의도치 않게 노출 | 저 | 기존 진입 게이트(`AppFlavor.isTestMode || kDebugMode || isTester`) 그대로. `MockLocationGate.isAllowed()`가 custom 좌표에도 동일 적용되는지 `/analyze`에서 확인 |
| 위젯 테스트 회귀 | 중 | `home_dashboard_screen.dart`의 `@visibleForTesting debugRunLocationVerification` 훅이 신규 QA 재판정 경로에도 적용되도록 설계. 기존 테스트 영향 목록은 `/analyze` 산출물에 정리 |

### 비즈니스 / 운영 위험

| 위험 | 대응 |
|------|------|
| QA 전용 코드가 늘어 유지보수 부담 | Test Mode 진입 게이트 밖에서는 어떤 값도 세팅되지 않음(기존 보장). 신규 prefs 키도 동일 게이트 뒤에서만 쓰기 |
| 테스터에게 "선택했는데 홈이 안 바뀐다"는 혼선 재발 | 상태 카드 "현재 mock 위치" + 스낵바 안내 + 우선순위(공주 진입 시 무시) 문구로 상시 노출 |

### 성능

- 홈 복귀당 재판정은 dirty 신호가 있을 때만 → 일반 탭 전환 비용 변화 없음.
- 재판정 1회는 Kakao 역지오코딩 + `RegionsApi.resolveRegion` + `PlacesApi.getExternalPlaces` — 기존 최초 진입과 동일 비용, QA 상황에서만 발생.

## 7. 성공 기준

- [ ] **S1** QA 패널에서 "충남 외 지역 홈 강제"를 켜고 홈 탭으로 돌아가면 `OutOfServiceHomeView`가 뜬다. 다시 끄고 홈으로 가면 정상 홈으로 복귀한다. (앱 재실행·초기화 불필요)
- [ ] **S2** QA 재판정 시 코스 선택/필름롤 화면으로 자동 이동하지 않는다.
- [ ] **S3** 지역=부여, 스팟=궁남지 선택 후 홈 복귀 시 헤더 지역명·"가까운 채록 장소"가 부여 기준으로 갱신된다.
- [ ] **S4** 임의 위경도(예: 서울역 37.5547, 126.9707) 입력 후, mock 위치가 그 좌표를 반환하고 홈이 재판정된다.
- [ ] **S5** 지역/스팟/좌표를 고르면 별도 조작 없이 mock 위치가 활성화된다(`isMockLocationEnabled() == true`).
- [ ] **S6** 패널 상태 카드에 현재 적용 중인 mock 위치(지역·스팟 라벨 또는 좌표, 또는 "꺼짐")가 정확히 표시된다.
- [ ] **S7** `공주 진입` 시나리오 실행 중에는 QA 선택 위치가 무시되고(주입/공주 우선), 상태 카드가 그 사실을 안내한다.
- [ ] **S8** "테스트 상태 초기화" 후 지역/스팟/임의 좌표/모드/`mockLocationEnabled`가 모두 기본값으로 돌아간다.
- [ ] **S9** 임의 좌표에 범위를 벗어난 값을 넣으면 저장되지 않고 안내가 뜬다.
- [ ] **S10** 기존 위젯 테스트(홈 대시보드 위치 인증 관련)가 통과하거나, 변경분에 맞춰 갱신된다.

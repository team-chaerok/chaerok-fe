# 🎯 홈 대시보드 복귀 시 새로고침 훅 추가 — 전략 문서

- **이슈**: [#92 코스 선택·탭 전환 후 홈으로 복귀 시 홈 대시보드가 새로고침되지 않음](https://github.com/team-chaerok/chaerok-fe/issues/92) (`❗[버그][홈]`)
- **브랜치**: `20260905_#92_코스_선택_탭_전환_후_홈으로_복귀_시_홈_대시보드가_새로고침되지_않음`
- **프로젝트 타입**: Flutter (`chaerok`) · Clean Architecture(`core`/`data`/`domain`/`features`) · 상태 관리: 순수 `StatefulWidget` + `setState`
- **작성일**: 2026-09-08
- **모드**: Plan (전략 수립 — 코드 미수정)

## 1. 요약

`MainTabScreen`이 `IndexedStack`으로 홈/채록길 탭을 상시 유지하기 때문에, 홈 탭은 최초 `initState` 이후 다시 빌드되지 않는다. 그 결과 (a) 홈에서 push한 화면(코스 선택·필름롤 상세·카메라 등)에서 pop해 돌아오거나, (b) 다른 탭에 갔다가 홈 탭으로 재진입하거나, (c) 앱이 백그라운드→포그라운드로 복귀할 때 "진행중 필름롤 / 진행률 / 가까운 채록 장소"가 이전 상태로 고정된다. 이미 존재하는 `ExploreScreenState.reevaluate()` 대칭 패턴(`GlobalKey` + public 메서드 + `WidgetsBindingObserver`)을 홈에도 그대로 이식해, **필름롤·주변 장소 데이터만** 재조회하는 `refresh()` 훅을 만들고 `MainTabScreen`이 세 진입점에서 호출한다.

## 2. 배경 및 목적

### 문제 / 필요성

| 항목 | 현재 동작 | 근거 위치 |
|------|-----------|-----------|
| 홈 탭 재빌드 | `IndexedStack`이 4탭(현재 코드상 홈/채록길 2개)을 상시 유지 → 홈은 `initState` 1회만 로드 | `main_tab_screen.dart:189-200` |
| 탭 복귀 갱신 | `_onTabSelected()`는 `index == _exploreTabIndex(1)`일 때만 `_exploreKey.currentState?.reevaluate()` 호출. 홈(`index 0`) 복귀 시 갱신 로직 **없음** | `main_tab_screen.dart:41-46` |
| 홈 데이터 로드 | `initState`에서 `_fetchUserInfo` / `_ensureLocationVerified`(postFrame) / `_loadRecoveredFilmRoll` 각 1회 | `home_dashboard_screen.dart:92-101` |
| 외부 refresh 진입점 | `_HomeDashboardScreenState`는 private, `GlobalKey`도 없어 외부에서 재조회 트리거 불가 | `home_dashboard_screen.dart:60` |
| 참고 대칭 패턴 | `ExploreScreenState`(public) + `with WidgetsBindingObserver` + `reevaluate()` + `MainTabScreen`이 `GlobalKey<ExploreScreenState>`로 호출 | `explore_screen.dart:58-133` |

- 홈의 개별 핸들러(`_onResumeFilmRollTap` `home_dashboard_screen.dart:346`, `_onStartFilmRollTap` `:383`, `_autoConnectFilmRollEntry` `:225`)는 pop 직후 `_loadRecoveredFilmRoll()`를 호출해 **부분적으로만** 자체 복구한다. 그러나 이 경로들을 타지 않는 복귀(탭 전환, 필름함/마이 버튼 pop, `가까운 채록 장소` 카드, 앱 재개)는 전혀 갱신되지 않는다.

### 목표

- route pop / 탭 재진입 / 앱 포그라운드 복귀 시 홈 대시보드가 **진행중 필름롤·진행률·최근 사진·가까운 채록 장소**를 최신 상태로 반영한다.
- `ExploreScreen.reevaluate()`와 **대칭되는** 홈 refresh 훅을 제공해 `MainTabScreen`의 탭 처리 로직을 좌우 대칭으로 만든다.

### 범위

**포함**
- `HomeDashboardScreen`에 외부 호출용 public refresh 메서드 신설 (state 클래스 public 전환 + `GlobalKey`)
- `MainTabScreen`: (1) 홈 탭(`index 0`) 복귀 시, (2) 카메라 액션 종료 시, (3) 홈에서 push하는 화면 pop 복귀 시 refresh 호출
- `HomeDashboardScreen`에 `WidgetsBindingObserver` 추가 → `didChangeAppLifecycleState`(`resumed`)에서 refresh
- 홈 내부에서 이미 `_loadRecoveredFilmRoll()`만 개별 호출하던 핸들러들을 새 refresh 메서드로 통일 (동작 동일, 일관성 확보)

**제외**
- 사용자 정보(`_fetchUserInfo`) 재조회 — 이번 refresh 범위에서 제외 (닉네임 등은 마이 화면에서 수정 후 별도 처리, 이슈 범위 밖)
- 위치 재인증(`_ensureLocationVerified` / `_onLocationVerified` / `_autoConnectFilmRollEntry`) 재실행 — **의도적 제외**. 캐시 히트 시 `_autoConnectFilmRollEntry`가 코스 선택/필름롤 화면으로 **자동 네비게이션**하므로, 단순 탭 전환에서 이를 재실행하면 심각한 오작동이 된다.
- 날씨(`_fetchWeather`) 재조회 — 위치 결과에 종속되며 변동성이 낮아 제외
- `가까운 채록 장소` 카드의 `onTap` 동작 구현 (현재 `() {}`, 별도 이슈)
- `IndexedStack` → `LazyIndexedStack`/`PageView` 등 셸 구조 변경 (과도한 범위)
- 라우팅 아키텍처 전면 개편 (RouteObserver 전역 도입은 대안에서 검토 후 보류)

## 3. 요구사항

### 필수 (P0)

- **P0-1** 다른 탭 → 홈 탭 복귀 시 진행중 필름롤/진행률/가까운 채록 장소가 재조회된다. (이슈 재현 4번)
- **P0-2** 홈 → 코스 선택 → 필름롤 상세 → 뒤로가기 복귀 시 홈이 최신 필름롤 상태를 반영한다. (이슈 재현 1~3번)
- **P0-3** refresh는 위치 재인증/자동 코스 진입 부작용을 발생시키지 않는다.
- **P0-4** 연타·빠른 탭 토글 시 stale 응답이 최신 상태를 덮어쓰지 않는다 (기존 요청 토큰 메커니즘 유지·활용).

### 중요 (P1)

- **P1-1** 앱 백그라운드→포그라운드 복귀 시에도 홈이 갱신된다 (`ExploreScreen`과 대칭).
- **P1-2** 홈 내부 기존 핸들러의 개별 `_loadRecoveredFilmRoll()` 호출이 새 refresh 메서드로 통일되어 코드 대칭성이 확보된다.
- **P1-3** 카메라 액션(`_onCameraTap`) 종료 후 홈도 함께 갱신된다 (현재는 explore만 `reevaluate`).

### 선택 (P2)

- **P2-1** `HomeDashboardScreen`에 테스트용 debug 훅이 있다면 refresh 경로도 위젯 테스트로 검증.
- **P2-2** refresh 진행 중 중복 호출 가드(불필요한 동시 네트워크 요청 억제).

## 4. 선택한 접근 방식

### 방식: **A. `ExploreScreen.reevaluate()` 대칭 이식 (GlobalKey + public `refresh()` + `WidgetsBindingObserver`)**

**핵심 구조 (구현은 `/analyze` → `/implement`에서 확정)**

1. `_HomeDashboardScreenState` → `HomeDashboardScreenState` (public 전환, `explore_screen.dart:55,58` 패턴 그대로)
2. `HomeDashboardScreenState with WidgetsBindingObserver` — `initState`에서 `addObserver(this)`, `dispose`에서 `removeObserver(this)`
3. public `Future<void> refresh()` 신설:
   - `_loadRecoveredFilmRoll()` 재호출 (이 메서드가 내부적으로 `_recoveredFilmRoll` 갱신 → 조건부 `_loadRecentPhotos` / `_loadNearbyPlaces(_locationResult)` 연쇄, `home_dashboard_screen.dart:303-328`)
   - `_locationResult != null`일 때만 주변 장소가 갱신되므로, 위치 미인증 상태에서는 자연스럽게 no-op에 가깝다 (부작용 없음)
   - `initState`의 나머지(`_fetchUserInfo`, `_ensureLocationVerified`)는 **호출하지 않는다**
4. `didChangeAppLifecycleState(state)` — `state == AppLifecycleState.resumed`에서 `unawaited(refresh())` (`explore_screen.dart:107-112` 대칭)
5. `MainTabScreen`:
   - `GlobalKey<HomeDashboardScreenState> _homeKey` 추가, `IndexedStack`의 `HomeDashboardScreen(key: _homeKey, ...)`
   - `_onTabSelected(index)`: `if (index == _homeTabIndex /* 0 */) _homeKey.currentState?.refresh();` 분기 추가 (`_exploreTabIndex` 분기와 대칭)
   - `_onCameraTap()` `finally`: 기존 explore `reevaluate` 옆에 `_homeKey.currentState?.refresh()` 추가
   - 홈에서 push되는 화면 복귀: 홈 내부 핸들러가 이미 `_loadRecoveredFilmRoll()`을 호출하는 지점을 `refresh()` 사용으로 정리 (동작 동등)
6. 요청 경합: `_loadRecoveredFilmRoll` / `_loadRecentPhotos` / `_loadNearbyPlaces`는 이미 `_recentPhotosRequestToken` / `_nearbyPlacesRequestToken` + `mounted` 가드가 있어 (`home_dashboard_screen.dart:86-90,264,335`) refresh 반복 호출에도 안전. 필요 시 refresh 자체에 `_isRefreshing` 가드만 얇게 추가 (P2-2).

### 이유 (근거)

- **코드 스타일 100% 준수**: `ExploreScreen`이 이미 확립한 패턴을 그대로 미러링 → 신규 개념·의존성 0, 리뷰 부담 최소, `MainTabScreen`이 좌우 대칭 구조가 된다.
- **부작용 격리**: refresh를 데이터 재조회(`_loadRecoveredFilmRoll` 계열)로만 한정해, 위치 인증 캐시 히트 시의 자동 네비게이션(`_autoConnectFilmRollEntry`, `home_dashboard_screen.dart:191-227`)을 절대 재트리거하지 않는다.
- **경합 안전성 기확보**: stale 응답 방어용 요청 토큰이 이미 구현돼 있어 추가 복잡도 없이 P0-4 충족.
- **테스트 용이**: `GlobalKey`로 `refresh()`를 직접 호출하는 위젯 테스트가 가능하고, 화면에 이미 `debugRunLocationVerification` 훅 선례가 있다.

### 대안

| 대안 | 내용 | 채택하지 않은 이유 |
|------|------|-------------------|
| **B. 전역 `RouteObserver` + `RouteAware.didPopNext()`** | `MaterialApp.navigatorObservers`에 `RouteObserver<PageRoute>` 등록, 홈 state가 `RouteAware` 구독 → 모든 route pop 복귀 자동 감지 | 코드베이스에 없는 신규 패턴(공통 규칙 §2 "새로운 방식 임의 제안 금지"). `main.dart` 앱 레벨 배선 필요. `IndexedStack` 탭 전환은 route 변화가 아니라 **여전히 별도 훅 필요** → 메커니즘 2개 공존. 이득 대비 표면적 과다. (탭/route/앱재개를 단일 메서드로 처리하는 A가 더 단순) |
| **C. `VisibilityDetector` / `focus_detector` 패키지 도입** | `IndexedStack` 내 홈 위젯 가시성 전환 감지 | 신규 의존성. 코드베이스 스타일 아님. 오버킬 |
| **D. `IndexedStack` → `LazyLoadIndexedStack` / `PageView` + `AutomaticKeepAlive` 조합으로 교체** | 탭 전환 시 홈을 조건부로 재생성 | 셸 구조 변경 = 회귀 위험(채록길 탭 상태 유지·`GlobalKey` 전제 붕괴). 이슈 대비 범위 과다 |
| **E. 홈 내부 핸들러마다 개별 재조회 추가 (현행 방식 확장)** | pop 지점마다 `_loadRecoveredFilmRoll()` 수동 삽입 | 탭 전환·앱 재개를 못 잡음. 진입점 누락이 반복될 구조 → 이슈가 재발 |

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| refresh 트리거 메커니즘 | `GlobalKey<HomeDashboardScreenState>` + public `refresh()` | `ExploreScreenState.reevaluate()`와 동일 패턴 (`explore_screen.dart`) |
| 재조회 범위 | 진행중 필름롤 + 진행률 + 최근 사진 + 가까운 채록 장소 (`_loadRecoveredFilmRoll` 계열만) | 사용자 질의 결과. 위치 재인증 시 자동 코스 진입 부작용 회피 |
| 사용자 정보(`_fetchUserInfo`) | refresh에서 제외 | 이슈 범위 밖, 변동성 낮음 |
| 위치 재인증 / 자동 코스 진입 | refresh에서 제외 (재실행 금지) | `_autoConnectFilmRollEntry`의 강제 네비게이션이 탭 전환에서 발생하면 치명적 |
| 갱신 트리거 경로 | 탭(홈) 복귀 + 홈 내부 route pop 복귀 + 앱 포그라운드 복귀 | 사용자 질의 결과 ("탭 복귀 + 홈 내부 route 복귀" + "포그라운드 복귀 포함") |
| 앱 라이프사이클 | `with WidgetsBindingObserver` + `didChangeAppLifecycleState` | `ExploreScreen`과 대칭 (`explore_screen.dart:59,108`) |
| RouteObserver 전역 도입 | 보류 | 신규 패턴·앱 레벨 배선·탭 전환 미커버, A로 충분 |
| 경합 방어 | 기존 요청 토큰(`_nearbyPlacesRequestToken` / `_recentPhotosRequestToken`) 유지, 필요 시 `_isRefreshing` 가드만 추가 | 이미 구현돼 있음, 추가 복잡도 최소 |
| 메서드 이름 | `refresh()` (잠정) | 홈은 explore처럼 "모드 재평가"가 아니라 데이터 갱신이므로 `reevaluate` 대신 `refresh`. 최종 확정은 `/analyze` |

## 6. 고려사항 및 위험요소

### 기술적 위험

| 위험 | 영향 | 대응 방안 |
|------|------|-----------|
| refresh가 위치 인증 흐름을 재트리거해 탭 전환 중 코스 선택 화면으로 튐 | 치명적 UX 오작동 | refresh 본문에서 `_ensureLocationVerified` / `_onLocationVerified` / `_autoConnectFilmRollEntry` **호출 금지**. `_loadRecoveredFilmRoll` + (조건부) `_loadNearbyPlaces(_locationResult)`만. 코드 리뷰 체크리스트에 명시 |
| 빠른 탭 토글로 refresh가 연속 호출되어 중복 네트워크 요청 | 경미(자원 낭비, stale 위험) | 기존 요청 토큰이 stale 반영 차단. 추가로 `_isRefreshing` 가드(P2-2) |
| state 클래스 public 전환이 다른 참조/테스트에 영향 | 낮음 | `_HomeDashboardScreenState` 외부 참조 없음(현재 private). grep으로 재확인 후 전환 |
| `didChangeAppLifecycleState`가 위치 인증 아직 미완료 시점(`_locationResult == null`)에 호출 | 낮음 | `refresh()`가 `_locationResult` null이면 주변 장소 갱신은 자연 skip, `_loadRecoveredFilmRoll`만 수행 → 안전 |
| `_onCameraTap` 종료 시 explore + home 동시 refresh | 낮음 | 두 화면 독립적, 각자 토큰 가드 보유 |
| IndexedStack 특성상 `didChangeDependencies`/`build`가 탭 전환 시 호출되지 않음 → 훅을 build 계열에 걸면 동작 안 함 | 중간 | 반드시 `MainTabScreen._onTabSelected`의 명시적 호출로 처리 (build 의존 금지) |

### 비즈니스 / 제품 위험

| 위험 | 영향 | 대응 방안 |
|------|------|-----------|
| 매 탭 전환마다 재조회로 데이터 사용량·API 부하 증가 | 낮음~중간 | 재조회 대상이 로컬 리포지토리(`recoverLastActiveFilmRoll`, `filmRollPlaceRepository`, `photoRepository`) 중심이라 서버 호출 비중 낮음. 필요 시 후속 이슈로 "변경 감지 시에만 setState" 최적화 |
| 새로고침 중 화면 깜빡임(로딩 상태 노출) | 낮음 | refresh는 성공 시에만 `setState`, 로딩 스피너로 전체 교체하지 않음(현행 유지). 데이터 없으면 이전 값 유지 |

## 7. 성공 기준

- [ ] 홈 → 채록길 탭 이동 후 필름롤 상태 변경 → 홈 탭 복귀 시 진행중 필름롤 카드/진행률/가까운 채록 장소가 최신값으로 갱신된다 (이슈 재현 4).
- [ ] 홈 → 코스 선택 → 필름롤 상세 → 뒤로가기 복귀 시 홈이 갱신된다 (이슈 재현 1~3).

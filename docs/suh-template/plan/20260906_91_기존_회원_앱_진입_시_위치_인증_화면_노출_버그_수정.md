> 브랜치: `20260906_#91_버그_위치인증_기존_회원_앱_진입_시_위치_인증_화면_노출`

---

## 1. 요약

위치 인증 전체 화면(지도 미리보기 + 안내 + FAQ + CTA)은 **회원가입 직후에만** 노출되어야 하는데,
`HomeDashboardScreen._ensureLocationVerified()`가 세션 캐시(`LocationVerificationResult.sessionCache`)가
비어 있으면 회원 여부와 무관하게 `LocationVerificationScreen`을 push 한다. 세션 캐시는 앱 프로세스
수명 동안만 유지되므로, 로그인 세션이 남아 있는 기존 회원도 앱을 재실행할 때마다 홈 위에 위치 인증
화면(idle 뷰)을 마주하게 된다.

해결 방향은 위치 인증 오케스트레이션(권한 → 좌표 → 행정구역 → 서비스 지역 → 관광지)을 UI 없는
**헤드리스 러너**로 추출하고, 홈 대시보드는 이 러너로 **화면 전환 없이 조용히** 위치를 확인한 뒤
결과만 반영한다. 권한 미허용·위치 실패 등 예외 상황에서만 기존 `LocationVerificationScreen`으로
폴백한다.

---

## 2. 배경 및 목적

### 문제 / 필요성

- **현상**: 로그인 세션이 남아 있는 계정으로 앱 완전 종료 → 재실행 → 스플래시 → 홈 진입 시,
  홈 위에 위치 인증 화면(`_Step.idle`)이 그대로 뜬다. 회원가입을 하지 않았는데도 노출된다.
- **원인**: [lib/features/home/presentation/home_dashboard_screen.dart:104-136](../../../lib/features/home/presentation/home_dashboard_screen.dart) —
  `_ensureLocationVerified()`가 `sessionCache == null && !outOfServiceSessionCache`이면
  무조건 `Navigator.push(LocationVerificationScreen())`.
  `sessionCache`는 `static` 필드라 앱 재실행 시 항상 초기화 → 기존 회원도 매번 push 대상이 된다.
- 스플래시에서 세션이 `authenticated`인 기존 회원은 위치 인증 화면을 거치지 않고
  [splash_screen.dart:90-110](../../../lib/features/splash/screens/splash_screen.dart)에서
  `MainTabScreen`으로 직행하는데, 홈이 이 게이트를 다시 세운다.

### 현재 흐름 정리

| 진입 경로 | 위치 인증 화면 노출 여부 (의도) | 현재 동작 |
|-----------|------------------------------|-----------|
| 회원가입 직후 (`SignupNavigation.toMainViaLocationVerification`) | ✅ 노출되어야 함 | `LocationVerificationScreen` push 후 `pushReplacement(MainTabScreen)`. 인증 완료 시 `sessionCache` 세팅 |
| 기존 회원 앱 재실행 (`Splash → MainTabScreen`) | ❌ 노출되면 안 됨 | 홈이 `sessionCache` 비어 있음을 보고 `LocationVerificationScreen` push ← **버그** |

> 핵심 관찰: 회원가입 경로는 `MainTabScreen` 도달 **이전에** `LocationVerificationScreen`을 거쳐
> `sessionCache`를 채우므로, 홈의 `_ensureLocationVerified()`는 이미 캐시 히트로 조용히 통과한다.
> 즉 `_ensureLocationVerified()` 안의 push가 실제로 발동되는 건 **기존 회원 재실행**(및 회원가입
> 도중 인증 화면을 뒤로가기로 이탈한 경우)뿐이다. → 홈에서 "신규/기존" 구분 플래그를 새로 만들
> 필요가 없다. 홈의 push 로직만 조용한 러너 호출로 바꾸면 된다.

### 목표

- 기존 회원이 앱에 진입하면 위치 인증 화면으로 **전환하지 않고** 백그라운드에서
  권한 확인 → 좌표 획득 → 지역 판별을 수행한다.
  - 권한이 이미 허용된 경우: 화면 전환 없이 결과만 홈에 반영(날씨 / 가까운 채록 장소 / 필름롤 자동 진입).
  - 권한 미허용·위치 실패인 경우에만 안내(기존 위치 인증 화면)로 폴백한다.
  - 서비스 지역 외인 경우 기존처럼 "충남 외 지역 홈"(`OutOfServiceHomeView`)으로 폴백한다.
- 회원가입 완료 직후(`SignupNavigation.toMainViaLocationVerification` 경로)에만 위치 인증 화면을 노출한다.

### 범위

**포함**
- 위치 인증 오케스트레이션의 헤드리스 러너 추출 (`LocationVerificationScreen._run()` 로직 이관).
- `HomeDashboardScreen._ensureLocationVerified()`를 조용한 러너 호출 + 예외 시 폴백 push로 변경.
- `LocationVerificationScreen`이 러너를 소비하도록 리팩터(동작 동일 유지).
- 폴백 push 시 idle 온보딩 뷰를 건너뛰고 바로 확인/에러 스텝으로 진입하는 `autoStart` 경로 추가.
- 관련 테스트 갱신 및 신규 홈 동작 테스트 추가.

**제외**
- 위치 인증 결과의 **영속 캐시(디스크)** 도입 — 세션 캐시 구조는 그대로 둔다(별도 이슈 후보).
- 회원가입 플로우(`signup_screen.dart`, `signup_navigation.dart`) UI/순서 변경.
- "충남 외 지역 홈"(`OutOfServiceHomeView`) 자체 로직 변경.
- 위치 권한 관련 카피/디자인 개편.

## 3. 요구사항

### 필수 (P0)

- 권한이 이미 허용된 기존 회원이 앱을 재실행하면 위치 인증 화면이 **일절 노출되지 않는다**.
- 조용한 확인 성공 시 `_locationResult`가 세팅되고 `_onLocationVerified()`(날씨/근처 장소/필름롤 자동 진입)가 기존과 동일하게 동작한다.
- 조용한 확인이 "서비스 지역 외"로 끝나면 기존처럼 `OutOfServiceHomeView`가 렌더된다(`outOfServiceSessionCache`도 세팅).
- 회원가입 직후 경로에서는 위치 인증 화면이 지금과 똑같이 노출된다(회귀 없음).
- `LocationVerificationResult.sessionCache` / `outOfServiceSessionCache`가 성공/서비스 지역 외 시점에 기존과 동일하게 채워져, `my_screen.dart`·`film_roll_sync_service.dart` 등 소비처가 영향받지 않는다.

### 중요 (P1)

- 권한 미허용(`denied` / `permanentlyDenied`) 또는 좌표/지역/관광지 조회 실패 시,
  idle 온보딩 뷰가 아니라 해당 **에러 스텝**(권한 안내 카드 등)으로 바로 진입하는 `LocationVerificationScreen`으로 폴백한다.
- 권한이 아직 허용되지 않은(`denied`, 영구거부 아님) 기존 회원은 앱 진입 시 **1회** OS 권한 다이얼로그를 띄운다(이미 허용/영구거부면 다이얼로그 없이 상태만 반환됨 — 기존 `requestPermission()` 동작).
- 러너는 mock 위치(`MockLocationProvider` / `MockLocationGate`)·디버그 지역 대체(`kDebugMode` fallback region)·QA 토글(`isDebugOutOfServiceArea`) 동작을 현행 그대로 보존한다.

### 선택 (P2)

- 헤드리스 러너에 대한 단위 테스트 골격 마련(정적 API 의존으로 커버리지 한계 있음 — 위험요소 참조).
- `HomeDashboardScreen`에 `@visibleForTesting` 러너 주입 훅을 추가해 홈 동작을 위젯 테스트로 검증.

## 4. 선택한 접근 방식

**방식**: **헤드리스 러너 추출 (Option A)**

`LocationVerificationScreen._run()`의 오케스트레이션 로직(권한 확인 → `LocationProviderFactory`
→ 좌표 → `KakaoLocalApiService.resolveAdministrativeRegion` → 서비스 지역 판별 → `RegionsApi.resolveRegion`
→ `PlacesApi.getExternalPlaces` → `sessionCache`/`outOfServiceSessionCache` 세팅)을 UI가 없는
재사용 함수로 추출한다.

```
lib/features/location/data/location_verification_runner.dart  (신규)
  class LocationVerificationRunner {
    static Future<LocationVerificationOutcome> run({bool requestPermissionIfNeeded = true});
  }
```

- `LocationVerificationScreen._run()` → 러너 호출 후 결과를 `_Step`에 매핑하는 얇은 래퍼로 축소.
- `HomeDashboardScreen._ensureLocationVerified()` → 캐시 미스 시 러너를 **조용히** 호출하고
  결과만 반영. 실패 시에만 `LocationVerificationScreen(autoStart: true)` 폴백.

**이유**

- 화면과 홈이 **정확히 같은 인증 절차**를 공유해야 결과(`sessionCache`)·부작용(`outOfServiceSessionCache`)·
  엣지 케이스(mock/디버그 대체)가 두 경로에서 어긋나지 않는다.
- 로직이 위젯 `State`에서 분리되어 단위 테스트 가능성이 올라가고, 향후 "스플래시에서 선(先)확인"
  같은 확장도 재사용 가능.
- 이슈가 명시적으로 `LocationVerificationScreen`은 `SignupNavigation`에서만 노출되어야 한다고
  지목 — 홈에서 화면 참조를 걷어내는 방향과 일치.

**대안 및 미채택 사유**

| 대안 | 내용 | 미채택 사유 |
|------|------|-------------|
| B. 화면에 `silent` 모드 플래그 | `LocationVerificationScreen`을 위젯 트리에 안 붙이고 `_run()`만 호출 | 위젯을 로직 컨테이너로 오용. 생명주기/`mounted`/`Navigator` 의존이 남아 홈에서 다루기 취약 |
| C. 홈에 인라인 구현 | 홈이 `LocationPermissionService`·API를 직접 조합 | `_run()`과 절차 로직이 이원화 → 한쪽만 고치는 드리프트 위험. mock/디버그 분기 중복 |
| D. 세션 캐시를 디스크 영속화 | `sessionCache`를 `AppPreferences`에 저장해 재실행에도 유지 | 근본 원인(회원 구분 없이 화면 push)을 안 고침. 캐시 만료·지역 이동 stale 문제 신규 발생. 별도 이슈로 분리 |

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 구현 구조 | 헤드리스 러너 추출 후 화면·홈이 공유 | 절차 일원화, 테스트 가능성, 이슈 의도(홈에서 화면 제거) 부합 |
| 권한 미허용·위치 실패 시 폴백 | 기존 `LocationVerificationScreen`으로 폴백(에러 스텝 자동 진입) | 앱 내 재요청·재시도 경로 유지, 코드 변경 최소, 홈이 빈 상태로 방치되지 않음 |
| 폴백 시 진입 스텝 | `autoStart: true`로 idle 온보딩 뷰 건너뛰고 `_run()` 즉시 실행 | 기존 회원에게 온보딩(FAQ/CTA) 뷰를 다시 보이면 이슈 재현. 재실행으로 전이 오류면 자동 성공 후 pop |
| 권한 미허용(denied) 기존 회원 진입 | 1회 OS 권한 다이얼로그 요청(`requestPermissionIfNeeded: true`) | 권한 획득률 확보. 이미 허용/영구거부면 다이얼로그 미표시(기존 동작) |
| 서비스 지역 외 처리 | 현행 유지 — 러너가 `outOfServiceSessionCache=true`, 홈이 `_isOutOfService=true` | `home_dashboard_out_of_service_test` 등 기존 계약 보존 |
| 신규/기존 회원 구분 플래그 | 추가하지 않음 | 회원가입 경로는 `MainTabScreen` 이전에 `sessionCache`를 채워 이미 캐시 히트로 통과 |
| `LocationVerificationOutcome` 확장 | 실패 사유를 표현하는 variant/enum 추가 | 홈·화면이 폴백 분기와 에러 카드 스텝을 결정하려면 사유가 필요 |
| 세션 캐시 영속화 | 이번 범위 제외 | 원인 해결 아님, 신규 stale 리스크. 후속 이슈 후보 |

### `LocationVerificationOutcome` 확장안 (구현 시 `/analyze`에서 확정)

`lib/features/location/data/location_verification_result.dart`:

```dart
sealed class LocationVerificationOutcome { ... }
class LocationVerified extends LocationVerificationOutcome { final LocationVerificationResult result; }
class LocationOutOfService extends LocationVerificationOutcome {}

// 신규
class LocationVerificationFailed extends LocationVerificationOutcome {
  const LocationVerificationFailed(this.reason, {this.isLocationServiceEnabled = true});
  final LocationVerificationFailureReason reason;
  final bool isLocationServiceEnabled; // locationFailed 카드의 GPS 꺼짐 안내 분기 유지용
}

enum LocationVerificationFailureReason {
  permissionDenied,
  permissionPermanentlyDenied,
  locationUnavailable,
  regionVerificationFailed,
  placesFailed,
}
```

- 화면 `_run()`은 `LocationVerificationFailed.reason` → `_Step` 매핑 함수로 처리.
- 홈은 `LocationVerificationFailed`이면 종류 무관하게 `LocationVerificationScreen(autoStart: true)` 폴백.

## 6. 고려사항 및 위험요소

### 기술적 위험

| 위험 | 영향 | 대응 |
|------|------|------|
| `_run()` 로직 이관 중 mock/디버그 분기 누락 (`MockLocationProvider`, `kDebugMode` fallback region, `MockLocationGate` + `isDebugOutOfServiceArea`) | QA/개발 빌드에서 위치 인증 회귀 | 이관은 로직 재작성이 아닌 **그대로 옮기기**. `_run()` 전/후 diff를 라인 단위로 대조. 상수(`_serviceProvinceName` 등)도 러너로 이동 |
| `KakaoLocalApiService`·`RegionsApi`·`PlacesApi`가 **정적 메서드** — 러너 단위 테스트에서 주입 불가 | 러너 happy-path 자동 커버리지 확보 어려움 (기존 화면 테스트도 `debugInitialOutOfServiceArea`로 우회 중) | (1) 러너는 위젯 State 밖으로 나오는 것만으로 가치. (2) 홈 동작은 `@visibleForTesting` 러너 주입 훅으로 위젯 테스트. (3) 정적 API 추상화는 범위 밖(후속) |
| 폴백 `autoStart` 재실행이 권한/좌표 조회를 한 번 더 수행 (조용한 시도 + 폴백 = 2회) | 진입 시 지연·중복 네트워크 | 사유가 전이성(placesFailed 등)일 때만 실질 재시도. 권한 거부는 즉시 카드 표시로 비용 미미. 필요 시 러너 결과를 화면에 전달해 재실행 생략하는 최적화는 후속 |
| 홈이 러너를 `await`하는 동안(권한 다이얼로그 포함) 사용자가 다른 탭 이동 등 → `mounted` 처리 | 크래시/`setState` after dispose | 기존처럼 모든 `await` 후 `if (!mounted) return;` 가드 유지 |
| 회원가입 중 인증 화면을 뒤로가기로 이탈한 사용자도 이제 홈에서 "조용한 시도" 대상 | 의도된 온보딩 노출을 놓칠 수 있음 | 이슈 취지(가입 직후에만 강제 노출)와 상충하지 않음. 권한 미허용이면 어차피 폴백으로 안내됨. 문서에 명시 |
| `outOfServiceSessionCache` / `sessionCache` write 위치가 화면 → 러너로 이동 | 소비처(`my_screen`, `film_roll_sync_service`, 기존 테스트) 타이밍 변화 | write 시점(성공 직후 / 서비스 지역 외 판정 직후)은 동일하게 유지. 관련 테스트 전량 실행 |

### 비즈니스 위험

| 위험 | 영향 | 대응 |
|------|------|------|
| 조용한 확인 실패 시 폴백 화면이 오히려 기존 회원에게 "또 뜬다"고 느껴질 수 있음 | 사용자 혼란 | 폴백은 권한 미허용·조회 실패 등 **실제 조치가 필요한 경우**로 한정. 정상 권한 사용자(대다수)는 무전환 |
| 앱 재실행마다 Kakao/백엔드 재호출(세션 캐시 미영속) | 트래픽·비용 | 이번 이슈 범위 밖. 영속 캐시는 후속 이슈로 트래킹 |

### 성공 기준

- [ ] 권한 허용 상태의 기존 회원: 앱 완전 종료 → 재실행 → 홈 진입 시 위치 인증 화면이 **뜨지 않고**, 날씨/가까운 채록 장소/필름롤 자동 진입이 정상 동작한다.
- [ ] 권한 미허용 기존 회원: 진입 시 1회 권한 요청 → 거부 시 idle 온보딩 뷰가 아닌 **권한 안내 카드 스텝**으로 폴백된다.
- [ ] 서비스 지역 외: `OutOfServiceHomeView`가 기존과 동일하게 렌더되고 `outOfServiceSessionCache`가 세팅된다.
- [ ] 회원가입 직후 경로: 위치 인증 화면이 지금과 동일하게 노출되고 완료 시 홈이 캐시를 재사용한다.
- [ ] `LocationVerificationScreen` 단독 동작(각 `_Step` 카드, out-of-service pop)에 회귀가 없다.
- [ ] `flutter analyze` 무경고, 관련 테스트 + 신규 홈 동작 테스트 그린.
- [ ] mock/디버그 빌드에서 mock 위치·디버그 지역 대체·QA 토글이 종전대로 동작한다.

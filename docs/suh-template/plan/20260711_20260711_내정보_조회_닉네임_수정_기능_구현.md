## 🎯 내 정보 조회 및 닉네임 수정 기능 구현 전략 문서

### 1. 요약

`UsersApi.getMe()`, `UsersApi.updateNickname()`과 `UserResponse`, `UpdateNicknameRequest` 모델은 이미 구현되어 있으나(`lib/data/remote/users_api.dart`), 이를 사용하는 UI가 전혀 없다. 이번 작업은 홈 화면(`home_screen.dart`) 상단에 내 정보(닉네임/이메일/가입 provider) 카드 섹션을 추가해 조회 기능을 노출하고, 설정 화면(`settings_screen.dart`)에 "프로필 수정" 진입점을 추가해 신설할 `ProfileEditScreen`에서 닉네임을 수정할 수 있게 한다. 상태관리 라이브러리가 없는 프로젝트 구조를 따라 `StatefulWidget` + 직접 API 호출 패턴을 유지하고, 닉네임 변경 후 홈 화면 반영은 "설정 화면에서 돌아올 때 재조회"하는 방식으로 간단히 처리한다.

### 2. 배경 및 목적

**문제/필요성**:
- `UserResponse`/`UpdateNicknameRequest` 모델과 `UsersApi.getMe()`/`updateNickname()` API 호출 로직은 준비되어 있지만 소비하는 화면이 없어 사용할 방법이 없음.
- 홈 화면(`lib/features/home/presentation/home_screen.dart`)은 현재 "로그인 성공" 안내 문구만 있는 `StatelessWidget`으로, 사용자 정보를 표시하지 않음.
- 설정 화면(`lib/features/settings/presentation/settings_screen.dart`)에는 로그아웃/회원탈퇴만 있고 프로필 관리 메뉴가 없음.

**목표**:
- 홈 화면 상단에 내 정보(닉네임, 이메일, 가입 provider) 카드를 추가해 앱 진입 시 자동으로 조회·표시한다.
- 설정 화면에 "프로필 수정" 메뉴를 추가하고, 신설 `ProfileEditScreen`에서 닉네임을 수정할 수 있게 한다.
- 수정 성공/실패에 대한 기본 피드백(스낵바)과 홈 화면 데이터 갱신을 처리한다.

**범위**:
- 포함: `UsersApi.getMe()` 연동 홈 화면 카드 UI, 설정 화면 "프로필 수정" 진입점, `ProfileEditScreen` 신설(닉네임 수정 UI + `UsersApi.updateNickname()` 연동), 기본 유효성 검사(공백/빈 문자열), 로딩·에러·성공 피드백, 홈 화면 데이터 갱신.
- 제외(별도 작업): 닉네임 중복 확인, 프로필 이미지, 이메일/provider 변경, 상태관리 라이브러리 도입, 캐싱·낙관적 업데이트.

### 3. 요구사항

**필수 (P0)**:
- 홈 화면을 `StatefulWidget`으로 전환하고 `initState`에서 `UsersApi.getMe()`를 호출해 닉네임·이메일·provider를 카드 형태로 표시한다.
- 조회 실패 시(네트워크 오류 등) 에러 메시지와 "다시 시도" 액션을 카드 영역에 표시한다.
- 설정 화면에 "프로필 수정" `ListTile`을 추가하고 탭 시 `ProfileEditScreen`으로 이동한다.
- `ProfileEditScreen`은 진입 시 `UsersApi.getMe()`로 현재 닉네임을 불러와 `TextField`에 프리필한다.
- 저장 버튼 탭 시 공백 제거(`trim`) 후 빈 문자열이면 저장을 막고 안내 메시지를 표시, 유효하면 `UsersApi.updateNickname()` 호출.
- 수정 성공 시 스낵바로 성공 메시지를 알리고 이전 화면(설정)으로 돌아간다. 실패 시 에러 스낵바를 띄우고 화면에 머문다.
- 홈 화면은 설정 화면으로의 `push`가 반환될 때(사용자가 설정→프로필 수정을 거쳐 돌아왔을 때) 내 정보를 재조회해 변경된 닉네임을 반영한다.
- API 요청 중에는 저장 버튼을 비활성화해 중복 제출을 막는다.

**중요 (P1)**:
- `settings_screen.dart`의 `_errorMessage()`와 동일한 로직을 홈/프로필 수정 화면에서도 써야 하므로(3곳 중복) `ApiError` 관련 공용 헬퍼(`apiErrorMessage(Object e)`)로 추출해 재사용한다.

**선택 (P2)**:
- 카드/입력 필드에 로딩 스켈레톤 또는 스피너 애니메이션 추가.

### 4. 선택한 접근 방식

**방식**: 홈 화면은 조회 전용 카드, 닉네임 수정은 설정 화면 하위의 별도 `ProfileEditScreen`에서 처리. 화면 간 데이터 동기화는 전역 상태관리 없이 "설정 화면에서 돌아올 때 홈이 재조회"하는 방식으로 처리.

**이유**:
- 프로젝트에 Provider/Riverpod/Bloc 등 상태관리 라이브러리가 없고(`pubspec.yaml` 확인), 기존 코드(`home_screen.dart`, `settings_screen.dart`)도 순수 `Navigator.push` + 로컬 상태 패턴을 따르고 있어 동일한 스타일을 유지하는 것이 가장 적은 변경으로 일관성을 지킨다.
- "재조회" 방식은 `Navigator.push(...)`가 반환하는 `Future`에 `.then()`을 붙이는 것만으로 구현 가능해 별도의 콜백/리스너 설계가 필요 없고, 서버 데이터를 항상 단일 진실 공급원(source of truth)으로 삼아 동기화 버그 여지가 적다.

**대안**:
- `ProfileEditScreen`이 `Navigator.pop(updatedUser)`로 수정된 `UserResponse`를 반환하고, 이를 설정 화면 → 홈 화면까지 두 단계에 걸쳐 전달해 재조회 없이 직접 상태를 갱신하는 방식도 검토했으나, `push`/`pop` 결과값을 두 단계 릴레이해야 해 코드가 복잡해지고 "빠른 MVP" 우선순위와 맞지 않아 채택하지 않음.

### 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|---|---|---|
| 내 정보 표시 위치 | 홈 화면 상단 카드 섹션 | 사용자가 명시적으로 요청("홈화면에 보여지게"), 별도 화면 불필요 |
| 닉네임 수정 진입 경로 | 설정 화면 → "프로필 수정" 버튼 → 신설 `ProfileEditScreen` | 사용자가 명시적으로 선택한 방식 |
| 상태 동기화 | 홈이 설정 화면 `push` 복귀 시 재조회 | 상태관리 라이브러리 없이 기존 스타일 유지, 구현 단순 |
| 유효성 검사 범위 | 공백/빈 문자열만 프론트에서 차단 | 사용자가 "기본 검사만" 선택, 상세 규칙은 백엔드 `ApiError` 메시지에 위임 |
| 에러 메시지 처리 | `apiErrorMessage()` 공용 헬퍼로 추출 | 홈/설정/프로필 수정 3곳에서 동일 로직 재사용 |
| UI 컴포넌트 | 기존 `ChaerokColors`/`ChaerokTypography`/`ChaerokSpacing`/`ChaerokButton` 재사용, 텍스트 입력은 design_system에 전용 컴포넌트가 없어 표준 `TextField`를 테마 스타일로 직접 구성 | 디자인 시스템에 텍스트 입력 컴포넌트가 아직 없음(`chaerok_button.dart`, `social_login_button.dart`만 존재) |

### 6. 고려사항 및 위험요소

**기술적 위험**:
- 텍스트 입력 디자인 시스템 컴포넌트 부재 → 표준 `TextField`를 직접 스타일링해야 하므로 다른 화면과 톤이 미세하게 어긋날 수 있음. 대응: 기존 `ChaerokColors`/`ChaerokTypography` 토큰만 사용해 최소한의 일관성 확보.
- 홈 화면이 "설정 화면 복귀 시" 재조회하는 구조라, 사용자가 설정을 거치지 않고 다른 경로로 닉네임을 바꿀 수 있는 기능이 향후 추가되면 갱신 누락 가능. 대응: 현재 범위(설정 경유만)에서는 문제 없음, 추후 전역 상태 도입 시 재검토.

**비즈니스 위험**:
- 닉네임 중복/금칙어 등 상세 검증 로직이 없어 백엔드 에러 메시지 품질에 UX가 좌우됨. 대응: `ApiError.message`를 그대로 노출(이미 프로젝트 관례).

### 7. 성공 기준
- [ ] 홈 화면 진입 시 닉네임/이메일/provider가 자동으로 조회되어 카드에 표시된다.
- [ ] 조회 실패 시 에러와 재시도 UI가 표시된다.
- [ ] 설정 화면에서 "프로필 수정"을 눌러 닉네임을 변경하면 성공 스낵바가 뜨고 이전 화면으로 돌아간다.
- [ ] 빈 닉네임/공백만 입력 시 API 호출 없이 저장이 막힌다.
- [ ] 닉네임 변경 후 홈 화면으로 돌아오면 변경된 닉네임이 반영되어 있다.
- [ ] 수정 실패(네트워크/서버 에러) 시 에러 스낵바가 뜨고 입력값이 유지된다.

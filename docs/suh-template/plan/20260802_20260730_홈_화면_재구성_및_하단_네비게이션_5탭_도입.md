## 🎯 홈 화면 재구성 및 하단 네비게이션 5탭 도입 전략 문서

### 1. 요약

현재 `HomeScreen`(`lib/features/home/presentation/home_screen.dart`, 449줄)에 위치 인증, 필름 롤 진입/재개, 컬렉션 진입, 디버그용 목업 지역 설정 등 서로 다른 책임이 한 화면에 몰려 있다. 홈/채록길/카메라/필름/마이 5탭 하단 네비게이션을 도입해 화면 책임을 분리한다. 다행히 `lib/ui/home/` 아래에 디자이너가 이미 완성해 둔 하단 네비게이션 위젯(`HomeBottomNavigation`, 중앙 카메라 버튼 `HomeCameraAction`, 대시보드 카드류)이 존재하지만 `main_ui_preview.dart` 전용 샘플 데이터로만 동작하고 실제 앱에는 연결되어 있지 않다. 이번 계획은 **이 프리뷰 위젯을 실제 데이터/컨트롤러에 연결해 재사용**하고, 기존 `film_roll`/`location`/`settings` 기능 모듈의 화면들을 탭 구조 아래로 재배치하는 **MVP 우선** 접근을 취한다.

### 2. 배경 및 목적

**문제/필요성**:
- `HomeScreen`이 사용자 카드 조회, 위치 인증 트리거, 필름 롤 진입/재개, 컬렉션 진입, `kDebugMode` 디버그 도구(목업 지역 설정, DB 뷰어, 위치 디버그 덤프), 설정 진입까지 담당해 화면 흐름 파악이 어렵다.
- 하단 네비게이션이 없어 "현재 상태 확인"과 "탐색/촬영/기록 관리"가 구분되지 않는다.
- 완성된 디자인 자산(`lib/ui/home/*`)이 `main_ui_preview.dart`라는 별도 진입점에 고립되어 실제 사용자에게 도달하지 못하고 있다.

**목표**: 5탭 구조(홈/채록길/카메라/필름/마이)로 네비게이션을 재편하고, 홈을 "상태 요약 + 다음 행동 유도" 대시보드로 재구성한다.

**범위**:
- 포함(P0/P1, 이번 계획): 하단 네비게이션 셸 구현, 프리뷰 위젯의 실데이터 연결, 기존 화면(관광지 조회/코스 추천/필름 롤/설정)의 탭 하위 재배치, 카메라 중앙 버튼의 분기 처리(진행 중 필름 롤 유무), 디버그 도구의 마이 탭 이전.
- 제외(P2, 후속 이슈): 지도 뷰, 검색·카테고리 필터 UI, 코스 변경 세부 플로우 고도화, 마이 탭 촬영/방문 통계, 약관·개인정보 처리방침 화면, 자유 촬영(필름 롤 미연결 촬영) 도메인 신규 모델링.

### 3. 요구사항

**필수 (P0)**
- 하단 네비게이션 셸(홈/채록길/카메라(중앙 돌출)/필름/마이) 구현, `IndexedStack` 기반 탭 상태 보존 (라우터 패키지 없이 기존 Navigator 1.0 컨벤션 유지).
- 홈: 현재/선택 지역, 진행 중 필름 롤 진행률, 다음 방문 장소, 최근 촬영 사진 프리뷰를 보여주는 대시보드로 재구성 (기존 프리뷰 카드 위젯 실데이터 연결).
- 채록길: 지역 선택 + 관광지 목록(기존 `LocationVerificationResult`/`PlacesApi` 연동) + 코스 추천 진입(`CourseSelectionScreen` 연결) 탭 신설.
- 카메라: 중앙 돌출 버튼, 탭 전환 없이 즉시 액션. 진행 중 필름 롤 있으면 `VisitCaptureScreen` 바로 진입, 없으면 "지역 선택하기"(기존 `enter_region_use_case` 플로우 연결) / "자유 촬영하기"(P2, 이번엔 안내용 placeholder만) 분기.
- 필름: `film_roll_collection_screen.dart` + `film_roll_screen.dart`를 이 탭의 루트로 승격, 화면 제목 "필름 컬렉션".
- 마이: 프로필 요약, 기존 `SettingsScreen`(프로필 수정/로그아웃/회원탈퇴) 진입점, `kDebugMode` 전용 디버그 도구(목업 지역 드롭다운, DB 뷰어, 위치 디버그 덤프)를 `HomeScreen`에서 이전.
- 탭 아이콘은 Material `Icons` 근사치로 매핑(홈=home, 채록길=explore/map, 카메라=camera_alt, 필름=photo_library, 마이=person), 기존 아이콘 사용 컨벤션 유지(새 의존성 없음).

**중요 (P1)**
- `SplashScreen`(`lib/features/splash/screens/splash_screen.dart:66-70`)과 로그인 성공 플로우가 기존 `HomeScreen` 대신 새 탭 셸(예: `MainTabScreen`)로 진입하도록 전환.
- 기존 `FilmRollModule.instance`, `TokenStorage`, `AppPreferences` 등 수동 싱글톤 DI 패턴, 콜백 기반 controller(`onStateChanged` + `setState`) 패턴을 그대로 유지 — Provider/Riverpod 등 상태관리 라이브러리 신규 도입 금지(기존 코드 주석의 명시적 컨벤션).

**선택 (P2, 후속 이슈로 분리)**
- 채록길 지도 뷰, 검색·카테고리 필터.
- 마이 탭 촬영/방문 통계, 권한 상태 상세 UI, 약관/개인정보 처리방침 화면.
- 자유 촬영(필름 롤 미연결) 도메인 모델링 및 실제 구현.
- `lib/ui/home` 프리뷰 트랙과 `main_ui_preview.dart`의 정리(삭제 여부)는 이번 계획 완료 후 별도 논의.

### 4. 선택한 접근 방식

**방식**: `lib/ui/home/*`의 완성된 위젯(HomeBottomNavigation, HomeCameraAction, ActiveFilmRollCard, PlaceCategoryMenu, RecommendedPlaceCard 등)을 `lib/features/home` 산하로 승격시키고, 정적 샘플 데이터(`HomePreviewData`) 대신 실제 컨트롤러/repository(`FilmRollModule`, `PlacesApi`, `CoursesApi`, `LocationVerificationResult`)에 연결한다. 라벨 불일치("지도"→"채록길")를 수정하고, 탭 셸은 새 `IndexedStack` 기반 위젯으로 신설한다. 구현 범위는 MVP 우선: 네비게이션 셸 + 기존 화면 이관을 먼저 완성하고, 지도 뷰·검색 필터·통계·약관 화면은 후속 이슈로 분리한다. 설정 화면은 마이 탭에서 진입점만 제공하고 `SettingsScreen`은 별도 화면으로 유지한다.

**대안 및 미채택 이유**:
| 대안 | 미채택 이유 |
|------|-------------|
| 프리뷰 위젯 참고만 하고 완전 새로 작성 | 이미 완성된 디자인 자산을 버리는 것은 낭비. 개발 속도가 느려지고, 팀이 이미 검증한 시각적 디자인과의 일관성이 깨질 위험. |
| 전체 스코프(지도뷰·필터·통계·약관 포함) 한 번에 구현 | 작업 범위가 과도하게 커져 리뷰·QA 난이도 상승, 완료 시점 불투명. 네비게이션 구조 자체의 정합성 검증이 지연됨. |
| 커스텀 브랜드 아이콘(SVG) 신규 도입 | `flutter_svg` 의존성 추가 및 디자이너 리소스 필요, 준비 시간 소요. 네비게이션 구조 자체가 먼저 검증되어야 아이콘 디테일 투자가 의미 있음. |
| SettingsScreen 로직을 마이 탭에 완전 흡수 | 기존 로그아웃/회원탈퇴 플로우 회귀 위험 증가. 진입점만 연결하는 편이 기존 코드 보존과 리뷰 범위 축소에 유리. |

### 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 위젯 재사용 여부 | `lib/ui/home` 위젯 승격 + 실데이터 연결 | 이미 완성된 디자인 자산 활용, 개발 속도 확보 |
| 구현 범위 | MVP 우선 (네비게이션 셸 + 기존 화면 이관) | 검증 가능한 단위로 분할, 리뷰/QA 부담 축소 |
| 아이콘 전략 | Material Icons 근사치 | 기존 컨벤션 유지, 신규 의존성 없음, 빠른 구현 |
| 설정 화면 통합 | 마이 탭에서 진입점만 제공 (SettingsScreen 유지) | 기존 로그아웃/탈퇴 로직 회귀 위험 최소화 |
| 상태관리 | 기존 콜백 기반 controller + setState 패턴 유지 | 프로젝트 명시적 컨벤션("Provider/Riverpod 등 미사용") 준수 |
| 네비게이션 | 라우터 패키지 미도입, `IndexedStack` + 기존 Navigator 1.0 | 현재 라우팅 방식과의 정합성 유지, 마이그레이션 리스크 회피 |
| 카메라 자유 촬영 분기 | P2로 분리, 이번엔 placeholder 안내만 | 필름 롤과 무관한 촬영 도메인이 아직 모델링되지 않음 |

### 6. 고려사항 및 위험요소

**기술적 위험**:
- `SplashScreen`/로그인 성공 콜백 등 `HomeScreen`을 직접 참조하는 모든 진입점을 새 탭 셸로 교체해야 하며, 누락 시 일부 플로우가 구 화면으로 빠질 수 있다 → `/analyze` 단계에서 `HomeScreen` 참조처 전수 검색 필요.
- `kDebugMode` 디버그 카드(목업 지역, DB 뷰어)를 마이 탭으로 옮기는 과정에서 `AppPreferences` 상태 연결이 끊기지 않도록 주의.
- 탭 전환 시 `IndexedStack`으로 상태를 보존하되, 각 탭 내부에서 여전히 `Navigator.push`로 하위 화면(코스 선택, 촬영 등)을 띄우는 하이브리드 구조이므로 뒤로가기 동작(탭 내부 스택 vs 탭 전환)을 명확히 설계해야 한다.
- `lib/ui/home`의 `HomePreviewData` 기반 위젯을 실데이터로 교체할 때 위젯 API(props)가 실제 도메인 엔티티(`FilmRoll`, `FilmRollPlace` 등)와 형태가 다를 수 있어 어댑터/매핑 작업이 필요.

**비즈니스 위험**:
- "자유 촬영하기" 기능을 이번 범위에서 제외하면서 사용자에게 미완성 기능으로 보일 수 있음 → placeholder 문구/추후 제공 안내로 기대치 관리.
- P2로 미룬 기능(지도뷰, 통계, 약관)이 많아 이슈 분할이 필요 — 후속 이슈 생성 시점과 우선순위를 팀과 별도 조율 필요.

### 7. 성공 기준

- [ ] 앱 실행 시 로그인 후 5탭 하단 네비게이션(홈/채록길/카메라/필름/마이)이 표시된다.
- [ ] 카메라 탭은 화면 전환 없이 중앙 버튼으로 동작하며, 진행 중 필름 롤 유무에 따라 올바르게 분기한다.
- [ ] 기존 관광지 조회/코스 추천/필름 롤 관리 기능이 채록길·필름 탭에서 동일하게 동작한다(회귀 없음).
- [ ] `kDebugMode` 디버그 도구가 마이 탭에서 정상 동작한다.
- [ ] 로그아웃/회원탈퇴 등 기존 설정 플로우가 회귀 없이 유지된다.
- [ ] 새로운 상태관리 라이브러리나 라우터 패키지를 도입하지 않고 기존 컨벤션을 준수한다.

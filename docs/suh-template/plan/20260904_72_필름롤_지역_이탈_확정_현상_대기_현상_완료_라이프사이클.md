## 1. 요약

기본 시나리오의 마지막 구간(지역 이탈 → 1시간 뒤 현상 완료)을 앱에 완성한다. 진행 모드에서 **포그라운드 위치가 갱신될 때** 현재 좌표의 행정구역을 필름롤 지역과 비교해, 벗어났으면 "지역을 벗어났어요 — 현상을 시작할까요?" 확인 다이얼로그를 띄운다. 확인 시 이미 정의만 되어 있고 호출부가 0곳인 `FilmRollsApi.exitFilmRoll`을 배선해 호출하고, 응답의 `developAvailable`로 분기한다 — `true`면 로컬 필름롤을 새 상태 `developing`으로 전환하고 `developAvailableAt`까지 카운트다운을 보여주는 **현상 대기 화면**을, `false`면 조건 미충족(EXPIRED) 사유를 안내한다. `developing` 필름롤은 탭/앱 재진입 시, 그리고 `developAvailableAt` 경과 시점에 `FilmRollsApi.getFilmRoll`을 1회 조회해 `completedAt`/`developAvailable`을 확인하고, 완료되면 `completed`로 전환하며 필름롤 컬렉션으로 유도한다. 실제 현상 결과(사진 공개) 조회 화면은 BE API가 없으므로 이번 범위에서 제외하고 후속 이슈로 넘긴다. MVP 우선 — happy path를 먼저 완성하고, 시계 조작·오프라인 중 만료·다중 기기 같은 엣지 케이스는 방어 코드 수준으로만 처리한다.

## 2. 배경 및 목적

### 문제 / 필요성

- 기본 시나리오의 마지막 단계(지역 이탈 후 1시간 뒤 현상 완료)가 앱에 구현돼 있지 않다.
- `FilmRollsApi.exitFilmRoll`(`POST /api/film-rolls/{id}/exit`)이 [lib/data/remote/film_rolls_api.dart:36](../../../lib/data/remote/film_rolls_api.dart)에 **정의만 되어 있고 호출부가 0곳**이다. `FilmRollExitResponse`(`developAvailable`/`developAvailableAt`/`status`/`exitedAt`)도 미사용.
- `FilmRollStatus`([lib/features/film_roll/domain/entity/film_roll_status.dart](../../../lib/features/film_roll/domain/entity/film_roll_status.dart))는 `inProgress`/`completed` 두 개뿐 — 이탈 확정 후 1시간 카운트다운(현상 대기) 상태를 표현할 수 없다.
- 사용자가 지역을 벗어나도 앱은 계속 "진행 중"으로만 보이고, 현상이 언제 끝나는지 알 수 없다. 진행 모드([FilmRollProgressView](../../../lib/features/explore/presentation/widgets/film_roll_progress_view.dart))는 "코스 채우기" 화면일 뿐, 이탈/현상 개념이 없다.
- 현재 지역 판별은 위치 인증 화면에서 **1회** 수행돼 `LocationVerificationResult.sessionCache`에 캐시되고 세션 내내 재사용된다([location_verification_screen.dart:68](../../../lib/features/location/presentation/location_verification_screen.dart), [kakao_local_api_service.dart](../../../lib/features/location/data/kakao_local_api_service.dart)). "지역을 벗어났다"를 감지하려면 **신선한 좌표로 역지오코딩을 다시** 돌려 필름롤 지역과 비교하는 경로가 새로 필요하다.

### 목표

- 진행 모드에서 위치가 갱신될 때 행정구역을 비교해 지역 이탈을 감지하고, 사용자 확인 후 `exitFilmRoll`을 호출한다.
- `FilmRollStatus`에 `developing`을 추가하고 로컬 스키마·매퍼·엔티티·복구/재평가 로직에 반영한다.
- 현상 대기 화면에서 남은 시간(카운트다운), 현상 조건, 완료 예정 시각을 보여준다.
- `developing` 필름롤의 현상 완료를 재진입/만료시각 조회로 감지해 `completed`로 전환하고 컬렉션으로 유도한다.

### 범위

**포함 (P0)**

- `FilmRollStatus.developing` 추가 + drift 컬럼(enum 저장) / 매퍼 / 엔티티 / 마이그레이션(v4 → v5)
- 진행 모드 지역 이탈 감지: 포그라운드 위치 갱신 시 현재 좌표 → Kakao 역지오코딩 → 필름롤 `regionCode`와 비교
- 이탈 확인 다이얼로그 + `exitFilmRoll` 호출 배선(로컬 저장소/유스케이스 경유)
- 응답 분기: `developAvailable=true` → `developing` 전환 + `developAvailableAt` 저장 / `developAvailable=false` → EXPIRED 사유 안내
- 현상 대기 화면: 카운트다운, 현상 조건 안내(재사용), 완료 예정 시각. 진행 모드(`_ExploreMode`)에 `developing` 분기 추가
- 현상 완료 감지: `developing` 상태에서 탭/앱 재진입 시 + `developAvailableAt` 경과 시 `getFilmRoll` 1회 조회 → `completedAt`/`developAvailable` 확인 → `completed` 전환
- `recover_last_active_film_roll_use_case` / `ExploreScreen.reevaluate` / `film_roll_collection_screen` 의 상태 필터에 `developing` 반영

**포함하되 경량 (P1)**

- EXPIRED 처리: 별도 로컬 상태를 새로 만들기보다, `exitFilmRoll` 응답이 `developAvailable=false`면 다이얼로그로 사유만 안내하고 로컬 필름롤은 `completed` 또는 기존 정리 경로로 종료(정확한 종료 처리 방식은 `/analyze`에서 BE `status` 문자열 확인 후 결정). 전용 `FilmRollStatus.expired`는 필요성이 확인되면 추가.
- 현상 완료 후 컬렉션/결과 화면 유도 동선(스낵바 + 이동 vs 자동 전환)

**제외**

- 현상 결과 / 사진 공개 조회 화면 — BE API 미정, 후속 이슈
- 백그라운드 위치 추적(앱 종료 상태 이탈 감지) — 상시 위치 권한/플랫폼 대응 부담, 범위 밖
- 상시 폴링 기반 실시간 완료 감지
- 자유 촬영 흐름, 코스 추천 알고리즘

## 3. 요구사항

### 필수 (P0)

- `FilmRollStatus`에 `developing` 추가, drift 스키마 v5 마이그레이션(기존 행 영향 없음 — enum은 문자열 컬럼, 신규 값만 추가)
- `developAvailableAt`(현상 완료 예정 시각)을 로컬에 보관 — `film_rolls` 테이블에 `DateTimeColumn get developAvailableAt => dateTime().nullable()()` 신설, 매퍼/엔티티/`copyWith` 반영
- 진행 모드에서 현재 좌표가 필름롤 지역 밖으로 판정되면 이탈 확인 다이얼로그 노출(중복 노출 방지 가드 포함)
- 확인 시 서버 필름롤 ID로 `exitFilmRoll` 호출. `serverFilmRollId == null`이면 먼저 동기화 시도 후 재시도, 그래도 없으면 안내 후 보류(로컬 상태 변경 없음)
- 응답 `developAvailable`로 분기: `true` → 로컬 `developing` + `developAvailableAt` 저장 → 현상 대기 화면 / `false` → EXPIRED 사유 다이얼로그
- 현상 대기 화면: 남은 시간 실시간 카운트다운(`Timer.periodic` 1s, dispose 처리), 완료 예정 시각(절대시각), 현상 조건 문구(`_developConditionLabel` 재사용)
- `developing` 상태에서 탭/앱 재진입 시 및 카운트다운 0 도달 시 `getFilmRoll` 1회 조회 → `completedAt != null || developAvailable == false→완료판정` 이면 `completed` 전환
- 완료 전환 시 채록길 탭은 탐색 모드로 복귀(기존 `reevaluate` 흐름 재사용) + 컬렉션 이동 안내

### 중요 (P1)

- EXPIRED 종료 처리 방식 확정 및 사유 문구(3유형 미충족 / 사진 1장+ 부족 구분은 BE `status`/메시지 확인 후)
- 이탈 감지 오탐 방지: 지역 경계 근처 GPS 튐 대응(정확도 필터 재사용, N회 연속 이탈 판정 등 — `/analyze`)
- 위치 미확보/권한 거부 시 이탈 감지 스킵(진행 모드 정상 동작 유지)
- 현상 대기 화면에서 "채록길 탭 벗어나도" 상태 유지(로컬 상태가 source of truth)

### 선택 (P2)

- 전용 `FilmRollStatus.expired` 상태 + 만료 필름롤 별도 표기
- 현상 대기 푸시 알림(완료 시점 로컬 알림)
- 이탈 감지 debounce/쿨다운(거절 후 재노출 간격)

## 4. 선택한 접근 방식

### 방식: "로컬 상태 확장 + 진행 모드 인라인 분기" (별도 화면/라우트 없음)

#69에서 자리잡은 `ExploreScreen` ↔ `FilmRollProgressView` 구조를 그대로 확장한다.

```
ExploreScreen (_ExploreMode 판별 소유)
 ├─ reevaluate(): recoverLastActiveFilmRoll() 결과의 status 로 모드 결정
 │     status == inProgress            → _ExploreMode.progress   (기존)
 │     status == developing            → _ExploreMode.developing (신규)  ← 현상 대기 뷰
 │     null / completed                → _ExploreMode.exploring  (기존)
 │
 ├─ _ExploreMode.progress  → FilmRollProgressView
 │     · 위치 갱신 콜백에서 지역 이탈 판정 → 이탈 다이얼로그 → exitFilmRoll → developing 전환 → onCompleted/onExited 로 reevaluate
 │
 └─ _ExploreMode.developing → FilmRollDevelopingView (신규, widgets/ 아래)
       · developAvailableAt 카운트다운 + 완료 예정 시각 + 현상 조건
       · initState / 카운트다운 0 / 재진입 시 getFilmRoll 1회 → completed 면 onCompleted() → reevaluate → 탐색 모드
```

- **이탈 감지 위치**: `ExploreScreen`이 이미 `_loadCurrentPosition()`으로 `_currentPosition`을 관리하고 `FilmRollProgressView`에 넘긴다. 위치가 갱신되는 지점(초기 로드, `onRequestPosition` 콜백)에서 "현재 좌표 → `KakaoLocalApiService.resolveAdministrativeRegion` → `RegionNormalizer.fromCityCountyName` → 필름롤 `regionCode`와 불일치" 판정을 추가한다. 판정 로직은 순수 함수(도메인)로 분리해 테스트한다.
- **exitFilmRoll 배선**: `FilmRollRepository`에 `markDeveloping({clientFilmRollId, developAvailableAt})` / 종료용 메서드를 추가하고, `ExitFilmRollUseCase`(신규)가 `FilmRollsApi.exitFilmRoll` 호출 + 응답 분기 + 로컬 반영을 담당한다. `FilmRollModule`에 조립. 기존 `EnterRegionUseCase`/`CompleteFilmRollUseCase` 패턴 100% 준수.
- **완료 감지**: `developing` 전용 얇은 컨트롤러 또는 `FilmRollDevelopingView` 내부 `initState`+`Timer`에서 `getFilmRoll` 1회 호출. 상시 폴링 없음. 조회 결과는 `updateServerStatus` 유사 경로로 로컬 반영.

### 이유

- 이슈가 "탐색/진행 모드 재평가 로직에 `developing` 상태 반영"을 명시 — #69 구조의 자연스러운 연장.
- 로컬 DB가 source of truth라는 기존 원칙 유지: 서버 응답(`exitFilmRoll`/`getFilmRoll`)은 로컬 상태 전이의 트리거일 뿐, 화면은 로컬 필름롤을 본다. 탭을 벗어나도 상태가 유지된다.
- 새 라우트/화면을 만들지 않아 `main_tab_screen`·네비게이션 변경이 없다.
- 카운트다운·완료 감지를 뷰 수명주기에 묶으면 "상시 동작"이 필요 없다(사용자가 볼 때만 갱신, 재진입 시 따라잡기).

### 대안

| 대안 | 내용 | 미채택 이유 |
|------|------|-------------|
| A. 현상 대기를 별도 라우트(`DevelopingScreen`)로 분리 | 이탈 확정 시 `Navigator.push` | #69가 "탭 안에서 상태 전환" 원칙 확립. 탭 이탈 시 상태·복귀 처리 복잡 |
| B. 백그라운드 위치로 자동 이탈 감지 | `geolocator` background + geofence | 상시 위치 권한 요구(스토어 심사·UX 부담), 플랫폼별 대응 큼. 이슈도 "진행 모드에서 트리거"로 한정 |
| C. 상시 폴링으로 완료 즉시 반영 | `developing` 동안 60s 간격 `getFilmRoll` | 1시간 대기에 폴링 비용 과다. 재진입+만료시각 조회로 체감 충분 |
| D. 프론트에서 1시간 타이머만으로 완료 처리(서버 조회 없음) | `developAvailableAt` 도달 시 로컬만 `completed` | 서버 현상 실패/지연·`completedAt` 불일치 시 거짓 완료. 서버 확인 1회는 필수 |
| E. `developing`을 안 만들고 `serverStatus` 문자열만으로 표현 | 로컬 enum 불변, `serverStatus`(QUEUED/PROCESSING 등)로 분기 | 재평가·복구·컬렉션 필터가 모두 `FilmRollStatus` 기준. 문자열 분기 산재로 일관성 깨짐 |

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 상태 표현 | `FilmRollStatus.developing` enum 값 추가 | 재평가/복구/컬렉션 필터가 전부 이 enum 기준. 단일 소스 |
| `expired` 상태 | 이번엔 만들지 않음(P2). `developAvailable=false`는 다이얼로그 안내 + 기존 종료 경로 | MVP 우선. 전용 상태 필요성은 BE `status` 확인 후 재판단 |
| 완료 예정 시각 저장 | `film_rolls.developAvailableAt` 컬럼 신설(nullable) | 카운트다운·재진입 조회 타이밍에 필요. `exitedAt`은 당장 불필요하면 보류 |
| 스키마 마이그레이션 | v4 → v5, `addColumn(developAvailableAt)` 만. enum 신규 값은 스키마 변경 아님 | drift 규칙 준수. 기존 행 무영향 |
| 이탈 감지 트리거 | 포그라운드에서 위치가 갱신되는 시점(진행 모드 진입/위치 재조회) | 사용자 결정. 백그라운드 추적·상시 폴링 배제 |
| 역지오코딩 재실행 | 이탈 판정용으로 `KakaoLocalApiService.resolveAdministrativeRegion`을 신선한 좌표로 재호출(sessionCache와 별개) | sessionCache는 1회 캐시라 이동 감지 불가 |
| 지역 비교 기준 | `RegionNormalizer.fromCityCountyName(현재 시군구) != 필름롤.regionCode` → 이탈. 정규화 실패(지원 밖 지역)도 이탈로 간주 | 완전 일치 원칙(부분 일치 금지) 재사용 |
| exitFilmRoll 대상 ID | `serverFilmRollId`(int). null이면 동기화 1회 시도 후 재시도, 실패 시 안내·보류 | API가 서버 PK 요구. 로컬만 있는 필름롤은 이탈 확정 불가 |
| 완료 감지 | `developing`에서 재진입 + `developAvailableAt` 경과 시 `getFilmRoll` 1회 | 사용자 결정. 폴링 없음 |
| 완료 판정 조건 | `completedAt != null` 우선. BE `status`/`developAvailable` 조합은 `/analyze`에서 실제 응답 스펙 확인 후 확정 | 서버 스펙 미확인분은 분석 단계로 이월 |
| 이탈 다이얼로그 중복 방지 | 뷰에 `_exitPromptShown`/거절 플래그. 같은 세션·같은 위치군에서 반복 노출 금지 | GPS 갱신마다 뜨는 것 방지 |
| 상태 관리 | 기존 패턴 — StatefulWidget + setState, `FilmRollController` 재사용, 신규 로직은 UseCase | 프로젝트 스타일 100% 준수 |
| 파일 배치 | `FilmRollDevelopingView` → `lib/features/explore/presentation/widgets/`. 이탈 판정 순수 함수 → `lib/features/film_roll/domain/` | #69 배치 관례 |

### 기술적 위험

| 위험 | 영향 | 대응 |
|------|------|------|

## 7. 성공 기준

- [ ] 진행 모드에서 현재 위치가 필름롤 지역 밖으로 판정되면 이탈 확인 다이얼로그가 뜬다(정상 위치에선 안 뜬다)
- [ ] 다이얼로그 확인 시 `exitFilmRoll`이 호출되고, `developAvailable=true` 응답에서 로컬 필름롤이 `developing`으로 전환된다
- [ ] `developAvailable=false` 응답에서 EXPIRED 사유가 안내되고 필름롤이 진행 상태로 되돌아가지 않는다
- [ ] 채록길 탭이 `developing` 필름롤을 감지해 현상 대기 화면(카운트다운·완료 예정 시각·현상 조건)을 보여준다
- [ ] 카운트다운이 `developAvailableAt` 기준으로 정확히 감소하고, 화면 재진입 후에도 이어진다
- [ ] `developAvailableAt` 경과 후 재진입 시 `getFilmRoll` 1회 조회로 완료가 확인되면 `completed`로 전환된다
- [ ] 완료 전환 시 채록길 탭이 탐색 모드로 복귀하고 컬렉션 이동 안내가 노출된다
- [ ] 앱을 재시작해도 `developing` 필름롤이 복구되어 현상 대기 화면이 유지된다
- [ ] `serverFilmRollId`가 없을 때 이탈 확정이 크래시 없이 "동기화 후 재시도" 안내로 처리된다
- [ ] drift v4 → v5 마이그레이션이 기존 필름롤 데이터 손실 없이 수행된다
- [ ] `flutter analyze` 무경고, 기존 위젯/유닛 테스트 통과 + 이탈 판정 순수 함수·상태 전이 단위 테스트 추가

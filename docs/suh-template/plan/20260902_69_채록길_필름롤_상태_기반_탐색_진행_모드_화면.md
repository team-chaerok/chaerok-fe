## 1. 요약

채록길 탭(`ExploreScreen`)을 **진행중인 필름롤 유무에 따라 두 가지 모드로 전환되는 단일 화면**으로 재구성한다. 필름롤이 없으면 "어디 갈지 고르는" **탐색 모드**(지역/검색/카테고리 필터 + 지도 + 주변 장소 리스트 + `시작하기` CTA), 진행중인 필름롤이 있으면 "지금 필름롤을 채워가는" **진행 모드**(진행률 + 현상 조건 + 진행 상태 필터 + 진행 상태 지도 마커 + 다음 장소 카드 + `방문 인증하기`/`필름 카메라` CTA)를 같은 탭 안에서 보여준다. 지도(kakao_map_sdk)와 진행 모드 UI를 채록길 탭에 인라인으로 새로 들이는 것이 이번 범위의 핵심이며, 기존 `FilmRollScreen`은 상세/심화 화면으로 유지한다. 현상(완료) 조건 진행도는 프론트 계산이 아니라 **방문 현황 조회 API(`VisitsApi.getVisits`)** 응답을 그대로 사용한다.

## 2. 배경 및 목적

### 문제 / 필요성

- 현재 `ExploreScreen`([lib/features/explore/presentation/explore_screen.dart](../../../lib/features/explore/presentation/explore_screen.dart))은 필름롤 진행 여부와 무관하게 "지역 선택 → 관광지 리스트 → 필름롤 시작하기" 단일 화면만 노출한다.
- 이미 필름롤을 진행중인 사용자가 채록길 탭에 들어와도 진행률·다음 장소·인증 상태를 이 탭에서 확인할 수 없다. 진행 정보는 `FilmRollScreen`([lib/features/film_roll/presentation/page/film_roll_screen.dart](../../../lib/features/film_roll/presentation/page/film_roll_screen.dart))에만 있고, 실사용 진입은 카메라 액션(`main_tab_screen._onCameraTap`)의 우회 경로에 의존한다.
- 탐색(고르는 중)과 진행(수행하는 중)은 사용자 심리·화면 목적이 다른데 UI가 동일해 "지금 뭘 해야 하는지"가 불명확하다.
- 디자인 시안(6a/6b)은 지도를 전제로 하는데 현재 채록길 탭에는 지도가 아예 없다.

### 목표

- 채록길 탭 진입 시 **필름롤 상태를 판별**해 탐색/진행 모드를 자동 전환한다.
- 두 모드 모두 **지도 + 하단 시트/리스트 + CTA** 골격을 공유하고, 모드별로 카드 내용·CTA·마커 상태·필터·상단 진행 정보만 바꾼다.
- 진행 모드에서 진행률·현상 조건·인증 가능 여부를 한눈에 보여주고 방문 인증/촬영으로 자연스럽게 유도한다.

### 범위

**포함**

- 필름롤 상태 기반 모드 판별 및 전환 로직
- 탐색 모드: 지역 선택, **장소 검색 입력**, **카테고리 필터 확장**(전체/미기록/자연/문화/카페/음식/유적지), 지도, 주변 장소 리스트 시트, `이 채록길 시작하기` CTA
- 진행 모드: 진행중 필름롤명, 방문 진행률, 현상(완료) 조건 안내, **진행 상태 필터**(전체/미방문/인증 가능/방문 완료/촬영한 장소), 스팟 목록 + 인증 상태, 다음 장소 강조 카드, `방문 인증하기`/`필름 카메라 열기` CTA
- **지도**(kakao_map_sdk) 도입 + 탐색용 마커 / 진행 상태 마커(완료·다음·미방문·인증 가능) 분기
- **저장/북마크**(채록길·장소 북마크, 3순위 CTA) — 로컬 저장
- 현재 위치 기준 인증 가능 여부 판정(거리 임계값)
- 필름롤 완료 시 탐색 모드 복귀 처리

**제외**

- 필름롤 서버 동기화 자체(별도 진행: #64) — 이 화면은 동기화 결과(`serverFilmRollId`)에 의존만 한다
- 자유 촬영(필름롤 없이 촬영) 흐름
- 채록길/코스 추천 알고리즘 변경
- 지도 경로(polyline) 시각화 고도화 — 마커 우선, 경로선은 P2

## 3. 요구사항

### 필수 (P0)

- 채록길 탭 진입 시 진행중 필름롤 조회 → 탐색/진행 모드 판별 (코스 미선택 상태 포함 3분기: 필름롤 없음 / 필름롤 있고 코스 미선택 / 필름롤 있고 코스 선택됨)
- 탐색 모드: 지역 선택 + 카테고리 필터 + 주변 장소 리스트 + `시작하기` CTA (기존 기능 유지·정리)
- 진행 모드: 진행률(방문 N/M) + 스팟 목록 + 인증 상태 + `방문 인증하기` CTA
- 현상(완료) 조건 진행도는 `VisitsApi.getVisits(serverFilmRollId)` 응답(`visitedCategoryCount`/`requiredCategoryCount`/`visitRequirementMet`)으로 표기
- 현재 위치 기준 인증 가능 여부 판정 및 CTA 활성/비활성 반영
- 필름롤 완료 시 탐색 모드로 복귀

### 중요 (P1)

- 지도(kakao_map_sdk) 도입 + 모드별 마커 상태 분기
- 장소 검색 입력
- 카테고리 필터 확장(음식/유적지) 및 실제 필터링 동작
- 진행 상태 필터(미방문/인증 가능/방문 완료/촬영한 장소)
- 다음 장소 강조 카드(6a 스타일, 내용은 진행 정보)
- 진행 모드에서 `필름 카메라 열기` CTA 연결

### 선택 (P2)

- 저장/북마크(채록길·장소)
- 지도 경로선(polyline) 시각화
- 정렬 옵션(가까운 순/추천 순) UI
- 인증 가능 마커의 원형 하이라이트 애니메이션

## 4. 선택한 접근 방식

### 방식: "단일 화면 · 상태 기반 모드 전환" + 모드별 위젯 분리

`ExploreScreen`을 상태 컨테이너로 두고, 내부에서 `_ExploreMode { exploring, inProgress }`를 판별해 `_ExploreModeView` / `_FilmRollProgressModeView` 두 개의 private 위젯을 스위칭한다. 공통 골격(AppBar, 지도 영역, DraggableScrollableSheet 형태의 하단 시트)은 컨테이너가 소유하고, 시트 내용·마커 빌더·CTA만 모드 위젯이 주입한다.

```
ExploreScreen (StatefulWidget, 상태·모드 판별 소유)
 ├─ 진입 시: FilmRollModule.recoverLastActiveFilmRoll()
 ├─ 지도 영역 (공통) ── markerBuilder 는 모드가 주입
 └─ 하단 시트 (공통 컨테이너)
      ├─ exploring    → 지역/검색/카테고리 필터 + 주변 장소 리스트 + [이 채록길 시작하기]
      └─ inProgress   → 진행률/현상조건 헤더 + 진행상태 필터 + 스팟 목록 + 다음 장소 카드
                        + [방문 인증하기] / [필름 카메라 열기]
```

### 이유

- 이슈 요구사항이 "화면을 분리하지 말고 상태만 바꿔라"이므로 라우팅 분기가 아닌 위젯 분기가 자연스럽다.
- 지도·시트 골격을 공유하면 모드 전환 시 레이아웃 점프가 없고, 시안의 6a↔6b 연속성이 유지된다.
- 모드 위젯을 private 클래스로 쪼개면 `ExploreScreen` 비대화를 막고(현재도 302줄) Flutter 가이드의 "큰 Widget → private Widget 분리" 원칙에 맞다.
- 진행 모드 로직(방문 인증/촬영)은 이미 `FilmRollController`·`VisitCaptureScreen`에 있으므로 재사용하고, 탭에서는 얇은 진행 요약 + 진입만 담당한다.

### 대안

| 대안 | 내용 | 미채택 이유 |
|------|------|-------------|
| A. 라우트 분리 (탐색 화면 ↔ 진행 화면 별도 route) | 진입 시 조건부 `Navigator.pushReplacement` | 이슈가 명시적으로 반대. 탭 유지·전환 연속성 깨짐 |
| B. 기존 `FilmRollScreen`을 채록길 탭으로 완전 흡수·삭제 | 진행 모드 UI로 `FilmRollScreen` 대체 | 리팩터 범위 과다(#64 서버 동기화 작업과 충돌 위험). `FilmRollScreen`은 상세/심화로 남기는 게 안전 |
| C. 현상 조건 프론트 계산 | 코스 장소 카테고리를 프론트에서 집계 | 서버가 카테고리 그룹(TOURISM/FOOD/CAFE_DESSERT) 기준으로 판정하므로 프론트 재구현 시 불일치 위험. `VisitsApi.getVisits`가 이미 정답 값을 내려줌 |

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 모드 전환 단위 | 라우트가 아닌 위젯 스위칭 (`ExploreScreen` 내부) | 이슈 요구사항, 전환 연속성 |
| 진행 모드 위치 | 채록길 탭에 인라인 구현, `FilmRollScreen`은 상세로 유지 | 사용자 결정. 리팩터 범위 최소화 |
| 현상 조건 데이터 소스 | `VisitsApi.getVisits(serverFilmRollId)` 응답 사용 (`visitedCategoryCount`/`requiredCategoryCount`/`visitRequirementMet`) | 사용자 결정. 서버 판정과 일치 보장 |
| 진행 모드 진입 전제 | `FilmRoll.serverFilmRollId != null` 이어야 방문 현황 조회 가능. null이면 로컬 진행률만 표시 + 동기화 안내 | 방문 현황 API가 서버 필름롤 ID(int)를 요구 |
| 지도 SDK | 기존 `kakao_map_sdk` 재사용, `CourseMapView` 패턴 참고해 신규 위젯 작성 | 이미 도입·검증됨 |
| 마커 상태 | 모드별 enum 분리. 탐색: `{normal, recommended, categoryX}` / 진행: `{visited, next, unvisited, verifiable}` | 시안 요구. `markerBuilder` 주입 구조 |
| 카테고리 필터 | 전체/미기록/자연/문화/카페 + **음식/유적지** 추가, `PlaceCategoryMenu` 확장 또는 신규 | 사용자 결정. 실제 필터링 동작 포함 |
| 진행 상태 필터 | 전체/미방문/인증 가능/방문 완료/촬영한 장소 | 사용자 결정 |
| 저장/북마크 | 로컬 저장(로컬 DB 테이블 or preferences), 3순위 CTA | 사용자 결정. 서버 연동은 범위 밖 |
| 인증 가능 판정 | `Geolocator.distanceBetween` + 임계값. 기준값은 `VisitCaptureScreen`/위치 인증 로직과 동일 상수 공유 | 판정 불일치 방지 |
| 상태 관리 | 기존 패턴 유지 — `ExploreScreen`은 StatefulWidget+setState, 진행 데이터는 `FilmRollController` 재사용 | 프로젝트 스타일 100% 준수 |
| 필름롤 완료 후 | 완료 → 탭 재빌드 시 자동으로 탐색 모드로 (모드 판별이 `recoverLastActiveFilmRoll` 결과 기반) | 자연스러운 복귀 |

## 6. 고려사항 및 위험요소

### 기술적 위험

| 위험 | 영향 | 대응 |
|------|------|------|
| 방문 현황 API가 `serverFilmRollId`를 요구하는데, #64 동기화 미완/부분 실패로 null일 수 있음 | 진행 모드에서 현상 조건 표기 불가 | serverFilmRollId null이면 로컬 진행률(`FilmRoll.visitedPlaceCount/totalPlaceCount`)만 표시하고 "서버 동기화 대기 중" 안내. API 성공 시 현상 조건 섹션 추가 노출 (graceful degradation) |
| kakao_map_sdk를 탭(IndexedStack)에서 상시 유지 → 메모리/렌더 비용 | 4개 탭이 항상 살아있어 지도가 백그라운드에서도 리소스 점유 | `IndexedStack` 유지 여부 재검토. 탭 비활성 시 지도 dispose 또는 `Visibility`/lazy 초기화. `/analyze`에서 kakao_map_sdk 생명주기 확인 |
| 카테고리 필터 확장 — 외부 장소 응답(`PlaceListResponse.categoryDetail`)과 필터 항목(자연/문화/카페/음식/유적지) 매핑 규칙 불명확 | 필터가 실제로 걸러내지 못함 | `/analyze`에서 `PlacesApi.getExternalPlaces` 응답의 카테고리 값 분포 확인 후 매핑 테이블 정의. `filters_api.dart` 활용 가능 여부 확인 |
| "미기록/미방문" 상태 — 탐색 모드에서 장소별 기록 여부를 어떻게 아는가 | 시안의 "아직 기록하지 않았어요" 배지 구현 불가 | `/analyze`에서 로컬 Photos/FilmRollPlaces 집계 또는 서버 API 존재 여부 확인. 없으면 P2로 강등 |
| 현재 위치 조회 실패/권한 거부 시 거리·인증 가능 판정 불가 | 진행 모드 CTA 항상 비활성 위험 | 위치 없으면 "위치를 확인하는 중"/권한 유도 상태로 분기, 인증 버튼은 안내 문구와 함께 비활성 |
| `ExploreScreen`이 이미 302줄 + 진행 모드까지 → 단일 파일 비대화 | 유지보수성 저하 | 모드별 위젯을 `lib/features/explore/presentation/widgets/`로 파일 분리. 진행 데이터 로딩은 `FilmRollController` 재사용 |
| 저장/북마크 로컬 스키마 신설 | 마이그레이션 필요 | `local_database.dart`에 테이블 추가 시 drift 마이그레이션 규칙 준수. 범위가 크면 P2 유지하고 이번엔 UI 자리만 |
| 모드 전환 타이밍 — 탭에 머무는 중 다른 경로(카메라 액션)로 필름롤 생성/완료 발생 | 채록길 탭이 옛 모드 유지 | 탭 `didChangeDependencies`/`RouteObserver` 또는 탭 재선택 시 모드 재판별. `main_tab_screen`과 연동 |

### 비즈니스 / UX 위험

| 위험 | 대응 |
|------|------|
| 진행중 필름롤이 있으면 사용자가 "다른 채록길 탐색"을 아예 못 하게 됨 | 진행 모드 상단에 "다른 채록길 둘러보기" 보조 진입(모달/토글) 제공 여부를 시안 담당과 확인. 최소한 필름롤 포기/전환 경로는 열어둠 |
| 모드가 자동 전환되어 사용자가 혼란 | 진행 모드 진입 시 필름롤명·진행률을 명확히 노출해 "진행 중" 맥락을 즉시 인지시키기 |
| 지도 도입으로 최초 로딩 체감 저하 | 지도는 지연 로드, 리스트/시트를 먼저 렌더 |

## 7. 성공 기준

- [ ] 진행중 필름롤이 없을 때 채록길 탭이 탐색 모드(지역·검색·카테고리 필터·지도·주변 장소 리스트·`시작하기`)로 표시된다
- [ ] 진행중 필름롤이 있을 때 같은 탭이 진행 모드(필름롤명·진행률·현상 조건·진행 상태 필터·스팟 목록·`방문 인증하기`/`필름 카메라`)로 전환된다
- [ ] 현상(완료) 조건 진행도가 `VisitsApi.getVisits` 응답 값과 일치한다 (프론트 임의 계산 아님)
- [ ] 지도가 모드별 마커(탐색용 / 진행 상태)로 다르게 렌더된다
- [ ] 현재 위치가 장소 인증 임계 거리 안일 때만 `방문 인증하기`가 활성화된다
- [ ] 카테고리 필터(음식/유적지 포함)와 진행 상태 필터가 실제로 리스트를 걸러낸다
- [ ] 채록길/장소를 저장(북마크)하고 다시 진입 시 유지된다
- [ ] 필름롤 완료 후 채록길 탭이 탐색 모드로 복귀한다
- [ ] `serverFilmRollId`가 없어도 진행 모드가 크래시 없이 로컬 진행률 + 동기화 안내로 동작한다
- [ ] `flutter analyze` 무경고, 기존 위젯 테스트 통과

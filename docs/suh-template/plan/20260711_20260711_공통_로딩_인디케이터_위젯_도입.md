# 🎯 공통 로딩 인디케이터 위젯 도입 전략 문서

> 참고: 관련 이슈 `docs/suh-template/issue/20260711_001_위치_권한_요청_및_위치_인증_화면_Mockup_추가.md`와는 별개 작업이며, 현재 컨텍스트에 확정된 이슈 번호가 없어 산출물 파일명은 누적순번(fallback)으로 대체했습니다.

## 1. 요약

`lib/features/splash/screens/splash_screen.dart:86`처럼 화면마다 `CircularProgressIndicator()`를 직접 호출하는 대신, `lib/shared/widgets/` 하위에 프로젝트 전역 공통 로딩 인디케이터 위젯(`ChaerokLoadingIndicator`)을 신설한다. 화면은 공통 위젯만 호출하고, 색상/크기 등 실제 스타일은 위젯 내부 한 곳에서만 관리해 추후 디자인 시안 반영 시 해당 파일 하나만 수정하면 되도록 한다.

## 2. 배경 및 목적

**문제/필요성**: 로딩 UI가 여러 파일에 흩어져 있어, 디자인 시안이 확정되면 사용 중인 모든 화면을 일일이 찾아 수정해야 하는 구조다. `lib/shared/widgets/`에 이미 `chaerok_button.dart`, `social_login_button.dart` 같은 공통 위젯이 있지만 로딩 인디케이터는 아직 공통화되어 있지 않다.

**목표**: 전역에서 재사용 가능한 단일 로딩 인디케이터 위젯을 만들고, 기존 `CircularProgressIndicator()` 직접 호출부를 이 위젯으로 교체한다.

**범위**:
- 포함: 전체 화면 로딩(스플래시 등)에서 사용하는 인디케이터 위젯 자체
- 제외: 버튼 내장 로딩 상태, 다이얼로그/오버레이형 로딩 래퍼, Lottie 등 외부 애니메이션 패키지 연동 (사용자 확인 결과 이번 범위에서 제외)

## 3. 요구사항

**필수 (P0)**:
- `lib/shared/widgets/chaerok_loading_indicator.dart`에 `ChaerokLoadingIndicator` (StatelessWidget) 신설
- 내부적으로 `CircularProgressIndicator` 기반, `ChaerokColors.primary`를 기본 색상으로 사용
- `splash_screen.dart:86`의 `CircularProgressIndicator()` 호출을 `ChaerokLoadingIndicator()`로 교체

**중요 (P1)**:
- `color`, `size`, `strokeWidth` 등 최소한의 커스터마이징 포인트를 named parameter로 노출 (기본값은 디자인 토큰 참조)

**선택 (P2)**:
- 없음 (MVP 범위로 최소화, 사용자 확인 결과 variant 분리는 이번 범위 제외)

## 4. 선택한 접근 방식

**방식**: 단일 `StatelessWidget` 하나로 구현 (Approach A)

기존 `ChaerokButton`, `SocialLoginButton` 패턴과 동일하게, `lib/core/design_system/` 토큰(`ChaerokColors` 등)을 참조하는 단순 `StatelessWidget` 하나만 추가한다. 화면 쪽 레이아웃(Scaffold/Center 등)은 각 화면이 그대로 유지하고, 위젯은 인디케이터 자체만 캡슐화한다.

```dart
class ChaerokLoadingIndicator extends StatelessWidget {
  const ChaerokLoadingIndicator({
    super.key,
    this.color = ChaerokColors.primary,
    this.size,
    this.strokeWidth = 4.0,
  });

  final Color color;
  final double? size;
  final double strokeWidth;

  @override
  Widget build(BuildContext context) {
    final indicator = CircularProgressIndicator(
      color: color,
      strokeWidth: strokeWidth,
    );
    if (size == null) return indicator;
    return SizedBox(width: size, height: size, child: indicator);
  }
}
```

**이유**:
- 이슈에 명시된 "우선 기본 CircularProgressIndicator 기반 스타일 적용" 요구사항과 정확히 일치
- 사용자가 "최소 위젯 하나(MVP)"를 선택, 현재 사용처가 splash 1곳뿐이라 과설계 불필요
- 기존 공통 위젯(`ChaerokButton` 등)과 동일한 네이밍/구조 컨벤션 유지 (일관성)

**대안 (선택하지 않음)**:
- **Approach B: 전체 화면 래퍼 위젯 세트** (`ChaerokFullScreenLoading` 등 Scaffold+Center까지 포함) — 재사용성은 높지만, 현재 사용처가 1곳뿐이고 화면마다 레이아웃 차이가 있을 수 있어 과설계. 사용처가 늘어나 패턴이 반복될 때 리팩토링으로 승격 고려
- **Approach C: variant enum 기반 설계 (small/large, overlay 모드 등 사전 정의)** — 확장성은 좋으나 사용자가 "MVP 우선"을 선택했고, 디자인 시안 미확정 상태에서 variant를 미리 정의하면 시안 확정 후 다시 뜯어고쳐야 할 가능성이 큼

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 위젯 개수 | 단일 위젯 (`ChaerokLoadingIndicator`) | 사용자 확인: MVP 우선, 현재 사용처 1곳 |
| 적용 범위 | 전체 화면 로딩만 | 사용자 확인: 버튼 내장/오버레이 로딩은 이번 범위 제외 |
| 커스터마이징 포인트 | color / size / strokeWidth named parameter | 디자인 시안 반영 시 위젯 내부 기본값만 수정하면 전체 반영 |
| 외부 애니메이션(Lottie 등) 확장 고려 | 고려하지 않음 | 사용자 확인: Material 위젯 범위 내에서만 |
| 파일 위치 | `lib/shared/widgets/chaerok_loading_indicator.dart` | 기존 `chaerok_button.dart` 등과 동일한 디렉토리 컨벤션 |

## 6. 고려사항 및 위험요소

**기술적 위험**:
- 현재 `CircularProgressIndicator()` 직접 사용처가 splash 1곳뿐이라, 위젯 교체 효과가 지금 당장은 크게 체감되지 않을 수 있음 → 향후 로딩 UI가 추가될 화면(로그인/회원가입 API 호출 등)에서 이 공통 위젯을 사용하도록 컨벤션을 문서화(코드 리뷰 시 안내)하는 것을 권장
- `color` 파라미터 기본값을 `ChaerokColors.primary`로 고정 시, 다크 배경 위에서 대비가 부족할 수 있음 → 실제 적용 화면(splash)의 배경색(`ChaerokColors.background`, 밝은 배경)과 대비 확인 필요

**비즈니스 위험**:
- 없음 (내부 리팩토링성 작업, 사용자 노출 UI 동작 변화 없음)

# 🎯 위치 권한 요청 로직 및 위치 인증 Mockup 화면 추가 전략 문서

## 1. 요약

로그인/회원가입 완료 시점에 사용자 위치 권한(Foreground)을 요청하는 로직과, 실제 디자인 확정 전 위치 권한/인증 상태 흐름을 검증할 수 있는 Mockup 화면을 `lib/features/location/`(신규)에 추가한다. 이번 범위는 **권한 요청 로직 + Mockup 화면**까지이며, 실제 위치 좌표를 활용하는 서버 연동(지역 판별 API)과 앱 사용 중 주기적 위치 확인 로직은 후속 작업으로 분리한다.

## 2. 배경 및 목적

**문제/필요성**:
- `pubspec.yaml`에 `geolocator`, `permission_handler` 등 위치 관련 패키지가 없고, `AndroidManifest.xml`/`Info.plist`에도 위치 권한 선언이 없어 위치 권한을 요청할 수단 자체가 없다.
- `lib/features/`에는 `auth`, `home`, `settings`, `splash`만 있고 위치 관련 feature 모듈이 없다.
- 실시간 위치 기반 서비스(장소 추천 등)를 계획 중이나, 실제 디자인이 확정되지 않아 권한/인증 상태 흐름을 확인할 화면이 없다.

**목표**:
- 로그인/회원가입 완료 후 위치 권한(Foreground)을 요청하는 로직을 추가한다.
- 권한 상태(승인/거부/영구거부)에 따른 흐름을 확인할 수 있는 Mockup 화면을 만든다.

**범위**:
- 포함: 패키지 추가, 플랫폼 권한 선언, 권한 요청 서비스/로직, Mockup 화면, 로그인·회원가입 완료 흐름 연동.
- 제외(후속 작업): 좌표 기반 실제 지역/장소 API 연동, 앱 사용 중 주기적 위치 확인(백그라운드 포함) 로직, 실제 디자인 반영.

## 3. 요구사항

**필수 (P0)**
- `pubspec.yaml`에 `geolocator`, `permission_handler` 추가
- `AndroidManifest.xml`(`ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`), `Info.plist`(`NSLocationWhenInUseUsageDescription`) 권한 키 추가
- `lib/features/location/`에 위치 권한 요청 서비스(`data/`) + Mockup 화면(`presentation/`) 작성
- 로그인 성공(`_handleLoginResponse` 기존 토큰 발급 분기) 및 회원가입 성공(`_onSignupTap` 성공 분기) 흐름 이후 위치 권한 요청 로직 연동

**중요 (P1)**
- 권한 거부/영구 거부(`permanentlyDenied`) 상태에 대한 안내 UI(설정으로 이동 유도 등)

**선택 (P2)**
- 실제 좌표 획득 후 화면에 좌표/권한 상태를 표시하는 디버그성 정보 노출 (Mockup 검증용)

## 4. 선택한 접근 방식

**방식**: `permission_handler`로 권한 요청/상태 확인, `geolocator`로 좌표 획득. 위치 로직은 `lib/features/location/data/location_permission_service.dart`(가칭)에 static 클래스로 구현하여 기존 `KakaoAuthService`/`GoogleAuthService` 스타일을 따른다. Mockup 화면은 `lib/features/location/presentation/location_mockup_screen.dart`(가칭)로 만들고, 로그인/회원가입 성공 후 `HomeScreen`으로 이동하기 전에 권한 요청을 실행(화면 이동은 하지 않고 권한 다이얼로그만 트리거하거나, Mockup 화면을 경유하는 것은 별도 확인 필요 — 아래 5번 결정사항 참고).

**이유**: 프로젝트가 Provider/Riverpod 등 상태관리 라이브러리 없이 `StatefulWidget` + `setState`만 사용하는 단순한 구조이므로, 기존 `auth` feature와 동일하게 `data/`(서비스 로직) + `presentation/`(화면) 분리 패턴을 따르는 것이 일관성이 높다. `geolocator`+`permission_handler` 조합은 Flutter 생태계에서 위치 권한/좌표 획득의 사실상 표준 조합이다.

**대안**: `location` 패키지(단일 패키지로 권한+좌표 처리) — 커스터마이징 유연성이 `geolocator`+`permission_handler` 조합보다 낮고, 영구거부 등 세밀한 권한 상태 분기가 어려워 채택하지 않음.

## 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 위치 패키지 | `geolocator` + `permission_handler` | Flutter 표준 조합, 권한 상태 세분화 가능 |
| 권한 범위 | Foreground(`When In Use`)만 | 사용자 확인: Background 불필요, iOS `NSLocationAlwaysAndWhenInUseUsageDescription`/Background Modes 설정 불필요 |
| 이번 범위 | 권한 요청 + Mockup 화면만 | 사용자 확인: resolveRegion API 연동, 주기적 위치 확인은 후속 작업 |
| 지역 판별 API(`resolveRegion`) 연동 | 이번 범위 제외 | `ResolveRegionRequest`/`RegionResponse` 모델은 존재하나 실사용처·API 클래스가 전혀 없어(grep 0건) 별도 설계 필요 — 이번 작업에서 임의로 연동하지 않음 |
| feature 구조 | `lib/features/location/data/` + `lib/features/location/presentation/` | 기존 `auth` feature와 동일한 컨벤션 |
| 권한 요청 연동 지점 | `login_screen.dart`의 `_handleLoginResponse` 토큰 저장 성공 후, `signup_screen.dart`의 `_onSignupTap` 토큰 저장 성공 후 | 이슈에서 요구한 "로그인/회원가입 완료 시점" 그대로 반영 |

## 6. 고려사항 및 위험요소

**기술적 위험**:
- iOS는 `Info.plist`에 사용 목적 문자열(`NSLocationWhenInUseUsageDescription`)이 없으면 앱이 크래시하므로 반드시 추가해야 함 — 대응: 플랫폼 파일 수정을 P0에 포함.
- 권한 거부 후 재요청 시 OS 다이얼로그가 다시 뜨지 않고 무시되는 경우(iOS 특성) — 대응: `permanentlyDenied` 상태를 감지해 설정 이동 안내(P1)로 대응.
- `permission_handler`는 Android `minSdkVersion`/iOS 배포 타겟에 따라 추가 설정이 필요할 수 있음 — 대응: 패키지 추가 후 빌드 검증 필수.

**비즈니스 위험**:
- "주기적 위치 확인"의 주기·트리거 조건이 미정 상태로 이슈에 명시되어 있음 — 대응: 이번 범위에서 완전히 제외하고 별도 이슈/논의로 분리, Mockup 화면에는 확장 여지(추후 백그라운드 로직 삽입 지점)만 남겨둠.
- 실제 디자인 미확정 — 대응: Mockup 화면은 최소한의 상태 표시(권한 상태, 좌표값, 재요청 버튼) 수준으로 단순하게 구성.

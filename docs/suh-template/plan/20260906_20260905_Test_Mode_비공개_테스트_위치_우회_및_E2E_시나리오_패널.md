## 1. 요약

원거리(공주 밖) 테스터가 실제 GPS 이동 없이 채록의 핵심 파이프라인
(공주 진입 → 촬영 → 방문 인증 3유형 → 공주 이탈 → 현상 → 결과/릴스)을
집에서 완주할 수 있도록, **위치 판정과 지역 진입·이탈 조건만** 테스트용으로
강제하는 **Test Mode**를 도입한다. 가짜 카메라·가짜 렌더는 만들지 않고 실제
백엔드 API를 그대로 태운다. production(정식 출시) 빌드에서는 **Android
flavor + compile-time flag 이중 게이트**로 Test Mode 진입 자체를 불가능하게
막고, flavor 빌드 내부에서도 **서버 `isTester` 플래그**를 상위 조건으로 유지한다.
마이 탭에 흩어진 QA 토글("Mock 위치", "충남 외 지역 홈 강제")은 Test Mode
패널로 통합하고 마이 탭에서는 제거한다. FCM 시작/완료 알림 검증은 이번
범위에서 제외(별도 이슈)한다.

## 2. 배경 및 목적

### 문제 / 필요성

- 채록의 E2E 플로우는 실제 위치가 충청남도(공주)여야만 시작·진행된다.
  Play Store 비공개 테스트 단계에서 원거리 테스터는 실제 GPS 이동 없이
  플로우를 한 번도 완주할 수 없다.
- 현재 우회 수단이 파편적이다.
  - `kDebugMode`에서만 서비스 지역 외 좌표를 공주시로 대체하는 폴백
    ([location_verification_screen.dart](../../../lib/features/location/presentation/location_verification_screen.dart) `_debugFallbackProvinceName`).
    → 릴리스(비공개 테스트) 빌드에서 동작하지 않는다.
  - `MockLocationGate` / `MockLocationProvider` 기반 좌표 주입
    ([mock_location_gate.dart](../../../lib/core/location/mock_location_gate.dart),
    [mock_location_provider.dart](../../../lib/core/location/mock_location_provider.dart)).
    → 좌표 주입은 되지만 "진입/이탈" 상태 전환과 유형별 방문 대상 선택을
    한 곳에서 다루지 못한다.
  - 마이 탭의 "Mock 위치 (QA)" / "충남 외 지역 홈 강제" 스위치
    ([my_screen.dart](../../../lib/features/settings/presentation/my_screen.dart)).
    → 개별 토글만 있고 E2E 시나리오를 순서대로 밟게 해주지 않는다.
- 정식 출시 빌드에 테스트 진입점이 노출되면 안 되는데, 지금 경계는
  `kDebugMode` + 서버 `isTester` 뿐이라 QA 전용 묶음 기능을 얹을 근거가 약하다.

### 목표

- 비공개 테스트 빌드에서만, 실제 GPS 이동 없이 E2E 플로우를 순서대로 완주
  가능하게 한다.
- 우회 범위는 **위치 시·도 판정 / 서비스 지역 검증 / 지역 이탈 감지**로 한정한다.
- production 빌드에서는 Test Mode 코드·화면 어디에서도 도달 불가.
- 파편화된 QA 진입점을 Test Mode 패널 하나로 통합한다.

### 범위

**포함**

- Test Mode 게이팅(Android flavor + compile-time flag) 및 production 차단 검증
- Test Mode 패널 화면(공주 진입 / 관광지·음식점·카페 인증 / 공주 이탈 / 초기화)
- 위치 판정·서비스 지역 검증을 Test Mode 진입/이탈로 강제하는 경로 연결
- 진행 모드 지역 이탈 감지를 Test Mode "공주 이탈" 버튼과 연동
- 유형별(TOURISM / FOOD / CAFE_DESSERT) 실제 DB 테스트 장소 지정 + 좌표 대조
- 마이 탭 QA 토글의 Test Mode 패널 통합 및 마이 탭 제거
- production 노출/비노출 회귀 테스트

**제외**

- 가짜 카메라 앱·별도 테스트 플로우
- 백엔드의 테스트용 가짜 렌더·가짜 완료 로직 (실제 파이프라인 그대로 사용)
- 방문 인증의 거리/정확도 게이트 우회 (실제 좌표 주입으로 실제 게이트 통과)
- FCM 시작/완료 알림 검증 및 `firebase_messaging` 도입 (pubspec 의존성 없음 →
  별도 이슈)

## 3. 요구사항

### 필수 (P0)

- P0-1. production 빌드에서 Test Mode 진입점(패널·게이트·우회 코드)이 완전
  비활성 — 코드/화면 어디에서도 도달 불가, 가능하면 tree-shaking으로 제거.
- P0-2. 비공개 테스트 빌드 + 서버 `isTester` 계정에서만 Test Mode 패널 노출.
- P0-3. Test Mode 패널에서 아래 6개 동작을 순서대로 밟을 수 있다.
  1. 공주 진입 (실제 GPS 무관, 공주 진입 상태로 처리 → 기존 로컬 FilmRoll 생성
     → `POST /api/film-rolls` 흐름 그대로)
  2. 관광지 인증 (TOURISM) — 실제 DB 공주 장소 1개 좌표 주입 → 실제 Visit API
  3. 음식점 인증 (FOOD) — 동일
  4. 카페 인증 (CAFE_DESSERT) — 동일
  5. 공주 이탈 (실제 GPS 무관, 공주 이탈 상태로 처리 → 기존 Exit → 현상 대기
     → 렌더 흐름 그대로)
  6. 테스트 상태 초기화 (진입/방문/이탈 강제값 되돌려 처음부터)
- P0-4. 우회 지점은 위치 판정으로만 한정한다.
  - 위치 인증의 시·도 판정 및 서비스 지역 검증
    ([location_verification_screen.dart](../../../lib/features/location/presentation/location_verification_screen.dart),
    [location_verification_result.dart](../../../lib/features/location/data/location_verification_result.dart))
  - 진행 모드의 지역 이탈 감지
    ([film_roll_progress_view.dart](../../../lib/features/explore/presentation/widgets/film_roll_progress_view.dart),
    [explore_screen.dart](../../../lib/features/explore/presentation/explore_screen.dart))
- P0-5. 방문 인증 거리/정확도 게이트는 우회하지 않는다. Test Mode는 실제 장소
  좌표를 좌표로 주입해 `evaluateVisitGate`(100m 거리 + 50m 정확도)를 그대로
  통과시킨다 — 기존 [mock_location_spots.dart](../../../lib/core/location/mock_location_spots.dart) 접근과 동일.
- P0-6. 유형별 테스트 장소는 `CoursesApi.getRecommendedCourses`가 내려준
  코스 `places` 좌표와 `Geolocator.distanceBetween`으로 대조해
  `kVisitVerifiableRadiusMeters`(100m, 권장 60m) 이내임을 확인한다.
- P0-7. 실제 카메라 촬영 / 사진 업로드 / 서버 FilmRoll 연동 / 방문 인증 /
  현상 / 결과 사진 / 릴스는 Test Mode와 무관하게 실제 그대로 동작한다.

### 중요 (P1)

- P1-1. 마이 탭 "Mock 위치" / "충남 외 지역 홈 강제" 토글을 Test Mode 패널로
  통합하고 마이 탭에서 제거. 기존 `AppPreferences` 키는 재사용/정리.
- P1-2. Test Mode 패널이 현재 진행 단계(진입 완료 / 방문 n/3 / 이탈 완료)를
  표시해 테스터가 순서를 잃지 않게 한다.
- P1-3. `MockLocationGate.isAllowed()`의 의미를 "flavor(TEST_MODE) 빌드 +
  (`isTester` 또는 debug/profile)"로 재정의하고 기존 호출부 회귀 없음 확인.

### 선택 (P2)

- P2-1. Test Mode 패널 진입 배너/워터마크(빌드 구분용 시각 표식).
- P2-2. 부여/서산/예산까지 Test Mode 지역 선택 확장 (초기엔 공주 고정).
- P2-3. Test Mode 상태를 앱 재시작에도 유지(SharedPreferences)할지 여부.

## 4. 선택한 접근 방식

### 게이팅: Android flavor + compile-time flag 병행 (사용자 확정)

**방식**

- **Android product flavor** (`prod` / `testers`) + iOS scheme/config 대응.
  `testers` flavor는 `applicationId` suffix(예: `.testers`)로 스토어 트랙을
  물리적으로 분리해, 정식 출시 산출물과 비공개 테스트 산출물이 섞이지 않게 한다.
- **compile-time flag** `const bool.fromEnvironment('CHAEROK_TEST_MODE')`.
  Dart 코드는 이 상수만 분기한다. `testers` flavor 빌드 스크립트/CI에만
  `--dart-define=CHAEROK_TEST_MODE=true`(또는 `--dart-define-from-file`)를 넣는다.
- `prod` flavor 빌드에는 flag가 없으므로 상수는 `false`, Test Mode 관련
  코드 경로는 Dart 컴파일러의 tree-shaking으로 제거된다(P0-1).

**이유**

- flag만으로도 tree-shaking·차단은 되지만, flavor를 함께 두면 스토어 트랙
  자체가 분리돼 "정식 빌드에 테스트 dart-define을 실수로 넣는" 사고까지 막힌다.
- 사용자가 "가장 안전, 이번 이슈 범위를 크게 넘김"을 감수하고 선택.

**대안 (선택 안 함)**

| 대안 | 왜 선택 안 함 |
|---|---|
| dart-define flag 단독 | 가볍지만 스토어 트랙 분리가 없어, 빌드 파이프라인 실수 시 정식 빌드에 flag가 섞일 여지가 남는다. |
| flavor 단독 | flavor만으로 분기하면 Dart 상수 기반 tree-shaking을 못 써서, 조건 분기가 런타임에 남는다. 코드가 산출물에 포함됨. |
| 서버 `isTester` 만으로 계속 | release 산출물에 우회 코드가 항상 포함돼 P0-1 위반. 서버 플래그 하나로 정식 사용자에게 노출될 위험. |

### `isTester` 관계: 유지 + Test Mode가 상위 게이트 (사용자 확정)

- `testers` flavor(=`CHAEROK_TEST_MODE=true`) 빌드에서만 Test Mode 패널·우회
  경로가 존재한다. **그 안에서** `MockLocationGate.isAllowed()`는 여전히
  `isTester`(또는 debug/profile)를 확인한다.
- 즉 mock 좌표 주입·위치 우회가 실제로 켜지려면 **`testers` 빌드 + 테스터
  계정** 두 조건이 모두 필요하다. 이중 안전장치.
- 기존 release 테스터 계정 우회 경로(`MockLocationGate.isAllowed()` →
  `isTester()`)는 그대로 두되, `!kReleaseMode` 분기 자리에 flavor(TEST_MODE)
  조건을 얹는다.

### QA 토글: Test Mode 패널로 통합, 마이 탭에서 제거 (사용자 확정)

- 마이 탭 `_showMockTools` 섹션([my_screen.dart](../../../lib/features/settings/presentation/my_screen.dart)) 삭제.
- "Mock 위치 on/off", "Mock 지역·지점 선택", "충남 외 지역 홈 강제"
  (`AppPreferences.isMockLocationEnabled` / `getMockRegionCodeName` /
  `getMockSpotIndex` / `isDebugOutOfServiceArea`)를 Test Mode 패널의 세부
  컨트롤로 이동. 저장 키는 재사용.

### FCM: 이번 범위 제외 (사용자 확정)

- `pubspec.yaml`에 FCM 의존성 없음. 기대 시나리오의 "알림 확인" 단계는 FCM
  도입 이후로 미루고, 별도 이슈로 트래킹.

## 6. 아키텍처 스케치 (구현 계획은 /analyze 에서 확정)

### 6.1 게이트 상수

```
lib/core/config/app_flavor.dart  (신규)
  class AppFlavor {
    static const bool isTestMode =
        bool.fromEnvironment('CHAEROK_TEST_MODE', defaultValue: false);
  }
```

- 빌드 스크립트: `flutter build appbundle --flavor testers --dart-define=CHAEROK_TEST_MODE=true`
- `android/app/build.gradle.kts` 에 `flavorDimensions` + `productFlavors { prod; testers { applicationIdSuffix = ".testers" } }`
- iOS: `Runner` scheme 복제 또는 xcconfig 분기 (범위 확인 필요)

### 6.2 Test Mode 세션 상태

```
lib/features/test_mode/  (신규 feature 디렉토리)
  domain/test_mode_session.dart
    - bool gongjuEntered
    - Set<VisitCategory> verifiedCategories
    - bool gongjuExited
    - reset()
  presentation/test_mode_panel_screen.dart   (6버튼 + 진행 표시)
  data/test_mode_spots.dart                   (유형별 실제 DB 장소 좌표)
```

- `AppFlavor.isTestMode == false` 이면 이 디렉토리의 화면 진입점은 빌드에서
  제외(조건부 라우트 등록).

### 6.3 우회 연결 지점

| 지점 | 파일 | Test Mode 개입 |
|---|---|---|
| 시·도 판정 / 서비스 지역 검증 | [location_verification_screen.dart](../../../lib/features/location/presentation/location_verification_screen.dart) `_run()` | `AppFlavor.isTestMode && session.gongjuEntered` 이면 실제 좌표/역지오코딩 결과와 무관하게 공주(충청남도/공주시)로 판정, 기존 `_debugFallbackRegion` 로직을 이 조건으로 일반화 |

## 7. 고려사항 및 위험요소

### 기술적 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| iOS flavor/scheme 분리 작업량이 Android보다 큼 (xcconfig, scheme, Info.plist, 서명) | 일정 초과 | `/analyze` 에서 iOS 구성 현황 먼저 확인. 우선 Android flavor + 공통 dart-define으로 P0 달성하고 iOS scheme는 후속으로 분리 가능(플래그가 실제 차단 주체이므로) |
| 코스 `places` 좌표가 `test_mode_spots` 후보와 100m 초과 | 방문 인증 실패 | 병합 전 `Geolocator.distanceBetween` 대조 스크립트/테스트로 검증 (P0-6). 어긋나면 코스 스팟 좌표에 맞춰 조정. 코스 데이터 개편 시 재대조 (mock_location_spots.dart 주석 규약) |
| `MockLocationGate.isAllowed()` 의미 변경이 기존 release 테스터 우회 경로 회귀 | 심사 계정 흐름 깨짐 | 기존 `isTester` 분기 유지한 채 flavor 조건을 AND로만 추가. 기존 QA 흐름 회귀 테스트 |
| 세션 상태가 `LocationVerificationResult.sessionCache` / `outOfServiceSessionCache` 와 충돌 | 진입/이탈 오판 | 초기화 버튼이 모든 관련 캐시를 함께 클리어. 캐시 우선순위 명문화 |
| tree-shaking이 기대만큼 제거 안 됨 (상수 분기 밖에서 참조) | 산출물에 우회 코드 잔존 | `AppFlavor.isTestMode` 를 `if` 최상단 조건으로만 사용, 화면/라우트 등록도 동일 상수로 가드. release AAB 역컴파일/문자열 검색으로 검증 |
| 마이 탭 QA 토글 제거로 기존 디버그 개발 편의 저하 | 개발자 DX | Test Mode 패널을 debug 빌드에서도 접근 가능하게(=`isTestMode || kDebugMode` 진입) 유지 |

### 비즈니스 위험

| 위험 | 대응 |
|---|---|
| 비공개 테스트 빌드가 정식 트랙에 잘못 업로드 | `applicationIdSuffix`(`.testers`)로 packageName이 달라 Play Console에서 정식 앱에 올릴 수 없음 |
| 테스터가 Test Mode로 만든 데이터가 운영 지표 오염 | 테스터 계정은 서버 `isTester`로 식별 가능 → 지표 집계 시 필터 (백엔드 협의 항목) |
| "실제 앱 그대로" 원칙 훼손 (편의상 게이트 우회 유혹) | P0-5 명문화. 방문 거리/정확도 게이트는 좌표 주입으로만 통과 |

## 8. 성공 기준

- [ ] `prod` flavor release AAB에 Test Mode 패널·우회 분기·`test_mode_spots`
      문자열이 포함되지 않는다 (역컴파일/`strings` 검색으로 확인).
- [ ] `prod` 빌드 실행 시 어떤 경로로도 Test Mode 패널에 도달할 수 없다.
- [ ] `testers` flavor + `CHAEROK_TEST_MODE=true` + 서버 `isTester` 계정에서만
      Test Mode 패널이 노출된다. 셋 중 하나라도 빠지면 미노출.
- [ ] 공주 밖 실기기에서 패널의 6버튼을 순서대로 눌러
      진입 → 촬영 → TOURISM/FOOD/CAFE_DESSERT 인증 → 이탈 → 현상 대기 →
      현상 완료 → 결과/릴스까지 완주된다.
- [ ] 방문 인증은 `evaluateVisitGate`를 실제로 통과한다(우회 로그 없음,
      주입 좌표가 코스 스팟 100m 이내).
- [ ] 사진 업로드 / 서버 FilmRoll 연동 / 현상 / 결과 사진 / 릴스가 실제 API로
      정상 동작한다.
- [ ] 마이 탭에서 "Mock 위치" / "충남 외 지역 홈 강제" 항목이 사라지고,
      동일 기능이 Test Mode 패널에서 동작한다.
- [ ] 기존 release 테스터 계정의 Mock 위치 심사 흐름이 회귀 없이 동작한다.
- [ ] "테스트 상태 초기화" 후 처음부터 다시 시작할 수 있다.

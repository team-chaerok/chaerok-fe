## 🎯 위치 인증 성공 → 지역 진입 → 코스 선택 원스텝 연결 전략 문서

- 이슈: [#75 🚀[기능개선][채록길] 위치 인증 성공 시 해당 지역 코스 선택으로 바로 연결](https://github.com/team-chaerok/chaerok-fe/issues/75)
- 작성일: 2026-09-05
- 관련 이슈: #72 (지역 이탈 확정 → 현상 대기 → 현상 완료 라이프사이클, 병합 완료)

### 1. 요약

위치 인증 성공 후 사용자가 코스 선택까지 도달하려면 현재 "인증 팝→홈 복귀→'필름롤 시작하기' 탭→FilmRollScreen 진입→'추천 코스 선택하기' 탭"까지 최소 2번의 수동 탭이 필요하고, Home과 Explore 두 진입점에 `enterRegion` 호출·에러 처리·코스 선택 push 로직이 대부분 그대로 중복되어 있다. 이번 작업은 Home·Explore 두 진입점을 대상으로, 위치 인증(또는 지역 확정) 직후 진행 중 필름롤이 없으면 지역 진입과 코스 선택 화면 push를 자동으로 이어주는 흐름을 도입하고, 그 판단 로직(활성 필름롤 유무·상태 분기)을 공유 유스케이스로 추출해 두 화면의 중복을 제거한다. 이번 범위에는 `FilmRollScreen`(Home 경로)이 "현상 대기(developing)" 상태를 표시하지 못하는 기존 결함 수정도 포함한다. 최우선 가치는 **안정성**이며, 기존 진행중/현상대기 화면의 동작을 깨뜨리지 않는 것을 최소 요건으로 삼는다.

### 2. 배경 및 목적

**문제/필요성**
- 기본 시나리오("충남 지역 → 예산군 코스 선택 화면 → 코스 선택")가 현재 UX에서 한 번에 이어지지 않아 신규 사용자가 다음 행동을 찾지 못한다.
- `HomeDashboardScreen._onStartFilmRollTap`과 `ExploreScreen._onEnterRegionTap`이 `enterRegion` 호출·예외 처리·로그를 사실상 동일하게 복붙하고 있고, 지역 판별도 `LocationVerificationScreen`(RegionsApi.resolveRegion + 세션 캐시)과 `ExploreScreen._fetchPlaces`(RegionsApi.resolveRegion 재호출)로 이원화되어 있다.
- `FilmRollScreen._buildLoaded`는 필름롤 상태를 분기하지 않아, Home 경로로 들어온 "현상 대기" 상태의 필름롤을 열면 진행중 UI가 그대로 뜬다(Explore의 `FilmRollProgressView`/`FilmRollDevelopingView`만 상태 분기를 갖고 있음).

**목표**
- 위치 인증 성공(서비스 지역 확인) 시점에 진행 중 필름롤이 없으면 자동으로 해당 지역 필름롤에 진입하고, 코스 미선택 상태면 코스 선택 화면으로 바로 이어준다.
- 이미 진행 중 필름롤이 있으면 그 상태(진행중/현상대기)에 맞는 화면으로 바로 연결한다.
- Home·Explore 두 진입점이 같은 판단 로직(활성 필름롤 조회 → 상태 분기)을 공유하도록 정리한다.

**범위**
- 포함: `HomeDashboardScreen`, `ExploreScreen`, 관련 도메인 유스케이스(`EnterRegionUseCase`, `RecoverLastActiveFilmRollUseCase` 활용), `FilmRollScreen`의 현상대기 상태 표시 보완.
- 제외(이번 이슈 범위 아님): `SignupNavigation.toMainViaLocationVerification` 경로(인증 결과를 현재 무시하는 부분)는 이번 변경에서 건드리지 않는다. 지역 판별 로직 자체(RegionsApi 이원화 통합)의 전면 리팩토링도 이번 범위 밖으로 하고, 필요한 최소 지점만 정리한다.

### 3. 요구사항

**필수 (P0)**
- 위치 인증 성공 + 진행 중 필름롤 없음 → 자동 지역 진입(`enterRegion`) 후 코스 미선택 상태면 코스 선택 화면으로 자동 연결 (Home 경로).
- Explore 탭에서도 동일한 판단 로직(공유 유스케이스)을 사용해 "지역 선택 → 진입" 흐름에서 코스 선택까지 자동 연결.
- 이미 진행 중(코스 선택 완료) 필름롤이 있으면 기존처럼 진행 화면으로 직행(현행 동작 유지, 회귀 금지).
- 현상 대기(developing) 상태면 Home·Explore 어느 경로든 현상 대기 화면으로 연결되도록 `FilmRollScreen` 보완.
- 기존 `EnterRegionUseCase`/`RecoverLastActiveFilmRollUseCase` 등 이미 테스트된 유스케이스의 동작·시그니처는 가능한 한 그대로 재사용(안정성 우선).

**중요 (P1)**
- Home/Explore의 `enterRegion` 호출·예외 처리(스낵바 문구 등) 중복 제거.
- 신규 오케스트레이션 로직에 대한 유닛 테스트 작성(기존 `enter_region_use_case_test.dart` 등과 같은 레벨).

**선택 (P2)**
- `RegionsApi.resolveRegion` 이원화 호출(LocationVerification vs Explore) 통합.
- `_serviceProvinceName = '충청남도'` 등 중복 상수 정리.

### 4. 선택한 접근 방식

**방식**: 도메인 레이어에 활성 필름롤 상태를 판정하는 공유 유스케이스(가칭 `ResolveFilmRollEntryUseCase`)를 신설하고, 각 화면(Home/Explore)은 이 유스케이스가 반환하는 판정 결과(예: `needsCourseSelection` / `resumeInProgress` / `showDeveloping`)에 따라 **기존 네비게이션 패턴 그대로** 화면을 이어붙인다. 코스 선택 완료 콜백(`selectCourse` 호출)도 이 판정 로직과 함께 한 곳에서 정의해 Home·Explore가 공유한다.

- 판정 로직: `RecoverLastActiveFilmRollUseCase`로 활성 필름롤 조회 → 없음이면 `EnterRegionUseCase` 호출 후 `needsCourseSelection` 반환 → 있고 `selectedCourseId`가 비어있으면 동일하게 `needsCourseSelection` → 있고 `status == developing`이면 `showDeveloping` → 그 외(진행중+코스선택완료)면 `resumeInProgress`.
- Home: 위치 인증 성공 콜백에서 이 유스케이스를 호출 → `needsCourseSelection`이면 `CourseSelectionScreen(regionId)`를 바로 push(코스 선택 결과를 받아 `selectCourse` 호출 후 `FilmRollScreen` push) → `showDeveloping`이면 `FilmRollScreen`에 상태를 전달해 `FilmRollDevelopingView`를 렌더 → `resumeInProgress`면 기존처럼 `FilmRollScreen` push.
- Explore: `reevaluate()`가 이미 상태별로 모드를 분기하는 구조이므로, 지역 선택 후 진입 시점에 동일 유스케이스를 호출해 `needsCourseSelection`이면 코스 선택을 자동으로 이어 붙이도록 보완(기존 `exploring/progress/developing` 모드 스위치는 유지).

**이유**
- "우선순위 = 안정성" 결정에 부합: `EnterRegionUseCase`/`RecoverLastActiveFilmRollUseCase`는 이미 존재하고 테스트되어 있으므로 이를 그대로 재사용하고, Home은 `MaterialPageRoute` push, Explore는 `IndexedStack` 내부 모드 전환이라는 서로 다른 네비게이션 구조를 무리하게 하나로 합치지 않는다. 판단 로직만 공유해 중복은 제거하되, 화면별 네비게이션 방식은 각자 유지해 변경 범위와 회귀 위험을 최소화한다.
- 현재 코드베이스에 화면-네비게이션까지 포함한 공유 컨트롤러 패턴이 없고(탐색 결과 5번 항목), `FilmRollController`도 화면별로 개별 인스턴스화되는 구조라 이를 무리하게 통합하려면 변경 범위가 커진다.
- `CourseSelectionScreen`은 `regionId`만 있으면 독립적으로 push 가능하다는 점(탐색 결과 4번 항목)을 활용해, 별도의 "자동 오픈 플래그"를 `FilmRollScreen`에 추가하지 않고도 인증 직후 바로 코스 선택으로 연결할 수 있다.

**대안**
- **대안 A — 화면별 개별 수정(공유 유스케이스 없이)**: Home과 Explore 각각에 판단 로직을 인라인으로 추가. 변경 범위는 가장 작지만, 이미 존재하는 중복(스낵바 문구, 예외 처리, enterRegion 호출)이 그대로 세 번째 갈래로 늘어나는 구조가 되어 "중복 로직 정리"라는 목표(사용자 응답에서 '공유 유스케이스/코디네이터 신설'을 명시적으로 선택)에 부합하지 않아 제외.
- **대안 B — 프레젠테이션 레이어 풀 오케스트레이터**: 화면 이동(Navigator push)까지 포함해 하나의 컨트롤러/서비스가 담당(Home push든 Explore inline이든 동일 클래스가 처리). 중복 제거 폭은 가장 크지만, Home(라우트 push)과 Explore(IndexedStack 내부 모드 스위치)의 네비게이션 방식 자체가 근본적으로 달라(탐색 결과 위험요소 1번) 오케스트레이터가 결국 진입점별 분기를 다시 갖게 되어 이점이 줄고, 위젯/통합 테스트가 전무한 이 영역(탐색 결과 위험요소 5번)에서 네비게이션까지 공유 클래스로 옮기면 회귀 위험이 커진다. "안정성 최우선" 결정에 따라 이번 이슈에서는 채택하지 않는다.

### 5. 주요 결정사항

| 결정 | 선택 | 이유 |
|------|------|------|
| 작업 범위 | Home + Explore 통합, Signup 경로는 제외 | 사용자 확인. Signup은 인증 결과를 현재 무시하는 별도 이슈 소지가 있어 범위 분리 |
| 오케스트레이션 구현 방식 | 공유 유스케이스(판단 로직만 공유) + 화면별 기존 네비게이션 유지 | 사용자 확인('공유 유스케이스/코디네이터 신설') + 안정성 우선으로 네비게이션 구조는 화면별 유지 |
| 현상 대기(developing) 처리 | 이번 범위 포함, `FilmRollScreen`에 developing 분기 추가 | 사용자 확인. 기존 `FilmRollDevelopingView`(Explore용) 재사용을 전제로 변경 범위 최소화 |
| 코스 선택 진입 방식 | `CourseSelectionScreen`을 `FilmRollScreen` 경유 없이 인증 직후 바로 push | `CourseSelectionScreen`이 `regionId`만 요구하므로 별도 플래그/화면 수정 불필요 |
| 지역 판별 이원화(RegionsApi) | 이번 이슈에서는 손대지 않음(P2로 이월) | 범위 확대 시 회귀 위험 증가, 안정성 우선 결정과 상충 |
| 우선순위 | 안정성 > 속도/확장성 | 사용자 확인 |

### 6. 고려사항 및 위험요소

**기술적 위험**
- `HomeDashboardScreen.initState`에서 `_loadRecoveredFilmRoll()`과 `_ensureLocationVerified()`가 순서 보장 없이 동시에 실행됨(탐색 결과 위험요소 3). 신규 자동 진입 로직은 반드시 "활성 필름롤 조회 완료 후"에만 `enterRegion`을 트리거하도록 명시적으로 순서를 맞춰야 하며, 그렇지 않으면 중복 진입 시도나 화면 이중 push가 발생할 수 있다. → 대응: 판정 유스케이스 내부에서 `recoverLastActiveFilmRoll`을 먼저 호출·대기하는 방식으로 순서를 강제.
- `MainTabScreen`이 Home/Explore를 `IndexedStack`으로 동시에 살려두므로(탐색 결과 위험요소 1), Home에서 자동 진입시킨 필름롤을 Explore 탭이 `reevaluate()`로 다시 읽을 때 두 화면의 로컬 상태(FilmRollController 인스턴스)가 서로 다르게 따로 존재한다. 코스 선택 직후 두 탭의 표시가 잠시 어긋나지 않도록 화면 전환/새로고침 시점을 QA에서 확인해야 한다.
- 디버그 빌드에서 위치 인증이 서비스 지역 밖 좌표를 '공주시'로 대체하는 폴백이 있다(탐색 결과 위험요소 6). 자동 진입 로직 개발/QA 시 이 폴백값 때문에 실제 지역과 다른 지역으로 자동 진입될 수 있음을 인지해야 한다.
- `FilmRollScreen`에 developing 분기를 추가할 때 `FilmRollDevelopingView`가 현재 Explore 전용 위치(`explore/presentation/widgets/`)에 있어, Home에서 재사용하려면 위젯을 공용 위치로 옮기거나 import 경로를 그대로 참조할지 결정 필요(구현 단계에서 확정).

**비즈니스 위험**
- 자동으로 지역에 진입시키는 것이므로, 사용자가 "일단 둘러만 보고 싶었던" 경우에도 필름롤이 자동 생성될 수 있다. 이슈 원문 요구사항상 의도된 동작이지만, 사용자가 원치 않는 필름롤 생성을 되돌릴 수 있는 기존 "나가기" 동선이 자동 진입 이후에도 정상 노출되는지 확인 필요.
- 현재 이 플로우 전체(Home/Explore/FilmRollScreen/CourseSelectionScreen)에 대한 위젯·통합 테스트가 전무하다(탐색 결과 위험요소 5). 회귀를 조기에 잡을 안전망이 없으므로, 구현 단계에서 최소한 신규 유스케이스에 대한 단위 테스트는 필수로 추가한다.

### 7. 성공 기준

- [ ] 위치 인증 성공 + 진행 중 필름롤 없음 상태에서, 별도 탭 없이 코스 선택 화면까지 자동으로 연결된다(Home 경로).
- [ ] Explore 탭에서 지역 선택 후 진입 시에도 동일하게 코스 선택까지 자동으로 이어진다.
- [ ] 이미 진행 중(코스 선택 완료)인 필름롤이 있으면 기존과 동일하게 진행 화면으로 바로 이동한다(회귀 없음).
- [ ] 현상 대기 상태의 필름롤을 Home 경로로 열어도 현상 대기 화면이 정상 표시된다.
- [ ] `enterRegion` 호출/예외 처리 로직이 Home·Explore에서 하나의 공유 지점으로 통합되어, 두 곳의 스낵바 문구·로그가 한 곳에서 관리된다.
- [ ] 신규 판정 유스케이스에 대한 단위 테스트가 추가된다.

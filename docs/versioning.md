# 버전 · 빌드 번호 관리 규칙

## 한 곳에서만 관리

`pubspec.yaml`의 `version: X.Y.Z+N` 한 줄만 수정한다.
Flutter가 iOS `CFBundleShortVersionString`(=`X.Y.Z`)와 `CFBundleVersion`(=`N`)에 자동 주입한다.
**Xcode / Info.plist를 직접 건드리지 않는다.**

```
version: 1.2.0+15
        └─┬─┘ └┬┘
    버전(X.Y.Z) 빌드번호(N)
```

## 버전 `X.Y.Z` — 사용자에게 보이는 값

| 자리 | 올리는 시점 | 예 |
|------|-------------|-----|
| `X` MAJOR | 대규모 개편·호환 깨짐 | 1.x.x → 2.0.0 |
| `Y` MINOR | 기능 추가 | 1.2.x → 1.3.0 |
| `Z` PATCH | 버그 수정만 | 1.2.0 → 1.2.1 |

- 올릴 때 아래 자리는 0으로 초기화 (`1.3.0`, `2.0.0`).
- TestFlight 내부 테스트만 도는 동안은 버전을 자주 안 올려도 된다. 빌드번호만 올린다.

## 빌드번호 `N` — 업로드마다 +1

- **단순 증가 정수.** 버전이 바뀌든 말든 항상 이전보다 커야 한다. 되돌리거나 재사용 금지.
- App Store Connect에 올리는 모든 빌드(같은 버전이어도)는 `N`이 유일하고 더 커야 한다. 안 그러면 업로드 거부.
- 버전을 올려도 `N`은 리셋하지 않고 계속 이어간다. (`1.2.0+15` → `1.3.0+16`)

## 릴리스 절차

1. `pubspec.yaml` `version` 수정 (버전 필요 시 + 빌드번호 +1)
2. 커밋: `chore : vX.Y.Z+N` / 필요 시 `git tag vX.Y.Z`
3. `flutter build ipa` → 업로드

## 예시 흐름

```
1.0.0+1    최초
1.0.0+2    같은 버전, TestFlight 재업로드
1.0.0+3    버그 픽스 후 재업로드
1.1.0+4    기능 추가 릴리스
1.1.1+5    핫픽스
```
